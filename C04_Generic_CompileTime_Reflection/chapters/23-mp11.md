# 23. Boost.Mp11：把手写 type_list 迁移到库算法

先修：[类型列表与签名计算](08-type-lists.md)、[字段选择 DSL](19-field-projection-dsl.md)。本章不重新发明 type_list，而是用固定版本 Boost.Mp11 重写同一类计算：字段 schema、元 map、惰性分支和受控运行时索引到类型分派。

Mp11 的核心模型很小：类型列表就是某个类模板包住一组类型，常用默认形态是 `mp_list<Ts...>`。算法接收类型，返回类型；需要返回布尔值时返回 `mp_true`、`mp_false` 或标准 type trait。它没有运行时容器，也不存对象。

```cpp
using xs = boost::mp11::mp_list<int, bool, int>;
using ys = boost::mp11::mp_unique<xs>; // mp_list<int, bool>

template<class T>
using add_ptr = T*;

using zs = boost::mp11::mp_transform<add_ptr, ys>; // mp_list<int*, bool*>
```

这里 `add_ptr` 是 metafunction：输入类型，输出类型。`mp_transform` 不调用函数，也没有循环变量；它只是把模板应用到包里的每个元素。

## 从 A02 字段 schema 到元 map

A02 的 schema 是普通 C++ 类型和常量的组合：

```cpp
template<fixed_string Name, auto Member>
struct field {
    static constexpr auto name = Name;
    static constexpr auto member = Member;
};

template<>
struct schema<Person> {
    static constexpr auto fields = std::tuple{
        field<"id", &Person::id>{},
        field<"active", &Person::active>{},
        field<"name", &Person::name>{}
    };
};
```

Mp11 map 需要“key 类型”。字符串字面量值不能直接作为 map 的类型 key，因此先包一层：

```cpp
template<fixed_string Name>
struct key {
    static constexpr auto name = Name;
};

template<auto Member>
using member_c = std::integral_constant<decltype(Member), Member>;
```

一个字段变成一个 pair：

```cpp
mp_list<key<"id">, member_c<&Person::id>>
```

整个 `std::tuple<field<...>...>` 变成：

```cpp
using person_map = mp_list<
    mp_list<key<"id">, member_c<&Person::id>>,
    mp_list<key<"active">, member_c<&Person::active>>,
    mp_list<key<"name">, member_c<&Person::name>>
>;
```

这就是 Mp11 的 meta-map。它仍是一组类型；成员指针值藏在 `std::integral_constant` 的 `value` 里。

## 查找：缺键返回 void

`mp_map_find<M, K>` 返回第一个 key 为 `K` 的 pair；找不到返回 `void`。因此公开接口通常分两层：

```cpp
template<class Record, fixed_string Name>
using find_field_t = mp_map_find<schema_map_t<Record>, key<Name>>;

template<class Record, fixed_string Name>
struct required_field {
    using found = find_field_t<Record, Name>;
    static_assert(!std::is_same_v<found, void>, "mp11 map key not found");
    using type = found;
};
```

`find_field_t` 适合写探测，`required_field_t` 适合对外 API。两者不要混在一起；否则“字段可选”和“字段必须存在”的诊断会变模糊。

`mp_map_insert`、`mp_map_replace` 和 `mp_map_update` 的语义也要按库实现理解：

- `mp_map_insert<M, T>`：key 已存在时保持原 map，不覆盖。
- `mp_map_replace<M, T>`：key 已存在时替换 pair；不存在时追加。
- `mp_map_update<M, T, F>`：key 已存在时用 `F<Key, OldValue...>` 更新 value；不存在时追加 `T`。

这三者覆盖了“注册默认字段”“强制覆盖字段”“基于旧类型推导新类型”三个不同动作。

## map/filter/unique/product

类型算法可以直接复用：

```cpp
template<class Pair>
using const_value_pair = mp_list<mp_first<Pair>, const field_value_type_t<Pair>>;

using const_fields = mp_transform<const_value_pair, person_map>;
```

`mp_filter<P, List>` 要求 `P<T>` 返回布尔 trait。字段过滤可以按成员类型做：

```cpp
template<class Pair>
using is_string_field = std::is_same<field_value_type_t<Pair>, std::string>;

using string_fields = mp_filter<is_string_field, person_map>;
```

`mp_unique` 按类型相等去重。它适合去重结果类型集合，不适合静默修正重复 schema；schema 重复 key 应当在更靠近声明处失败。

`mp_product<F, A, B>` 会形成笛卡尔积，常用于“每个字段类型 × 每个策略”的组合。它很方便，也容易爆炸；教学题只用小集合展示形状，真实大 schema 要先算规模，再决定是否展开。

## 惰性

惰性分支的重点不是少写一行，而是未选分支不能被实例化：

```cpp
template<bool ChooseThen, class ThenProvider, class ElseProvider>
struct lazy_provider;

template<class ThenProvider, class ElseProvider>
struct lazy_provider<true, ThenProvider, ElseProvider> {
    using type = typename ThenProvider::type;
};
```

如果 `ElseProvider` 没有 `type`，上面的 true 分支仍合法。`mp_eval_if`、`mp_defer`、`mp_valid` 是 Mp11 里同类边界的基础工具；读库源码时要看它们是否把危险表达式放在延迟位置。

## 运行时索引到类型分派

有时运行时拿到一个字段序号，但处理逻辑仍想知道编译期类型。Mp11 提供 `mp_with_index<N>(i, f)`：它在已经实例化的 `mp_size_t<0>` 到 `mp_size_t<N-1>` 分支中运行时选择一个，再调用对应 callable。这里没有在运行时创建新类型。

正确顺序是先检查边界：

```cpp
if (index >= field_count_v<Record>) {
    throw std::out_of_range("field index out of range");
}
return mp_with_index<field_count_v<Record>>(index, visitor);
```

不要把未检查的输入直接交给 `mp_with_index`。库负责分派，不负责把你的运行时前置条件变成安全 API。空schema还需要类型层边界：虽然`index >= 0`总会抛出，普通`if`仍不能阻止后面的`mp_with_index<0>`实例化。U01用`if constexpr (count > 0)`包住分派表达式，空schema只抛出`out_of_range`且visitor零次调用。这个反例说明，运行时校验与模板支持域校验各有职责。

## 源码导读：mp_map_find

本课固定 Boost.Mp11 `boost-1.91.0`，commit `b94b089d4ec83cd397f20958f34edf25bc3e06f4`。入口文件是：

```text
include/boost/mp11/detail/mp_map_find.hpp
```

当前 MSVC 分支的核心是三步：

1. 把每个 map 元素 `T` 包成 `mp_identity<T>`。
2. 用 `mp_inherit<mp_identity<T>...>` 形成一个同时继承所有候选 pair 的类型。
3. 调 `f(static_cast<U*>(0))`，让重载解析选择 `mp_identity<L<K, U...>>*`，找不到则落到 `...` 并返回 `void`。

这是编译期“查表”，但不是运行时查表。它利用的是类型继承、函数重载和 `decltype` 的未求值语境。

文件顶部还有一个 `BOOST_MP11_WORKAROUND(BOOST_MP11_GCC, >= 140000)` 分支。那是 GCC 14+ 的 workaround，用 `mp_append` 和 `mp_front` 改写查找路径；它不是当前 MSVC 本机验证走的分支。讲源码时要把版本、编译器分支和退出条件说清楚。
