# 02. 借用视图、Arena 与对象图

先修 C02 的拥有/借用和 C05 的有界字节表达。先运行 [L02](../exercises/L02_views_graphs/README.md)，再进入真实 Protobuf 的 Arena 实验。本章解决两个常被“序列化”一词遮住的问题：返回对象依赖谁继续存活，以及跨对象引用到底保存了什么。

## 拷贝解码保存的是独立对象

最直接的解码器把每段文本复制到 string，返回对象拥有自己的数据。输入缓冲释放后，结果仍有效。代价是分配和复制；优点是调用者不必延长输入的生命周期。P1 日志存储的 get 也采用拥有型返回，避免读者把文件读取缓冲或下一次更新失效的引用带出去。

借用视图改变了这个契约。L02 的表格式由 count、count+1 个偏移和连续 payload 组成。偏移使用固定宽度大端整数；先验证整个偏移表，再返回 payload 的 span。

必须同时成立：

- count 不超过 1024，整个输入不超过 1 MiB。
- 第一个偏移为 0，最后一个偏移等于实际 payload 长度。
- 偏移非递减；相邻偏移相等表示一个合法空字段。
- 查询下标在字段数量之内。

“最后偏移正确”不能代替单调性：中间一段仍可能反向、重叠或越界。先验证所有偏移，让后续 at 只执行已经建立边界的切片。

## 视图只省去了哪部分复制

blob_view 拥有一份小型偏移数组，payload 仍借用输入。它并非零分配，也不是把所有解码成本变成零。L02 比较第一段数据地址和原缓冲的 payload 地址，直接验证别名关系；这比测一个很小的耗时再猜“实现零拷贝了”可靠。

```cpp
auto bytes = c12::encode_blobs(values);
auto view = c12::blob_view::read(*bytes);
auto first = view->at(0);  // 借用 *bytes 的存储
```

bytes 必须覆盖 view 及其切片的使用期，而且不能发生使存储失效的 resize/reallocation。span<const byte> 限制通过这个 span 修改数据，不会冻结别名持有者的 vector。需要跨越输入生命周期时，显式复制成拥有型对象。

不要用“先释放 bytes，再观察还能否打印出 hello”验证借用规则；那会执行未定义行为，偶然输出正确也无意义。本课检查合法使用下的地址和复制后的独立值，并用生命周期推导说明禁止的路径。

## Arena 改变释放方式，不自动解决所有权

Arena 把多个对象的分配与销毁归到一个区域。区域对象及其字符串、子消息可能随 Arena 一次性失效。跨作用域保存对象指针仍需要区域活得足够久；把堆对象指针换成 Arena 指针不会让它自动变成拥有型句柄。

真实 Protobuf 单元使用固定版本的 Arena::Create，先在区域存活时构造、序列化和比较，再销毁区域。它对照普通拥有对象与区域对象的释放责任。这里不手写另一个内存池；allocator/pmr 的公共机制继续由 C07 主讲。

## 为什么对象引用不能写成地址

假设节点 10 指向 20，20 又指向 10。写入原始地址既不能跨进程使用，也无法表达新分配对象的身份。递归“展开被引用对象”则可能无限递归，或者把同一个对象复制成多个不再共享身份的副本。

L02 输入使用稳定 ID 与 ID 引用列表，分两遍建立对象图：

1. 建立 ID 到节点位置的映射，拒绝 0 和重复 ID。
2. 确认每个引用指向已登记节点，再把引用转成内部下标。

整张图在校验完成后才返回。节点最多 1024、总边数最多 4096；循环是合法图结构，不是自动展开的命令。遍历使用显式队列和 visited，每个节点最多入队一次，因此环不会造成无限递归。

内部下标属于当前 materialization，持久格式继续使用稳定 ID。这个区别与数据库主键、外键相通：物理位置变化不应偷偷改变逻辑身份。采用 shared_ptr 环并不能替代图的编码模型，还可能产生所有权环；本例由一个图对象拥有全部节点，边只是索引关系。

## 实验、误区与解析

L02 的完整观察程序检查空字段、嵌入 NUL 的字节值、所有截断位置、非单调偏移、超量字段、循环引用、悬空引用和重复 ID。字符串表只是字节表，不自动施加 Unicode 语义；作为资源名称时仍须走 C05 的领域校验。

**视图通过检查以后能否随意移动输入 vector？** 要看操作是否保留实际存储与所有者寿命，不能只根据变量名推断。最容易复现的安全规则是让拥有缓冲的对象在使用切片期间保持存储稳定。

**为什么两遍解析不把缺失引用当成空指针？** 输入可能已经损坏。静默替换会把不满足领域不变量的对象图交给下游；本接口选择明确拒绝。

**图遍历通过能否证明反序列化任意 C++ 对象安全？** 不能。这里只支持显式 ID 图和有界字节表；构造函数、虚函数、私有状态、资源句柄及多态类型选择都需要另行定义协议和允许列表。课程不提供按输入任意实例化类型的入口。
