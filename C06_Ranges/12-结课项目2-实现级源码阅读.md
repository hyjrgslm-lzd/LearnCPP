### 必做任务（5 项）

#### 任务 1：重读四份实现，标注关键模式

**1a. `single_view` / `empty_view` / `iota_view`（completion-style view，"just_view"类比）**

阅读入口（libstdc++）：`<ranges>` 中搜索 `class single_view` 和 `class iota_view`。

标注要点（对应模块 F 的 CRTP 注入技术）：

- `view_interface<single_view<T>>` 继承关系：`view_interface` 通过 CRTP 的 `derived()`
  把 `empty()` / `front()` / `back()` / `operator[]` 注入，派生类只提供 `begin()` / `end()`
- `single_view` 持有一个 `T` 的 `movable-box`（规范包装，用于让不可赋值的 T 仍能被 view 拷贝/赋值），`begin()` 返回指向盒内值的裸指针，`end() = begin() + 1`；
  无底层 view 依赖，无缓存——O(1) move/copy/destroy 成立的前提是 T 本身也满足这些复杂度（若 T 是重类型，single_view 的 destroy 代价随之上升）
- `iota_view` 的 `iterator_concept`：整数类型推导为 `random_access_iterator_tag`；
  `enable_borrowed_range<iota_view<W, B>> = true`（见 P1664 / P0896R4 的 borrowed_range 设计）：迭代器只持有当前整数值，不依赖 view 对象生命周期
- `empty_view` 极简：begin/end 均返回 `static_cast<T*>(nullptr)`，体现"no cache, no state"

**1b. `transform_view`：inner iterator 模式**

阅读入口：搜索 `class transform_view`，看内部嵌套的 `_Iterator` 类。

标注要点（对应模块 G 的 inner iterator 技术）：

- inner iterator 持有两样东西：底层迭代器 `_M_current` + 指向 `transform_view` 本体的指针
  `_M_parent`（通过它访问函数对象 `_M_fun`）
- `operator*()` 实现：`return std::invoke(*_M_parent->_M_fun, *_M_current);`——用 `invoke`
  覆盖成员指针 / 函数指针 / 仿函数全部情形
- `iterator_concept` 推导：取底层 concept 与 `random_access_iterator_tag` 的 min；
  contiguous 底层降为 random_access（`operator*` 返回 prvalue，不是真实内存引用）
- `iter_move` 通过 hidden-friend 定制（模块 H 对应技术），把 `ranges::iter_move` 转发到底层
  并对结果应用变换

**1c. `filter_view`：`__non_propagating_cache`，begin() 非 const**

阅读入口：搜索 `class filter_view`，找 `_M_begin` 缓存成员。

标注要点（对应模块 H 的缓存实现技术）：

- `__non_propagating_cache<optional<iterator_t<_Vp>>>` 成员 `_M_begin`：拷贝构造时调用
  `reset()`，赋值时同样重置——这是"non-propagating"的来源。模块 H 练习实现的 begin cache
  与此功能等价，标准库通过专门的 wrapper 类型强制保证语义，而非依赖程序员记住
- `begin()` 是非 const 成员函数：需要向 `_M_begin` 写入扫描结果，写操作不能在 const 方法里
- `iterator_concept` 上界：取底层 concept 与 `bidirectional_iterator_tag` 的 min——random access
  底层在 filter 后也只能是 bidirectional（`operator-` 无法 O(1) 完成）
- `filter_view` 不是 `sized_range`：`view_interface` 的 `size()` 注入失效（满足条件的元素数
  只有遍历才能确定）

**1d. `join_view`：外/内双层迭代器状态，xvalue 内层范围缓存**

阅读入口：搜索 `class join_view`，找内部 `_Iterator` 中的双层状态。

标注要点：

- 迭代器持有两层状态：外层迭代器 `_M_outer`（当前子范围）+ 内层迭代器 `_M_inner`（子范围内的元素）；
  `operator++` 先推进内层，到达 inner end 后推进外层并重置内层
- xvalue 内层范围缓存：若外层解引用返回右值（xvalue），则每次 `*_M_outer` 产生不同临时对象，
  需用 `__non_propagating_cache<inner_range>` 缓存内层子范围本体
- `iterator_concept` 合成：`min(外层 concept, 内层 concept, bidirectional_iterator_tag)`——
  见 `01-心智模型.md` 的"迭代器概念双轨"章节
- `join_view` 不是 `borrowed_range`：迭代器有效性依赖 view 对象生命周期

#### 任务 2：对每份实现回答五个问题

对 single_view / transform_view / filter_view / join_view 各回答一次：

1. **用了 CPO 还是普通函数 dispatch？**
   外部接口（`ranges::begin(v)`）通过 CPO 转发；内部 `begin()` / `end()` 是成员函数，
   CPO 优先调用成员版本；`ranges::iter_move` 是 CPO，transform_view 通过 hidden-friend 定制

2. **`iterator_concept` 如何推导？**
   single_view → `contiguous`；transform_view → `min(底层, random_access)`；
   filter_view → `min(底层, bidirectional)`；join_view → `min(外层, 内层, bidirectional)`

3. **是否有 cache？什么类型？**
   single_view 无；transform_view 无；filter_view 有 `__non_propagating_cache<optional<It>>`；
   join_view 在 xvalue 内层时有 `__non_propagating_cache<inner_range>`

4. **operation state（迭代器内部状态）是栈对象还是堆对象？**
   四者均为栈对象；transform_view 的 iterator 持有 parent 裸指针，但 iterator 本身在调用方栈上

5. **是否使用了 variant/tuple 做内部状态？**
   join_view 用 `optional` 管理内层迭代器（可能未初始化）；zip_view（进阶）用
   `tuple<iterator_t<Rs>...>` 存储多个底层迭代器

#### 任务 4：stdexec tag_invoke vs ranges CPO 的设计哲学对比（至少 4 维度）

| 维度 | ranges CPO（`ranges::begin` 等） | stdexec tag_invoke |
|------|----------------------------------|-------------------|
| **定制入口形式** | `inline constexpr` 函数对象，"成员优先 → ADL 次之 → 回退"优先级链 | `tag_invoke(tag_t, ...)` 自由函数，类型 tag 作为第一参数携带语义 |
| **ADL 隔离方式** | CPO 本身是函数对象，不参与 ADL 查找；内部再决定调成员还是走 ADL | tag_invoke 仍依赖 ADL，但所有定制集中在同名函数，避免名字冲突 |
| **多态点结构** | 每个操作有专属 CPO，多态点分散但命名清晰 | 所有 CPO 共用 `tag_invoke`，由第一参数 tag 类型区分，更集中但更难阅读 |
| **扩展对称性** | 不支持用户定义全新 CPO 与现有框架平等（`range_adaptor_closure` 是例外，P2387R3） | 天然允许用户定义新 tag，扩展点对称 |
| **编译期查询** | 直接用于 concept 约束：`requires { ranges::begin(r) }` | 依赖 `tag_invocable<tag_t, Args...>` concept 检测 |

#### 任务 5：读书笔记

**题目：我现在如何向别人解释 stdlib ranges 的实现架构**

stdlib `<ranges>` 的实现是三层机制的叠加，不是一堆 view 类的简单集合。

第一层是**定制点协议层**。`ranges::begin`、`ranges::end`、`ranges::iter_move` 这些 CPO
不是函数模板，是函数对象。这个选择让它们不参与 ADL 查找，阻止第三方库的同名函数意外劫持
行为（模块 E 的核心论据）。CPO 内部按照"成员函数优先 → ADL 次之 → 标准回退"的优先级链
选择实现路径。niebloid（`ranges::sort` 等算法）是同样原理的算法侧对应物。

第二层是**类型基础设施层**。`view_interface<Derived>` 通过 CRTP 向派生 view 注入
`empty()` / `front()` / `back()` / `size()` / `operator[]`，派生类只需提供 `begin()` 和
`end()`（模块 F 核心）。`range_adaptor_closure<Derived>`（P2387R3）通过 CRTP 注入
`operator|`，使任何继承它的对象都可以出现在管道右侧（模块 G 核心）。两个 CRTP 基类解决同
一个问题：不重复代码地让所有 view 满足相同对外接口约定。

第三层是**实现模式层**。每个 view 归结为几个可组合的模式：inner iterator（持有底层迭代器
+ parent 指针）；`__non_propagating_cache`（缓存 begin 位置但拷贝时重置，保卫 O(1) copy
公理）；iterator_concept 推导（取底层 concept 与本层上界的 min）；borrowed_range 标记
（通过 `enable_borrowed_range` 特化声明迭代器独立于 view 生命周期）。

真正读懂 stdlib ranges，意味着看到 `filter_view::_M_begin` 时立刻能说出：这是
`__non_propagating_cache`，它的 non-propagating 语义是 O(1) copy 公理的实现机制。

### 进阶任务（3 项）

#### 进阶 1：阅读 `zip_view` 的 proxy reference / iter_move / iter_swap

`operator*` 返回 `tuple<range_reference_t<Rs>...>`（prvalue tuple，proxy reference）——这是
`iterator_category` 被降为 `input_iterator_tag` 的根本原因。`ranges::iter_move` 被定制为
对每个底层迭代器调用 `ranges::iter_move`，返回 `tuple<range_rvalue_reference_t<Rs>...>`。
`iter_swap` 则 element-wise 调用 `ranges::iter_swap`。验证：`iterator_concept =
random_access_iterator_tag` 但 `iterator_category = input_iterator_tag`（双轨现象）。

#### 进阶 2：阅读 `range_adaptor_closure` 基类 + `operator|` 的实现

libstdc++ 中搜索 `__adaptor` 命名空间。`operator|` 有两条路径：`range | closure` 转换为
`closure(range)`；`closure1 | closure2` 生成新的 `_Pipe<C1, C2>` 对象。`_Pipe<C1, C2>`
本身也继承 `range_adaptor_closure<_Pipe<C1,C2>>`，因此组合后仍是 closure，可继续参与管道。
关键约束：两个 `operator|` 重载互斥（左侧是 range 还是 closure 决定走哪条路）。

#### 进阶 3：ranges adaptor 与 sender adaptor 的结构对比

| 结构位置 | ranges transform | stdexec then |
|----------|-----------------|--------------|
| closure 类型 | `_Partial<transform_fn, F>` 持有 F，等待 range | `_then_sender<S, F>` 持有底层 sender + F |
| 内部状态传播 | inner iterator 持有 parent 指针访问 F | inner receiver 持有 F，在 `set_value` 时调用 |
| 惰性点 | `operator*` 调用时才执行 F（拉模型） | `start()` 驱动底层，完成信号里调用 F（推模型） |
| 类型安全 | `iterator_concept` 静态描述迭代能力 | `completion_signatures` 静态描述完成信号类型 |

根本差异：ranges adaptor 工作在同步拉模型；sender adaptor 工作在异步推模型。
这正是 `C06_Ranges` 与 `C10_Execution` 的分工——ranges 管如何取值，execution 管何时执行
（见 `README.md` 两套抽象定位说明）。

## 结课项目 4：mini-ranges 子集实现

### 项目目标

这个 mini-ranges 是子集，不是完备实现，不覆盖 C++23 全部 view，但对象关系和编译期语义必须正确。

### 必须包含的组件

#### 1. 核心协议 + 类型基础设施

```cpp
// C++20
namespace my::ranges {
// CPO: 函数对象（不参与 ADL），内部调用成员 begin/end
namespace _begin { struct _fn {
    template<typename R> requires requires(R& r){ r.begin(); }
    auto operator()(R& r) const { return r.begin(); }
}; }
inline constexpr _begin::_fn begin{};
namespace _end { struct _fn {
    template<typename R> requires requires(R& r){ r.end(); }
    auto operator()(R& r) const { return r.end(); }
}; }
inline constexpr _end::_fn end{};

// 关联类型
template<typename R> using iterator_t        = decltype(my::ranges::begin(std::declval<R&>()));
template<typename R> using range_value_t     = std::iter_value_t<iterator_t<R>>;
template<typename R> using range_reference_t = std::iter_reference_t<iterator_t<R>>;

// concept 子集
template<typename T> inline constexpr bool enable_view          = false;
template<typename T> inline constexpr bool enable_borrowed_range = false;
template<typename R> concept range        = requires(R& r){ my::ranges::begin(r); my::ranges::end(r); };
template<typename R> concept view         = range<R> && std::movable<R> && enable_view<std::remove_cvref_t<R>>;
template<typename R> concept input_range  = range<R> && std::input_iterator<iterator_t<R>>;
template<typename R> concept forward_range= input_range<R> && std::forward_iterator<iterator_t<R>>;

// view_interface CRTP: 注入 empty/front（完整实现还需 back/size/operator[]）
template<typename D> struct view_interface {
    bool empty() { auto& d=static_cast<D&>(*this); return my::ranges::begin(d)==my::ranges::end(d); }
    auto front() { return *my::ranges::begin(static_cast<D&>(*this)); }
};

// range_adaptor_closure CRTP: 注入 operator|（range|closure 路径；closure|closure 为简化骨架）
template<typename D> struct range_adaptor_closure {
    template<my::ranges::range R>
    friend auto operator|(R&& r, const D& d) { return d(std::forward<R>(r)); }
};
} // namespace my::ranges
```

#### 3. 基础 view + adaptor + 消费端骨架

```cpp
// C++20: iota_view（有界整数序列，iterator_concept = random_access）
namespace my::views {
template<std::integral W>
class iota_view : public my::ranges::view_interface<iota_view<W>> {
    W _b, _e;
public:
    iota_view(W b, W e) : _b(b), _e(e) {}
    struct iterator {
        using value_type = W; using difference_type = std::ptrdiff_t;
        using iterator_concept = std::random_access_iterator_tag;
        W _cur;
        W operator*() const { return _cur; }
        iterator& operator++() { ++_cur; return *this; }
        bool operator==(const iterator&) const = default;
        friend difference_type operator-(iterator a, iterator b) { return a._cur - b._cur; }
    };
    iterator begin() const { return {_b}; }
    iterator end()   const { return {_e}; }
};
template<std::integral W> inline constexpr bool my::ranges::enable_view<iota_view<W>>          = true;
template<std::integral W> inline constexpr bool my::ranges::enable_borrowed_range<iota_view<W>> = true;
constexpr auto iota = [](auto b, auto e) { return iota_view{b, e}; };

// single_view: begin/end = 裸指针，iterator_concept 自动为 contiguous
template<std::copy_constructible T>
class single_view : public my::ranges::view_interface<single_view<T>> {
    T _v;
public:
    explicit single_view(T v) : _v(std::move(v)) {}
    T* begin() noexcept { return std::addressof(_v); }
    T* end()   noexcept { return begin() + 1; }
};
template<typename T> inline constexpr bool my::ranges::enable_view<single_view<T>> = true;
constexpr auto single = [](auto v) { return single_view{std::move(v)}; };
} // namespace my::views

// transform_view: inner iterator 持有底层迭代器 + parent 指针
namespace my::views {
template<my::ranges::range V, std::copy_constructible F> requires my::ranges::view<V>
class transform_view : public my::ranges::view_interface<transform_view<V, F>> {
    V _base; F _fun;
public:
    transform_view(V b, F f) : _base(std::move(b)), _fun(std::move(f)) {}
    struct iterator {
        using _BaseIt = my::ranges::iterator_t<V>;
        _BaseIt _cur; F* _fp;
        // contiguous 底层降为 random_access（operator* 返回 prvalue）
        using iterator_concept = std::conditional_t<std::contiguous_iterator<_BaseIt>,
            std::random_access_iterator_tag,
            typename std::iterator_traits<_BaseIt>::iterator_category>;
        using value_type      = std::remove_cvref_t<std::invoke_result_t<F&, my::ranges::range_reference_t<V>>>;
        using difference_type = std::iter_difference_t<_BaseIt>;
        decltype(auto) operator*() const { return std::invoke(*_fp, *_cur); }
        iterator& operator++() { ++_cur; return *this; }
        bool operator==(const iterator& o) const { return _cur == o._cur; }
    };
    iterator begin() { return {my::ranges::begin(_base), &_fun}; }
    iterator end()   { return {my::ranges::end(_base),   &_fun}; }
};
template<typename V, typename F> inline constexpr bool my::ranges::enable_view<transform_view<V,F>> = true;

// take_view: sentinel 异型（end 类型 ≠ begin 类型）
template<my::ranges::range V> requires my::ranges::view<V>
class take_view : public my::ranges::view_interface<take_view<V>> {
    V _base; std::ptrdiff_t _n;
public:
    take_view(V b, std::ptrdiff_t n) : _base(std::move(b)), _n(n) {}
    // 本 mini-take_view 仅对 random_access 底层工作（因为 sentinel::operator== 用了 _begin + _n）
    // 真实 std::ranges::take_view 用 counted_iterator + default_sentinel 处理 non-random-access 底层
    struct sentinel {
        my::ranges::iterator_t<V> _begin; std::ptrdiff_t _n;
        bool operator==(const my::ranges::iterator_t<V>& it) const
            requires std::random_access_iterator<my::ranges::iterator_t<V>>
        { return it == _begin + _n; }
    };
    auto begin() { return my::ranges::begin(_base); }
    auto end()   { return sentinel{my::ranges::begin(_base), _n}; }
};
// 使用时用 concept 约束底层 view 为 random_access：
//   template<my::ranges::range V>
//     requires std::random_access_iterator<my::ranges::iterator_t<V>>
// 在 mini-ranges 里简化掉这层约束，直到你想扩展 non-random-access 支持为止。
template<typename V> inline constexpr bool my::ranges::enable_view<take_view<V>> = true;

// closure 对象：继承 range_adaptor_closure，注入 operator|
template<typename F>
struct _transform_closure : my::ranges::range_adaptor_closure<_transform_closure<F>> {
    F _f; explicit _transform_closure(F f) : _f(std::move(f)) {}
    template<my::ranges::range R> auto operator()(R&& r) const { return transform_view{std::forward<R>(r), _f}; }
};
template<typename N>
struct _take_closure : my::ranges::range_adaptor_closure<_take_closure<N>> {
    N _n; explicit _take_closure(N n) : _n(n) {}
    template<my::ranges::range R> auto operator()(R&& r) const { return take_view{std::forward<R>(r), (std::ptrdiff_t)_n}; }
};
constexpr auto transform = [](auto f) { return _transform_closure{std::move(f)}; };
constexpr auto take      = [](auto n) { return _take_closure{n}; };
} // namespace my::views

// ranges::to（简化版）+ iter_move CPO
namespace my::ranges {
template<typename C>
struct _to_closure : my::ranges::range_adaptor_closure<_to_closure<C>> {
    template<my::ranges::input_range R> C operator()(R&& r) const {
        C result;
        for (auto&& e : r) result.push_back(std::forward<decltype(e)>(e));
        return result;
    }
};
template<typename C> constexpr auto to() { return _to_closure<C>{}; }

// iter_move CPO: hidden-friend 优先，回退到 std::move(*it)
namespace _iter_move { struct _fn {
    template<typename I> decltype(auto) operator()(I&& it) const {
        if constexpr (requires { iter_move(std::forward<I>(it)); }) return iter_move(std::forward<I>(it));
        else return std::move(*std::forward<I>(it));
    }
}; }
inline constexpr _iter_move::_fn iter_move{};
} // namespace my::ranges
```

### 进阶任务（4 项）

#### 进阶 1：增加 `my::views::filter(pred)` + `__non_propagating_cache`

实现一个等价的 non-propagating optional wrapper：拷贝构造时调用 `reset()`，赋值时同样重置；
begin() 是非 const 成员函数；验证"拷贝不传播、移动传播"行为；验证 `const filter_view`
不能调用 `begin()`。

#### 进阶 2：增加 `my::views::enumerate()` 并让其在底层 borrowed 时也 borrowed

`enumerate_view<V>` 的 `enable_borrowed_range` 特化：当且仅当底层 `V` 是 `borrowed_range`
时特化为 true。迭代器解引用返回 `pair<ptrdiff_t, range_reference_t<V>>`（proxy reference），
`iterator_category` 设为 `input_iterator_tag`（C++17 兼容）。

#### 进阶 3：实现 iterator_concept 双轨

在 `transform_view` 的 iterator 中完整实现：`iterator_concept` 为 `min(底层, random_access)`；
`iterator_category` 根据 F 的返回值是否为左值引用分支：是则透传底层 category，否则降为
`input_iterator_tag`。用 `static_assert` 验证两套标签的不同值。

#### 进阶 4：让 mini-ranges 某个 view 被 stdlib `std::ranges::copy` 消费

```cpp
// C++20: 互操作测试
auto my_view = my::views::iota(1, 6)
             | my::views::transform([](int x){ return x * 2; });
std::vector<int> out;
std::ranges::copy(my_view, std::back_inserter(out));
// out == {2, 4, 6, 8, 10}
```

`std::ranges::begin(my_view)` 优先调用 `my_view.begin()`（成员函数），只要迭代器满足
`std::input_iterator` concept，stdlib 约束算法就能消费它。互操作是"成员优先 CPO 设计"的直接受益。

### 验收点（6 项）与复盘问题（5 项）

**验收点**：

1. `my::ranges::begin` 是 `inline constexpr` 函数对象，能作为值存储，不是函数模板
2. `my::ranges::view` concept 对 `iota_view` 成立，对 `std::vector<int>` 不成立
3. 管道 `iota(1,11) | transform(x*x) | take(5) | to<vector<int>>()` 编译运行，结果为 `{1, 4, 9, 16, 25}`
4. `take_view` 的 `end()` 返回类型与 `begin()` 返回类型不同（sentinel 异型）
5. `iota_view` 的 `enable_borrowed_range = true`；`transform_view` 的为 `false`（默认）
6. 能拿着六层架构图解释整个系统，指出每层的职责和层间依赖方向

**复盘问题**：

1. 实现过程中，哪一层最出乎意料地复杂？CPO ADL 隔离、range_adaptor_closure 的 closure-to-closure
   组合，还是 to<Container> 的通用性约束？
2. `take_view` 的 sentinel 异型设计，在 `to<Container>` 消费端带来了什么额外要求？
3. 如果要增加 `my::views::filter`，begin cache 的 non-propagating 语义如何影响 copy 行为的测试设计？
4. 你的 mini-ranges 与 stdlib 相比，最大的简化在哪里？这些简化会在什么场景下导致错误（而不只是缺失功能）？
5. 完成这个项目后，对 P2387R3 的设计选择有什么新理解？为什么标准选择 CRTP 基类而非要求用户手写 `operator|`？
