# 08 新容器：有序、固定容量与稳定对象位置

先修是序列容器、关联容器、对象存活与失效。新容器并不把旧容器排成一条速度升级链：它们改变存储方式与接口保证，分别适合不同的操作分布。先写出必须保证什么，再选择实现，最后测量成本。

本章的三个问题是：大量查找、少量更新时怎样保存有序键值？容量有硬上界时怎样避免为元素存储动态增长？频繁删除对象时怎样避免移动其他对象？对应的是flat容器、inplace_vector和hive。主实验是[F01](../exercises/F01_frontier/README.md)，每个主体都包含真实标准API；缺能力时不会伪造替代类型。

## 从有序vector理解flat_map

假设日志导入完成后反复按用户查询，而更新主要集中在下一次批量导入。节点map为单次插入和稳定节点位置付出存储成本；有序vector可以二分查找，但插入中间元素要移动后缀。选择取决于构建、查询、更新的比例，而不只取决于一次find。

`std::flat_map<Key, T>`将有序映射适配到两个容器：keys与values。默认底层是vector，它们在同一索引上的元素组成一对。三个不变量必须同时成立：keys按比较器有序；唯一键之间不等价；keys与values长度相同且位置一一对应。这里的等价仍是`!comp(a,b) && !comp(b,a)`，并不要求`operator==`相等。

二分只需要读取键数组，找到下标后才能访问相应值。随机访问意味着可以按偏移定位逻辑键值对，但逻辑的`pair<const Key&, T&>`不一定以一块pair对象连续存储。因此flat_map的迭代器可以随机访问，却不是指向连续pair数组的contiguous iterator；这也是后面proxy iterator的一个实际用途。flat_set则只维护排序、唯一的键序列。

```cpp
std::flat_map<int, std::string> names;
names.insert_or_assign(20, "beta");
names.insert_or_assign(10, "alpha");
names.insert_or_assign(20, "updated");
// 逻辑迭代次序为10、20，第二次20是更新，不是新增键。
```

这段输入在[flat_containers.cpp](../exercises/F01_frontier/flat_containers.cpp)中实际检查。查找的比较次数可以是对数级，插入和删除却可能要移动后缀，并且受底层容器失效规则影响。不要把map节点稳定性搬过来；也不要把默认vector的连续存储推到用户自选的所有底层类型。

## 提取并替换存储为什么需要同时搬动两列

`std::move(names).extract()`交出内部keys/values；`replace`接收两列新存储。这种入口适合批量生成已经正确组织的数据，却把更多前提交给调用者：长度、排序、唯一性与配对关系必须一致。`sorted_unique`类入口也是调用者的保证，不是请求库帮你自动验证。

假设keys为`{20,10}`、values为`{"beta","alpha"}`，只排序keys后变成`{10,20}`，关联就被悄悄颠倒了。正确的准备方式是按键重排完整记录，再分别生成两列，或使用会维护配对关系的标准构造/插入入口。不能为了省一次整理成本调用前提不满足的replace。

F01只将合法extract得到的两列原样移入新容器，并检查查找结果；它没有执行违反replace前提的程序。异常发生时，整个操作的保证还与底层容器、比较器和元素操作有关；“两个vector”本身不是强异常保证的证明。

## inplace_vector：容量与对象数量仍然是两件事

`std::inplace_vector<T, N>`把最多N个元素需要的存储放在容器对象内部，size仍表示已经构造的元素个数。默认构造空容器不意味着先默认构造N个T。不要称它为“总在栈上”：容器对象本身也可能是另一个堆对象的成员。

与vector相比，增长不需要另选更大的元素缓冲区，但上限不能自动扩大；与array相比，它可以只让部分T存活，并通过插入删除管理这些对象。普通尾插超容量会报告`std::bad_alloc`，这里描述的是容器容量不足，不能据此判断整个机器已经耗尽物理内存。元素构造本身仍可能抛出其他异常或分配资源。

2026-03采纳的新签名中，`try_push_back/try_emplace_back`返回`std::optional<T&>`，容量不足时为空；早期提案和旧实现用T*，必须标明年代。[标准状态与来源](../references/standards.md)说明了这个变化。试插入失败不应消耗传入的待移动值，所以调用者还能选择另一个容器或报告拒绝。

```cpp
std::inplace_vector<std::string, 2> values;
values.push_back("first");
auto accepted = values.try_push_back("second"); // 当前签名：optional<string&>
std::string third = "not consumed";
auto rejected = values.try_push_back(std::move(third));
// 容量已满：rejected为空，third仍可使用。
```

完整主体[inplace_vector.cpp](../exercises/F01_frontier/inplace_vector.cpp)检查空与满、普通插入异常、尝试插入返回类型及N=0。`unchecked_*`要求调用者已经证明容量前提，本实验不在容量不足时调用它。异常、空结果和前提违反是三种不同的失败通道，不能混写成“都会返回false”。

原位尾插不搬迁已有元素，并不意味着所有引用永远有效：擦除中间元素、销毁容器、移动容器对象都有各自的失效影响。返回的optional引用仍然借用容器内元素，并不拥有或延长其生命期。课程的动态数组练习研究增长事务，不能将其错误地等同为inplace_vector标准实现。

## hive：保留活对象，复用已擦除的位置

日志通常适合顺序追加；实体集合、任务集合等场景却可能频繁插入、擦除，并且其他结构保存了未删除对象的地址。vector擦除中间对象需要搬移后续元素；list避免搬移，却为节点链接付出成本。hive采用多个元素块，迭代时跳过已经擦除的位置，并允许之后的插入利用这些空位。

这个选择改变了顺序契约：调用者不能把插入先后当成稳定的逻辑顺序，也不能把它当作支持`operator[]`的vector。其迭代器是双向迭代器，不支持随机访问。保留的元素可以在其他元素插入、擦除期间维持所承诺的稳定性，但被擦除对象自己的指针和迭代器立即失去使用依据。clear、赋值、整理存储等其他操作要分别查看条款。

[hive.cpp](../exercises/F01_frontier/hive.cpp)保存一个活对象的地址，擦除另一个对象后增加元素，再检查保留对象与遍历总和。程序从不再解引用被擦除的iterator，也不要求新元素必须复用某一个特定地址。块大小、增长方式和空位管理有实现选择；若要判断局部性或实际吞吐，应做对应负载的测量，不能从“分块”两个字推出速度结论。规范入口见[hive](https://eel.is/c++draft/hive)。

## 怎样在主案例中做选择

| 要求 | 应先考虑的契约 | 必须另行评估的代价 |
|---|---|---|
| 导入后多次有序查询 | 有序vector/flat_map的查找与批量构建 | 中途插入、值移动、失效和构建成本 |
| 每批最多N个记录 | inplace_vector的固定容量与显式拒绝 | 对象本身体积、N选取、元素自己的分配 |
| 插删期间其他结构借用活对象 | hive或节点容器的稳定性 | 顺序需求、内存管理、遍历与定位成本 |
| 同时要稳定句柄和有序报告 | 分开保存对象与索引，并维护一致性 | 这是增加了一项系统责任，不是免费组合 |

上表不是性能排名。B01实验只对其固定输入比较实际实现；本机缺hive/inplace_vector时，不能借另一个容器的成绩替它们交付性能结论。

## 练习与解析

1. 运行F01_flat_containers，预测覆盖同键插入、extract/replace和flat_set去重的结果。解析：唯一性按比较器等价关系维护；两列一起转移才能保持键值关联，set只留下`1,2,4`，擦除2后保留1和4。
2. 在支持当前inplace_vector的环境运行主体，解释第三次try插入为何不移动third。解析：容量检查失败时不构造新元素，空optional表示没产生引用；不需要也不能把返回值delete。普通push的bad_alloc是不同接口的约定。
3. 解释hive实验为什么不检查“新元素一定占据被删地址”。解析：容器允许复用，但具体选择与存储块管理由实现决定；实验只验证保留元素稳定和可见活元素集合。
4. 如果某工具链只有旧inplace_vector指针返回API怎么办？解析：记录旧版本能力，当前主体标SKIP；不能改题目类型断言或将T*强行包装后宣称新标准接口已通过。

运行F01时，flat容器主体和各前沿主体必须分开记录。能力不足时应写明缺头文件、宏或实现入口；已进入主体后的编译、链接或运行错误不能降级为SKIP。
