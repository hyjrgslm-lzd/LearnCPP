# 10 模块 G：自行实现视图

## 模块目标

前面的模块 F 让你手写过自定义迭代器与 sentinel，掌握了 `iterator_concept` 双轨标记和 concept 约束推导。这个模块要把你推到真正从零实现一个可组合 view 的层次：

- 理解 `view_interface<Derived>` 作为 CRTP 基类注入的默认成员（`empty()` / `operator bool()` / `front()` / `back()` / `operator[]` / `size()` / `data()` / `cbegin` / `cend`），以及它"脚手架"性质的边界——它注入成员但不负责存储任何数据
- 理解 `enable_view<T>` 与 `enable_borrowed_range<T>` 两个 opt-in 变量模板的语义公理承诺
- 掌握 `range_adaptor_closure<Derived>`（P2387R3）CRTP 基类，让自定义 adaptor 自动获得 `operator|` 与 closure-to-closure 组合
- 亲手实现 `my_take_view`、`my_transform_view`、`my_enumerate_view` 三个自定义视图
- 理解 CTAD（Class Template Argument Deduction）推导指引的作用与写法

如果你跳过这一层，就很容易把标准 view 的实现当成"库作者的黑盒魔法"，而不是"有结构可循的 CRTP + CPO 组合模式"。

## 前置要求

- 模块 F（概念精化与迭代器分类）：你已经能手写自定义迭代器、理解 `iterator_concept` / `iterator_category` 双轨、实现 sentinel，能用 concept 约束推导迭代器层级
- 模块 B（基础适配器与管道）：你理解 `range_adaptor_closure` 是部分应用对象、`operator|` 是左折叠组合、管道是嵌套 view 而非函数链
- 心智模型（01）的 borrowed_range / dangling 章节：你能解释 `enable_borrowed_range` 的设计意图

## 模块完成标准

做完本模块，你至少要能稳定说清楚：

- `view_interface<Derived>` 是 CRTP 基类，通过调用 `static_cast<Derived&>(*this).begin()` 和 `end()` 推导出其他成员，但它不存储任何数据，也不提供 `begin()` / `end()`——那两个必须由 `Derived` 自己实现。
- 自己实现的 view 只需提供 `begin()` + `end()`，CRTP 基类里 `empty()`、`front()`、`back()`、`operator[]`、`size()`、`data()` 这些成员会按条件自动注入（条件是底层具备对应能力：`sized_range` 才有 `size()`，`contiguous_range` 才有 `data()` 等）。
- `enable_view<MyView> = true`（或继承 `view_base`，或继承 `view_interface`）是 opt-in 语义：你承诺该类型满足"O(1) move / O(1) copy-if-copyable / O(1) destroy"三条语义公理，标准库不会为你验证，这是你对框架的承诺。
- `enable_borrowed_range<MyBorrowedView> = true` 是"借用"标记：表示迭代器有效性不依赖 view 对象本身的生命周期，rvalue 传给算法时框架会返回真正的迭代器而非 `dangling`。
- `range_adaptor_closure<Derived>` 让自定义 adaptor 获得 `operator|(range, closure)` 的重载，同时支持 closure-to-closure 组合：`f | g` 产生新的 closure，等价于先 `f` 后 `g`。
- CTAD 推导指引（deduction guides）让 `my_take_view{vec, 3}` 无需显式写出模板参数，编译器通过指引推导出 `V = ref_view<vector<int>>`。

## 练习 G-1：my_take_view —— 最小 view_interface 实战

### 目标

实现一个最小的 `my_take_view<V>`，继承 `view_interface` 让 CRTP 注入默认成员，用 `static_assert` 验证它满足 `std::ranges::view` concept。

### 前置理解

- 你在模块 F 里手写过自定义迭代器，理解 `iterator_concept` 双轨和 sentinel 的实现模式。
- 你知道 `std::ranges::view` concept 的三条语义公理（O(1) move / copy / destroy）以及如何通过 `enable_view` opt-in。
- 你知道 `view_interface` 是 CRTP 基类：它调用 `Derived::begin()` 和 `Derived::end()` 来推导其他成员——这意味着你必须先提供这两个成员，`view_interface` 的注入才生效。
- 你接受这题先实现最简形式，进阶任务再扩展条件分支。

### 必做任务

```cpp
// C++26 default for this course. my_take_view chooses a safe teaching contract:
// negative count throws std::invalid_argument; std::views::take itself has a
// non-negative-count precondition.
#include <algorithm>
#include <cassert>
#include <iterator>
#include <list>
#include <ranges>
#include <sstream>
#include <stdexcept>
#include <utility>
#include <vector>

namespace c06_g1_doc {

template<std::ranges::view V>
class my_take_view : public std::ranges::view_interface<my_take_view<V>> {
    using difference_type = std::ranges::range_difference_t<V>;

    class guarded_iterator {
        std::ranges::iterator_t<V> current_{};
        std::ranges::sentinel_t<V> last_{};
        difference_type remaining_{};

    public:
        using value_type = std::ranges::range_value_t<V>;
        using difference_type = std::ranges::range_difference_t<V>;
        using iterator_concept = std::input_iterator_tag;

        guarded_iterator() = default;
        guarded_iterator(std::ranges::iterator_t<V> current,
                         std::ranges::sentinel_t<V> last,
                         difference_type remaining)
            : current_(std::move(current)), last_(std::move(last)), remaining_(remaining) {}

        decltype(auto) operator*() const { return *current_; }

        guarded_iterator& operator++() {
            if (remaining_ > 0 && current_ != last_) {
                ++current_;
                --remaining_;
            }
            return *this;
        }

        void operator++(int) { ++*this; }

        friend bool operator==(const guarded_iterator& it, std::default_sentinel_t) {
            return it.remaining_ <= 0 || it.current_ == it.last_;
        }
    };

public:
    my_take_view() = default;

    my_take_view(V base, difference_type count)
        : base_(std::move(base)), count_(count) {
        if (count < 0) {
            throw std::invalid_argument("my_take_view requires a non-negative count");
        }
    }

    auto begin() {
        if constexpr (std::ranges::random_access_range<V> && std::ranges::sized_range<V>) {
            return std::ranges::begin(base_);
        } else if constexpr (std::ranges::sized_range<V>) {
            return std::counted_iterator{std::ranges::begin(base_), clamped_count()};
        } else {
            return guarded_iterator{std::ranges::begin(base_), std::ranges::end(base_), count_};
        }
    }

    auto end() {
        if constexpr (std::ranges::random_access_range<V> && std::ranges::sized_range<V>) {
            return std::ranges::begin(base_) + clamped_count();
        } else {
            return std::default_sentinel;
        }
    }

    auto size() requires std::ranges::sized_range<V> {
        return static_cast<std::ranges::range_size_t<V>>(clamped_count());
    }

private:
    difference_type clamped_count() {
        auto size = static_cast<difference_type>(std::ranges::size(base_));
        return std::min(count_, size);
    }

    V base_{};
    difference_type count_{};
};

template<std::ranges::viewable_range R>
my_take_view(R&&, std::ranges::range_difference_t<R>) -> my_take_view<std::views::all_t<R>>;

} // namespace c06_g1_doc

template<class R>
std::vector<int> collect(R&& range) {
    std::vector<int> out;
    for (int value : range) out.push_back(value);
    return out;
}

int main() {
    using c06_g1_doc::my_take_view;

    std::vector<int> vec{1, 2, 3, 4, 5};
    my_take_view first_three{vec, 3};
    static_assert(std::ranges::view<decltype(first_three)>);
    static_assert(std::ranges::common_range<decltype(first_three)>);
    static_assert(std::ranges::sized_range<decltype(first_three)>);
    assert(collect(first_three) == std::vector<int>({1, 2, 3}));
    assert(first_three.front() == 1);
    assert(first_three.back() == 3);
    assert(first_three[1] == 2);
    assert(first_three.size() == 3u);

    std::list<int> list{1, 2, 3};
    my_take_view list_take{list, 10};
    static_assert(!std::ranges::common_range<decltype(list_take)>);
    assert(collect(list_take) == std::vector<int>({1, 2, 3}));
    assert(list_take.size() == 3u);

    std::istringstream input{"7 8"};
    my_take_view stream_take{std::views::istream<int>(input), 5};
    static_assert(std::ranges::input_range<decltype(stream_take)>);
    static_assert(!std::ranges::common_range<decltype(stream_take)>);
    assert(collect(stream_take) == std::vector<int>({7, 8}));

    bool threw = false;
    try {
        my_take_view invalid{vec, -1};
        (void)invalid;
    } catch (const std::invalid_argument&) {
        threw = true;
    }
    assert(threw);
}
```

### 进阶任务

**A. 分支行为可观察验证**

给 `begin()` / `end()` 三条路径加日志：`std::vector<int>` 触发 random-access+sized，`std::list<int>` 触发 sized 非 random-access，单遍 input/non-common/unsized range 触发 guarded iterator。

```cpp
// C++20: -std=c++20
#include <ranges>
#include <list>
#include <iostream>
#include <iterator>

// 沿用上面的 my_take_view 定义...

int main() {
    std::list<int> lst{10, 20, 30, 40, 50};

    // 注意：size() 成员被 requires 约束保护，list 是 sized_range 所以仍然提供
    static_assert(std::ranges::sized_range<decltype(tv_lst)>,

    int n = 0;
    for (int x : tv_lst) {
        std::cout << x << ' ';
        ++n;
    }
    std::cout << "\ntook " << n << " elements\n";  // 应为 3
```

**B. view_interface 自动注入条件表**

| 成员             | 注入条件                                                           |
|------------------|--------------------------------------------------------------------|
| `empty()`        | `sized_range<D>` 或 `forward_range<D>`（比较 begin == end）        |
| `operator bool()`| 同 `empty()`（返回 `!empty()`）                                    |
| `size()`         | `forward_range<D>` 且 `end() - begin()` 合法（`common_range` + 差）；或 `Derived` 自己提供 `size()` |
| `front()`        | `forward_range<D>`                                                 |
| `back()`         | `bidirectional_range<D>` 且 `common_range<D>`                      |
| `operator[](n)`  | `random_access_range<D>`                                           |
| `data()`         | `contiguous_range<D>`                                              |
| `cbegin/cend()`  | 始终注入（调用 `const_iterator<D>` 包装）                          |

**C. enable_view 的三条等价路径**

```cpp
// 路径 1：继承 view_interface（最常用，隐式 enable_view）
template<std::ranges::view V>
class MyView1 : public std::ranges::view_interface<MyView1<V>> { /*...*/ };

// 路径 2：继承 view_base（不注入成员，只满足 enable_view）
class MyView2 : public std::ranges::view_base { /*...*/ };

// 路径 3：显式特化变量模板（适用于无法修改基类的情况）
class MyView3 { /*...*/ };
template<> inline constexpr bool std::ranges::enable_view<MyView3> = true;

// 三者都满足 std::ranges::view concept（前提是各自还满足 range + movable）
```

### 验收点

- `static_assert(std::ranges::view<my_take_view<...>>)` 编译通过。
- `my_take_view{vec, 4}` 推导指引生效，无需显式模板参数。
- `random_access + sized` 底层时 `common_range` 且 `sized_range`；`bidirectional` 底层时非 `common_range`。
- `view_interface` 注入的 `empty()` / `front()` / `back()` / `operator[]` 可以直接使用。
- 你能解释 `view_interface` 为什么不提供 `begin()` / `end()`，以及 CRTP 的"向下转型"机制。

### 观察点

- `view_interface` 的核心实现模式：`constexpr bool empty() { return ranges::begin(derived()) == ranges::end(derived()); }`，其中 `derived()` 是 `static_cast<Derived&>(*this)`。它只是语法糖，所有逻辑依赖 `Derived::begin()` 和 `Derived::end()`。
- 继承 `view_interface` 并不意味着你的类型自动满足 view concept——你还需要满足 `movable`、`default_initializable`（C++20 原始要求，P2325R3 后放宽）、以及实际上能被 range 消费（begin/end 合法）。
- 这道题与模块 B 的 `views::take` 是镜像关系：B 里你是"使用 take_view"，G-1 里你是"实现 take_view"，两者的 begin/end 逻辑完全对应。

### 常见坑

- **忘继承 `view_interface`**：导致 `empty()` / `front()` 等默认成员缺失，但仍然满足 `range`——这会让你误以为所有成员都需要手写。
- **`begin()` 和 `end()` 返回类型不构成有效 iterator/sentinel 对**：编译器在 range-for 或算法里会给出非常嘈杂的 concept 失败信息，优先检查 `begin()` 的返回类型是否满足 `input_iterator`。
- **没写推导指引导致 `my_take_view(vec, 3)` 推导失败**：因为构造函数参数类型是 `V`（已是 view），但用户传入 `vec`（是 `vector<int>&`，非 view），编译器无法推导 `V`。推导指引在 `R&&` 层面接受 viewable_range，然后用 `views::all_t<R>` 映射到 view 类型。
- **`end()` 路径 A 里用 `ranges::distance` 而非 `ranges::size`**：对 sized_range 应用 `distance` 是合法的，但 `size` 更直接；另一个细节是 `min` 需要处理类型统一（`ptrdiff_t` vs `size_t`）。

### 提示

- 先只实现路径 A（random_access + sized），把 static_assert 跑通，再加路径 B 的 if constexpr 分支。
- 调试 CRTP 失败时，单独写 `auto x = tv.empty(); (void)x;` 并读编译器里"要求 begin() 返回…"之类的提示。
- deduction guide 如果写不对，先用显式模板参数 `my_take_view<std::views::all_t<decltype(v)>>{v, 4}` 确认逻辑正确，再回来修 guide。

### 复盘问题

- `view_interface` 的 `size()` 注入条件是什么？和你自己提供的 `size()` 成员有优先级冲突吗？
- 如果你不继承 `view_interface` 但手写了所有等价成员，`enable_view` 需要怎么处理？
- P2325R3 放宽了 view concept 的 `default_initializable` 要求之后，你的实现哪些地方可以简化？
- 为什么 `view_interface` 注入的 `back()` 要求 `common_range`？如果 end() 类型是 sentinel，如何实现等价的 back()？

## 练习 G-2：my_transform_view + range_adaptor_closure

### 目标

实现一个带闭包 pipe 语法的 `my_transform_view<V, F>`，以及配套的 `my_transform_closure<F>` 和工厂对象 `my_transform`，验证 `vec | my_transform(sq)` / `vec | my_transform(sq) | my_transform(inc)` / `my_transform(sq) | my_transform(inc)` 三种用法全部工作。

### 前置理解

- 你已完成 G-1，理解 `view_interface` 的 CRTP 机制。
- 你知道模块 B 里 `range_adaptor_closure` 是什么：绑定了除 range 参数外所有参数的部分应用对象，`operator|` 把 range 填进去返回 view。
- P2387R3 将 `std::ranges::range_adaptor_closure` 正式化：继承它的类型自动获得 `operator|(range, closure)` 以及 `operator|(closure, closure)` 两个重载。
- 你接受这题的核心难点是 iterator 的 `value_type` / `reference` 类型推导，以及 closure 的值语义（不能存引用）。

### 必做任务

```cpp
// C++26 default for this course; range_adaptor_closure is the standard pipe base.
#include <cassert>
#include <concepts>
#include <functional>
#include <iterator>
#include <memory>
#include <ranges>
#include <sstream>
#include <type_traits>
#include <utility>
#include <vector>

namespace c06_g2_doc {

namespace detail {
template<class It>
concept has_iterator_category = requires { typename std::iterator_traits<It>::iterator_category; };

template<class It, class Ref>
struct iterator_category_for {
    using iterator_category = std::input_iterator_tag;
};

template<class It, class Ref>
    requires std::is_lvalue_reference_v<Ref> && has_iterator_category<It>
struct iterator_category_for<It, Ref> {
    using iterator_category = typename std::iterator_traits<It>::iterator_category;
};
} // namespace detail

template<std::ranges::view V, std::move_constructible F>
    requires std::is_object_v<F> &&
             std::regular_invocable<F&, std::ranges::range_reference_t<V>>
class my_transform_view : public std::ranges::view_interface<my_transform_view<V, F>> {
    class sentinel;

    class iterator : public detail::iterator_category_for<
        std::ranges::iterator_t<V>,
        std::invoke_result_t<F&, std::ranges::range_reference_t<V>>> {
        using base_iterator = std::ranges::iterator_t<V>;
        F* function_{};
        base_iterator current_{};

    public:
        using reference = std::invoke_result_t<F&, std::ranges::range_reference_t<V>>;
        using value_type = std::remove_cvref_t<reference>;
        using difference_type = std::ranges::range_difference_t<V>;
        using iterator_concept =
            std::conditional_t<std::random_access_iterator<base_iterator>, std::random_access_iterator_tag,
            std::conditional_t<std::bidirectional_iterator<base_iterator>, std::bidirectional_iterator_tag,
            std::conditional_t<std::forward_iterator<base_iterator>, std::forward_iterator_tag,
            std::input_iterator_tag>>>;

        iterator() = default;
        iterator(F& function, base_iterator current)
            : function_(&function), current_(std::move(current)) {}

        reference operator*() const { return std::invoke(*function_, *current_); }
        iterator& operator++() { ++current_; return *this; }
        iterator operator++(int) requires std::forward_iterator<base_iterator> { auto old = *this; ++*this; return old; }
        void operator++(int) { ++*this; }
        iterator& operator--() requires std::bidirectional_iterator<base_iterator> { --current_; return *this; }
        iterator operator--(int) requires std::bidirectional_iterator<base_iterator> { auto old = *this; --*this; return old; }
        iterator& operator+=(difference_type n) requires std::random_access_iterator<base_iterator> { current_ += n; return *this; }
        iterator& operator-=(difference_type n) requires std::random_access_iterator<base_iterator> { current_ -= n; return *this; }
        iterator operator+(difference_type n) const requires std::random_access_iterator<base_iterator> { auto out = *this; out += n; return out; }
        friend iterator operator+(difference_type n, iterator it) requires std::random_access_iterator<base_iterator> { return it + n; }
        iterator operator-(difference_type n) const requires std::random_access_iterator<base_iterator> { auto out = *this; out -= n; return out; }
        difference_type operator-(const iterator& other) const requires std::random_access_iterator<base_iterator> { return current_ - other.current_; }
        reference operator[](difference_type n) const requires std::random_access_iterator<base_iterator> { return std::invoke(*function_, current_[n]); }
        bool operator==(const iterator& other) const requires std::equality_comparable<base_iterator> { return current_ == other.current_; }
        auto operator<=>(const iterator& other) const requires std::random_access_iterator<base_iterator> { return current_ <=> other.current_; }

        friend class sentinel;
    };

    class sentinel {
        std::ranges::sentinel_t<V> last_{};
        bool equal(const iterator& it) const { return it.current_ == last_; }

    public:
        sentinel() = default;
        explicit sentinel(std::ranges::sentinel_t<V> last) : last_(last) {}
        friend bool operator==(const iterator& it, const sentinel& s) { return s.equal(it); }
        friend bool operator==(const sentinel& s, const iterator& it) { return s.equal(it); }
    };

public:
    my_transform_view() = default;
    my_transform_view(V base, F function)
        : base_(std::move(base)), function_(std::move(function)) {}

    iterator begin() { return iterator{function_, std::ranges::begin(base_)}; }

    auto end() {
        if constexpr (std::ranges::common_range<V>) {
            return iterator{function_, std::ranges::end(base_)};
        } else {
            return sentinel{std::ranges::end(base_)};
        }
    }

    auto size() requires std::ranges::sized_range<V> { return std::ranges::size(base_); }

private:
    V base_{};
    F function_{};
};

template<std::ranges::viewable_range R, class F>
my_transform_view(R&&, F) -> my_transform_view<std::views::all_t<R>, F>;

template<std::move_constructible F>
class my_transform_closure : public std::ranges::range_adaptor_closure<my_transform_closure<F>> {
public:
    explicit my_transform_closure(F function) : function_(std::move(function)) {}

    template<std::ranges::viewable_range R>
        requires std::copy_constructible<F> &&
                 std::regular_invocable<F&, std::ranges::range_reference_t<R>>
    auto operator()(R&& range) const& {
        return my_transform_view{std::views::all(std::forward<R>(range)), function_};
    }

    template<std::ranges::viewable_range R>
        requires std::regular_invocable<F&, std::ranges::range_reference_t<R>>
    auto operator()(R&& range) && {
        return my_transform_view{std::views::all(std::forward<R>(range)), std::move(function_)};
    }

private:
    F function_;
};

struct my_transform_fn {
    template<std::move_constructible F>
    auto operator()(F function) const {
        return my_transform_closure<F>{std::move(function)};
    }

    template<std::ranges::viewable_range R, std::move_constructible F>
        requires std::regular_invocable<F&, std::ranges::range_reference_t<R>>
    auto operator()(R&& range, F function) const {
        return my_transform_view{std::views::all(std::forward<R>(range)), std::move(function)};
    }
};

    MoveOnlyAdd& operator=(MoveOnlyAdd&&) = default;
    MoveOnlyAdd(const MoveOnlyAdd&) = delete;
    MoveOnlyAdd& operator=(const MoveOnlyAdd&) = delete;
    int operator()(int value) { return value + *delta; }
};

template<class R>
std::vector<int> collect(R&& range) {
    std::vector<int> out;
    for (int value : range) out.push_back(value);
    return out;
}

int main() {

    auto squared = values | my_transform(square);
    static_assert(std::ranges::random_access_range<decltype(squared)>);
    assert(collect(squared) == std::vector<int>({1, 4, 9}));

    auto composed = values | (my_transform(square) | my_transform(inc));
    assert(collect(composed) == std::vector<int>({2, 5, 10}));
```

### 观察点

- `range_adaptor_closure<Derived>` 是 P2387R3 的正式化成果。在此之前，标准库内部用 `__range_adaptor_closure_t`（libstdc++ 命名）等实现类似效果，P2387R3 把它暴露给用户代码。这是从模块 B 的"使用 `|`"到模块 G 的"实现 `|`"的直接连接。
- iterator 的 `f_` 成员存的是 `F*`（指向 view 的 `f_` 字段），而不是 `F` 值。这避免了函数对象在迭代器间被重复拷贝，但要求迭代器的生命周期在 view 之内。
- `iterator_category` 和 `iterator_concept` 的设置需要区分：`invoke` 结果通常是 prvalue，C++17 视角保守降到 `input_iterator_tag`；只有真实左值引用且底层暴露 `iterator_category` 时才继承底层。C++20 的 `iterator_concept` 可以按底层能力继承。

### 常见坑

- **忘继承 `range_adaptor_closure`**：导致 `vec | my_transform(sq)` 找不到 `operator|`，编译报"no match for operator|"，误以为是 view 定义问题。
- **iterator 存 F 引用而非指针/值**：closure 是临时对象，iterator 如果存闭包的引用，在 `auto r = vec | my_transform(sq);` 后 closure 被销毁，iterator 的引用悬垂。正确做法是 view 值持有 `F`，iterator 持有指向 view 里 `f_` 字段的指针。
- **`value_type` 写成 `invoke_result_t<F&, range_reference_t<V>>`（未 decay）**：`value_type` 应该是"元素的值类型"，不能是引用。应为 `remove_cvref_t<invoke_result_t<F&, range_reference_t<V>>>`。
- **`operator|` 被定义为成员函数**：`operator|` 必须是非成员（或 friend）重载，否则当左操作数是 range（不是 closure 的子类）时无法匹配。`range_adaptor_closure` 提供的 `operator|` 是 hidden friend，不需要你自己定义。

### 提示

- 先只实现 `my_transform_view`（没有 closure）和直接调用形式 `my_transform(vec, sq)`，验证正确后再加 closure 和 `|` 支持。

## 练习 G-3：my_enumerate_view + enable_borrowed_range

### 目标

实现一个 enumerate view，产出 `(index, element)` pair，并根据底层 range 是否 `borrowed_range` 来决定自身是否 borrowed；配套实现 `my_enumerate_closure` 和 `my_enumerate_fn`，验证与 `my_transform_view`（G-2）的组合。

### 前置理解

- 你已完成 G-1 / G-2，理解 `view_interface` 和 `range_adaptor_closure`。
- 你知道 `enable_borrowed_range` 的语义：见心智模型（01）的 borrowed_range 章节——迭代器有效性不依赖 view 对象的生命周期时才能标记为 borrowed。
- 你接受 enumerate view 的 iterator 产出 proxy pair（非真实左值引用），因此 `iterator_category` 最高为 `input_iterator_tag`，但 `iterator_concept` 可以继承底层（上界 random_access）。

### 必做任务

```cpp
// C++20: -std=c++20
#include <ranges>
#include <iterator>
#include <concepts>
#include <utility>    // std::pair
#include <vector>
#include <list>
#include <string_view>
#include <cassert>
#include <iostream>

// ── my_enumerate_view<V> ──────────────────────────────────────────────────────
//
// iterator 维护 range_difference_t<V> idx + 底层迭代器 it_
// operator* 返回 std::pair<range_difference_t<V>, range_reference_t<V>>（proxy pair）
//
// borrowed_range 标记：
//   如果 V 是 borrowed_range，则 my_enumerate_view<V> 也是 borrowed_range。
//   条件特化：
//   template<std::ranges::view V>
//   inline constexpr bool
//     std::ranges::enable_borrowed_range<my_enumerate_view<V>> =
//       std::ranges::enable_borrowed_range<V>;

template <std::ranges::view V>
class my_enumerate_view
    : public std::ranges::view_interface<my_enumerate_view<V>> {

    // ── inner iterator ────────────────────────────────────────────────────────
    struct iterator {
    private:
        using InnerIt = std::ranges::iterator_t<V>;
        InnerIt it_{};
        std::ranges::range_difference_t<V> idx_{};

    public:
        using reference     = std::pair<std::ranges::range_difference_t<V>, std::ranges::range_reference_t<V>>;
        using value_type    = std::pair<std::ranges::range_difference_t<V>,
                                        std::ranges::range_value_t<V>>;
        using difference_type = std::ranges::range_difference_t<V>;

        // iterator_concept：继承底层，上界 random_access
        using iterator_concept =
            std::conditional_t<
                std::random_access_iterator<InnerIt>,
                std::random_access_iterator_tag,
            std::conditional_t<
                std::bidirectional_iterator<InnerIt>,
                std::bidirectional_iterator_tag,
            std::conditional_t<
                std::forward_iterator<InnerIt>,
                std::forward_iterator_tag,
                std::input_iterator_tag
            >>>;

        // iterator_category：proxy pair 是 prvalue → input_iterator_tag
        // （C++17 算法要求 *it 是可赋值的左值；pair<difference_type, T&> 不完全满足该要求）
        // 注：C++23 的标准 views::enumerate（P2164）用带命名类型的 proxy 并按
        // 底层 iterator_category 继续细分 category；这里简化为一律 input 以回避规则差异。
        using iterator_category = std::input_iterator_tag;

        iterator() = default;
        constexpr iterator(InnerIt it, std::ranges::range_difference_t<V> idx) : it_(std::move(it)), idx_(idx) {}

        constexpr reference operator*() const {
            return reference{idx_, *it_};
        }

        constexpr iterator& operator++() {
            ++it_;
            ++idx_;
            return *this;
        }

        constexpr iterator operator++(int)
            requires std::forward_iterator<InnerIt>
        {
            auto tmp = *this;
            ++(*this);
            return tmp;
        }

        constexpr void operator++(int) {
            ++(*this);
        }

        constexpr iterator& operator--()
            requires std::bidirectional_iterator<InnerIt>
        {
            --it_;
            --idx_;
            return *this;
        }

        constexpr iterator operator--(int)
            requires std::bidirectional_iterator<InnerIt>
        {
            auto tmp = *this;
            --(*this);
            return tmp;
        }

        constexpr iterator& operator+=(difference_type n)
            requires std::random_access_iterator<InnerIt>
        {
            it_  += n;
            idx_ += n;
            return *this;
        }

        constexpr iterator& operator-=(difference_type n)
            requires std::random_access_iterator<InnerIt>
        {
            it_  -= n;
            idx_ -= n;
            return *this;
        }

        constexpr iterator operator+(difference_type n) const
            requires std::random_access_iterator<InnerIt>
        { return iterator{it_ + n, idx_ + n}; }

        friend constexpr iterator operator+(difference_type n, const iterator& it)
            requires std::random_access_iterator<InnerIt>
        { return it + n; }

        constexpr iterator operator-(difference_type n) const
            requires std::random_access_iterator<InnerIt>
        { return iterator{it_ - n, idx_ - n}; }

        constexpr difference_type operator-(const iterator& other) const
            requires std::random_access_iterator<InnerIt>
        { return it_ - other.it_; }

        constexpr reference operator[](difference_type n) const
            requires std::random_access_iterator<InnerIt>
        { return reference{idx_ + n, it_[n]}; }

        constexpr bool operator==(const iterator& other) const
            requires std::equality_comparable<InnerIt>
        { return it_ == other.it_; }

        constexpr bool operator!=(const iterator& other) const
            requires std::equality_comparable<InnerIt>
        { return it_ != other.it_; }

        constexpr auto operator<=>(const iterator& other) const
            requires std::random_access_iterator<InnerIt>
        { return it_ <=> other.it_; }

        // iter_move：因为 reference 是 proxy pair，需要显式提供 iter_move
        // 让 ranges::iter_move 返回 pair<difference_type, range_rvalue_reference_t<V>>
        // 这样 ranges::sort 可以正确移动元素（如果底层支持）
        friend constexpr auto iter_move(const iterator& it)
            noexcept(noexcept(std::ranges::iter_move(it.it_)))
        {
            return std::pair<std::ranges::range_difference_t<V>,
                             std::ranges::range_rvalue_reference_t<V>>{
                it.idx_,
                std::ranges::iter_move(it.it_)
            };
        }
    };

public:
    my_enumerate_view() = default;

    explicit constexpr my_enumerate_view(V base)
        : base_(std::move(base)) {}

    constexpr iterator begin() {
        return iterator{std::ranges::begin(base_), 0};
    }

    constexpr iterator end()
        requires std::ranges::common_range<V>
    {
        return iterator{std::ranges::end(base_),
                        static_cast<std::size_t>(std::ranges::distance(base_))};
    }

    constexpr auto end()
        requires (!std::ranges::common_range<V>)
    {
        return std::ranges::end(base_);
    }

    constexpr auto size()
        requires std::ranges::sized_range<V>
    { return std::ranges::size(base_); }

    constexpr V base() const& { return base_; }
    constexpr V base() &&     { return std::move(base_); }

private:
    V base_{};
};

// ── 推导指引 ──────────────────────────────────────────────────────────────────
template <std::ranges::viewable_range R>
my_enumerate_view(R&&) -> my_enumerate_view<std::views::all_t<R>>;

// ── enable_borrowed_range 条件特化 ────────────────────────────────────────────
//
// 语义：my_enumerate_view 的迭代器持有 InnerIt（来自 V）。
// 若 V 是 borrowed_range，则 InnerIt 在 V 销毁后仍有效，
// 但 idx_ 是 view 内部的值，实际上迭代器内部复制了 idx，
// 不依赖 view 对象——因此借用语义可以透传。
//
// 注意：即使 V 不是 borrowed_range，迭代器也存储了 idx 的值拷贝；
// 但 InnerIt 的有效性依赖 V 底层数据，所以整体跟随 V 的 borrowed 状态。

template <std::ranges::view V>
inline constexpr bool
    std::ranges::enable_borrowed_range<my_enumerate_view<V>> =
        std::ranges::enable_borrowed_range<V>;

// ── my_enumerate_closure + my_enumerate_fn ────────────────────────────────────

class my_enumerate_closure
    : public std::ranges::range_adaptor_closure<my_enumerate_closure> {
public:
    template <std::ranges::viewable_range R>
    constexpr auto operator()(R&& r) const {
        return my_enumerate_view{std::views::all(std::forward<R>(r))};
    }
};

struct my_enumerate_fn {
    // 无参数调用 → 返回 closure（等待 range）
    constexpr my_enumerate_closure operator()() const {
        return my_enumerate_closure{};
    }

    // 直接传入 range → 立即构造 view
    template <std::ranges::viewable_range R>
    constexpr auto operator()(R&& r) const {
        return my_enumerate_view{std::views::all(std::forward<R>(r))};
    }
};

inline constexpr my_enumerate_fn my_enumerate{};

// ── 验证 ──────────────────────────────────────────────────────────────────────

int main() {
    std::vector<int> vec{10, 20, 30, 40, 50};

    // 基础迭代：验证 (index, value) pair
    {
        std::size_t expected_idx[] = {0, 1, 2, 3, 4};
        int         expected_val[] = {10, 20, 30, 40, 50};

    {

        for (auto [idx, val] : vec | my_enumerate()) {

            assert(val == vec[i]);

        }
        std::cout << "管道语法通过\n";
```

- 模块 B 里你观察到 `filter_view` 缓存 `begin()`；这道题的 `end()` 对 `common_range` 底层调用了 `ranges::distance(base_)` 来计算 end-index。注意这里 distance 是 O(1)（因为只进入 common_range 分支，且 distance 对 sized_range 是 O(1)）——但如果你在 end() 里对非 sized_range 调用 distance，就变成 O(n)。要小心。

### 常见坑

- **忘了 `enable_borrowed_range` 条件特化**：导致把 `my_enumerate_view<string_view>` 的右值传给算法时返回 `dangling`，而不是真正的迭代器。这是一个静默的正确性问题，不会有明显编译错误，只是行为不符合预期。
- **`index_type` 用 `int`**：对超过 `INT_MAX` 个元素的 range 会溢出（有符号溢出是 UB）。应使用 `range_difference_t<V>`，让 index 与迭代器差值类型一致。
- **`reference` 写成 `pair<difference_type&, T&>`**：index 不是底层 range 里存储的数据，不能返回对 `idx_` 的引用——因为 `idx_` 是迭代器内部的局部状态，`operator*` 返回后就是悬垂引用。正确做法是 `pair<difference_type, T&>`：index 是值，element 是引用。
- **end() 对 common_range 分支调用 `ranges::distance` 而底层不是 sized_range**：`distance` 对非 sized_range 是 O(n)，导致每次 `end()` 调用都遍历一次底层序列。解决方案是把 distance 改为 size（在 sized_range 底层时），或者不缓存 end-index（让 end() 返回 sentinel 配合检测 it == inner_end）。

### 提示

- 先只实现最简 iterator（input only），跑通基础迭代，再逐步添加 `bidirectional` 和 `random_access` 的运算符（使用 `requires` 约束保护）。
- `enable_borrowed_range` 特化必须在 `my_enumerate_view` 定义之后、但在 `main` 使用之前出现——模板特化的可见性是编译期的，确保顺序正确。

## 做完模块 G 之后，你现在应该能说清楚什么

至少把下面几句话说顺：

- `view_interface` 是脚手架：它通过 CRTP 向下转型调用 `Derived::begin()` / `Derived::end()`，按条件注入 `empty()` / `front()` / `back()` / `operator[]` / `size()` / `data()`——但它不负责存储任何数据，也不提供 `begin()` / `end()`，这两个必须由你的类型提供。
- `enable_view<MyView> = true` 是你对框架的语义承诺，不是框架对你的验证：你声明该类型满足 O(1) move / copy / destroy 三条公理，标准库相信你，并在 adaptor 组合时依赖这些公理。
- `enable_borrowed_range<MyView> = true`（或条件特化）是"迭代器有效性不依赖 view 对象生命周期"的标记，决定右值传给算法时是返回真迭代器还是 `dangling`。这不是性能优化，是正确性承诺。
- `range_adaptor_closure<Derived>` 是 pipe 语法的接入点：继承它之后，`range | closure` 和 `closure | closure` 两个 `operator|` 重载自动可用，你只需要实现 `operator()(range)` 这一个调用接口。
- CTAD 推导指引让用户写 `my_take_view{vec, 3}` 而非 `my_take_view<ref_view<vector<int>>>{vec, 3}`：指引在 `viewable_range R` 层面接受参数，用 `views::all_t<R>` 映射到对应 view 类型。

**三件套总结**：view_interface 是脚手架，range_adaptor_closure 是 pipe 语法的接入点，enable_borrowed_range 是"我值得信任"的承诺。三件套让你自己的 view 无缝接入标准 ranges 管道。

## 本轮实现校准：G1/G2/G3

G1 的 `my_take` 明确采用教学安全接口：负 `count` 抛 `std::invalid_argument`。这不同于 `std::views::take` 的非负前提。实现上必须区分三类 end：random-access + sized 可用 `begin + min(n, size)`；sized 非 random-access 可用已截断计数；unsized 必须在迭代器/哨兵比较中同时检查“剩余计数为 0”或“底层已经到 end”，否则 `n` 大于短输入时会越界。

G2 的 `my_transform` 保留标准 closure 组合路径，要求 stateful callable 按 view 状态保存，move-only callable 可通过右值 closure 进入 view，`operator*` 可返回 prvalue。good/reference 都不依赖对方，bad 用“每次解引用复制 callable”暴露多余复制；checker通过复制构造计数观察，不改变调用结果。stateful指保存参数，operator()仍须满足regular_invocable的相等性及不修改对象/参数要求。不能把依赖调用次数返回不同值的函数当成标准transform的合法输入。

G3 的 `my_enumerate` 按 C++23 enumerate 语义教学实现：返回 `(index, element)` proxy pair，`value_type` 与 `reference` 分开，`iter_move` 返回 `(index, element&&)`。`enable_borrowed_range` 只在底层 view borrowed 时透传：`string_view` 路径为正例，右值 `vector` 经 owning view 后是反例。borrowed 只承诺迭代器是否依赖 range 对象生命周期，不承诺元素所有者生命周期无限延长。

G2 的 `my_transform_view` 和 G3 的 `my_enumerate_view` 有同一个 non-common range 约束：只要工厂接受 `viewable_range`，就必须让 wrapper iterator 能和 end sentinel 比较。对 `std::views::istream<T>` 这类 input/non-common/move-only iterator，正确实现同时需要移动构造底层 iterator，并惰性暴露 `iterator_category`，避免提前实例化不存在的 `iterator_traits<It>::iterator_category`。
