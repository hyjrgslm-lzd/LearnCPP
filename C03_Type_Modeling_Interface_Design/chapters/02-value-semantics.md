# 02：值语义

值语义的核心是：复制得到同样的值，但两个对象可以独立变化。C02 已讲深复制和资源释放；C03 关心接口层的承诺：比较看什么，复制后哪些观察相同，修改副本是否影响原对象，`swap` 是否能作为提交点。

值和身份要先分开。`Money{1200, "CNY"}` 的身份是某个 C++ 对象；它的值是 1200 分人民币。复制后有两个对象身份，但值相等。`Socket{fd=12}` 的值若直接等于文件描述符，就会诱导复制；更合理的接口通常删除复制，只允许移动，因为它建模的是一个运行期资源身份。

`Money{1200, "CNY"}` 的值由金额和币种组成。两个对象相等，表示它们公开观察到的金额和币种相同，不表示它们共享同一块存储。`operator+` 只能合并同币种金额；币种不同不是一个可偷偷转换的状态，必须通过错误通道报告。

好的值类型通常满足：

- 默认、复制、移动、析构语义清楚。
- 相等比较只看值，不看地址。
- 操作返回新值时不修改输入，除非名字明确表示原地修改。
- `swap` 若声明 `noexcept`，就不能在交换中分配或抛异常。

接近标准库算法期望的普通值类型通常还接近 regular：可默认构造、可复制、可移动、可相等比较，复制后保持相等，赋值后目标等于来源。不是每个类型都必须 regular；但如果一个类型看起来像值，却在复制后共享可变内部状态，它会破坏调用者直觉。

相等、排序和哈希必须使用同一个语义。反例：

```cpp
struct Money {
    long long cents;
    std::string currency;
};

bool operator==(const Money& a, const Money& b) {
    return a.cents == b.cents; // wrong: ignores currency
}

bool operator<(const Money& a, const Money& b) {
    return std::tie(a.currency, a.cents) < std::tie(b.currency, b.cents);
}
```

这里 `Money{100, "CNY"} == Money{100, "USD"}` 为真，但排序又把它们分开。放入 `std::set`、`std::map` 或用作缓存 key 时，调用者无法得到一致规则。若相等看 `currency+cents`，排序和哈希也要看同一组字段。若业务需要按金额排序，应把它命名为 `by_amount` 比较器，而不是伪装成自然顺序。

语义公理不是数学装饰，它们直接保护容器和算法：

- 自反：`a == a` 为真。
- 对称：`a == b` 与 `b == a` 相同。
- 传递：`a == b` 且 `b == c` 时 `a == c`。
- 等值哈希一致：`a == b` 时 `hash(a) == hash(b)`。
- 严格弱序：`less(a, a)` 为假，且排序不会形成环。

违反这些公理，程序不一定马上崩溃，但容器查找、去重、缓存命中都会变成偶发错误。C03 的值类型练习会用同一个 checker 同时检查加法、比较、排序和哈希，防止只修一个入口。

`swap` 对 C03 很重要，因为它常是 strong guarantee 的提交点。先在临时对象中完成所有可能失败的工作，再用不抛异常的交换一次性提交。若交换本身可能抛出，就不能作为强保证提交点。

练习 L02 要实现 `Money`。checker 会检查复制独立、同币种相加、异币种拒绝、失败后输入不变、排序和哈希与相等一致。坏变体会忽略币种，checker 应拒绝它。
