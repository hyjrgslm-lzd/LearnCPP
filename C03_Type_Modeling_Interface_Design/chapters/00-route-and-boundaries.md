# 00：类型建模与接口边界

C03 接在 C02 之后。C02 已经说明对象何时存在、资源何时获得和释放、引用何时失效。本课不重复对象生命期主线，而是回答另一个问题：一个类型公开了什么承诺，调用者怎样只依赖这些承诺，作者怎样在实现变化后仍保持承诺成立。

类型不是字段集合。类型是可构造状态、可观察操作、失败语义和不变量的组合。`class Account { int cents; };` 只声明了存储；`Account::withdraw(Money)` 如果说明了余额不得为负、失败时余额不变、金额单位一致，才形成接口契约。

接口边界要保护公有入口，而不是保护内部字段。私有字段只能阻止调用者直接写坏状态；真正的保护来自构造函数、工厂函数和每个公开成员。若 `Account::deposit(int cents)` 接受负数，`balance_` 私有也没有用，非法状态仍通过公有接口进入对象。

构造失败发生在对象尚未完成构造的阶段。此时没有完整对象可以调用成员函数，也不应要求调用者清理半个对象；C02 已经说明已完成成员会自动析构。C03 关心的是接口怎样表达这个阶段：直接构造可以抛异常拒绝非法输入，命名工厂可以先解析和校验输入，再只在成功时返回对象。两者都必须说明失败后没有产生可用对象。

对象完成构造后，接口承诺转向“每次公开函数返回时状态合法”。一个成员函数可以临时打破内部状态，只要它不把坏状态暴露出去，并且失败路径能恢复到声明的保证。06 章会把这件事写成 basic 与 strong guarantee。

本课按六层推进：

1. 类不变量：哪些状态合法，构造和每个公开操作如何保持合法。
2. 值语义：复制、移动、比较、交换和组合后，值的身份与资源身份如何分离。
3. 显式空值与多选状态：用 `std::optional` 和 `std::variant` 表达状态集合，不把哨兵值混进业务值。
4. 错误通道：用异常或 `std::expected` 表达失败，说明失败发生后对象处于什么状态。
5. 异常安全：区分 basic guarantee、strong guarantee 和 no-throw 操作，设计提交点。
6. 接口演进：组合、继承、静态/动态多态和类型擦除各适合什么边界。

C04 会系统讲模板推导、约束和定制点；本课只使用能解释当前接口问题所需的最小泛型知识。C06 会深入 range/view 和迭代器语义；本课只在接口返回序列时说明借用和失效。C08 之后才讨论并发访问契约；本课默认单线程对象，除非章节明确说明。

术语边界：

- 值：调用者能通过公开接口观察和比较的业务内容。
- 身份：这个对象占据的地址、句柄、数据库行或运行期实体。
- 资源：文件、内存、锁、socket 等需要释放或转交的东西。
- 表示：类型内部字段和辅助缓存，调用者不能直接依赖。

一个类型可以同时有值和资源。`std::string` 有动态内存资源，但它的公开语义是值；复制字符串得到独立值，不要求共享同一块内存。一个 socket wrapper 则通常是身份/资源类型，不应默认可复制。C03 要求每个接口先说清它是哪一种。

练习分两类。观察题给完整程序，运行只证明已执行的观察，不证明你已经完成预测和解释。实现题有 `src/student`、`src/reference`、`validation/good` 和 `validation/bad`，同一个 checker 会分别消费它们，防止学生代码调用答案或靠完成标记过关。
