# 13：间接值与多态值语义

`std::unique_ptr<T>` 表达独占所有权，`std::shared_ptr<T>` 表达共享所有权。它们解决资源归属，但不自动提供“值语义”。一个 `unique_ptr<Shape>` 被复制时无法深复制；一个 `shared_ptr<Shape>` 被复制时共享同一个对象，修改一处会影响另一处。第 09 章讲动态多态时，接口常需要“保存一个未知派生类型的对象，并且容器复制时也复制对象本身”。这就是 C++26 `std::indirect` 与 `std::polymorphic` 的动机。

`std::indirect<T>` 可以理解为“堆上对象的值包装器”。它通过间接存储获得稳定地址和较小外层对象，通过复制底层 `T` 获得值语义。它不是 nullable 指针模型：移动后可能进入 valueless 状态，访问前要满足有值前提。复制可能分配，也可能因 `T` 的复制构造失败而抛异常。const 传播也不同于裸指针：`const indirect<T>` 应让底层对象按 const 访问，避免 `const unique_ptr<T>` 那种“指针本身 const，但仍可改 pointee”的误读。

`std::polymorphic<T>` 面向开放派生集合。它保存一个动态类型为 `T` 派生类的对象，复制包装器时复制动态对象并保留动态类型。传统写法要在基类提供 `clone()` 虚函数，或者在外部维护工厂表；C++26 标准化的设施把这种“多态值”变成可组合的库类型。它仍然不是 magic：基类析构必须正确，克隆/分配失败仍要保持原对象状态，移动后源对象状态要按规范处理，allocator 参与对象创建和失败回收。

这一章最容易犯的错是把三类责任混成一个。`unique_ptr<Base>` 清楚表达“一个 owner”，适合不可复制对象和实体身份。`shared_ptr<Base>` 表达“共享同一实体”，适合观察者和共享生命周期，但复制不是深复制。多态值表达“复制时得到另一个等价对象”，适合命令、规则、策略、图形对象这类把动态类型当值使用的接口。如果业务语义是共享实体，强行改成多态值会制造重复状态；如果业务语义是值，使用 shared_ptr 会制造隐式别名。

C++26 设施本机当前未实现，所以正文必须完整讲设计边界，但可运行核心实验使用不同名的教学 `clone_value`。它只验证“深复制多态值”这个概念，不冒充 `std::polymorphic`。教学类型显式要求基类提供 `clone()`，复制构造调用 `clone()`，移动后源对象可以为空，访问空对象抛 `std::logic_error` 而不是模拟标准前置条件。这样实验安全、可重复，也能观察 clone 失败时原对象不被破坏。

allocator 边界在标准设施中更重要：复制动态对象时可能分配，构造失败要释放已获得资源；allocator propagation 会影响容器复制、移动和 swap 的 noexcept 条件。教学 `clone_value` 不实现 allocator 参数，因此它只能说明值复制、移动后空状态、const 传播和异常边界。源码阅读和实现状态仍以 `F01_frontier` 的 `c26_indirect_polymorphic.cpp` 为前沿入口；没有本机宏时返回 77，不能把教学类型改名成 `std::indirect` 或 `std::polymorphic`。

练习 L13 是观察型。Part 1 对比 `unique_ptr` 移动后源为空、`shared_ptr` 复制后共享同一对象、`clone_value` 复制后得到独立对象。Part 2 检查 const 访问：`const clone_value` 只能得到 `const Shape&`。Part 3 注入 clone 失败，证明目标对象仍保持原值，异常不会泄漏半构造对象。Part 4 观察移动后 valueless 边界，使用者必须先检查再访问。

完整解析：间接存储解决的是对象大小和动态类型问题，不直接定义业务身份。是否需要深复制由接口语义决定，而不是由“看起来是指针”决定。多态值适合把动态派发隐藏在值对象里；当对象代表外部资源、唯一句柄、数据库实体或 UI 控件身份时，复制出第二个动态对象往往是错误语义。C03 只建立模型；真正 `std::indirect/std::polymorphic` 的可用性由 C++26 工具链和 F01 探测决定。
