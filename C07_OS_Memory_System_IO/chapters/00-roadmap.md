# 00 从对象所有权走到操作系统

## 先弄清我们到底在管理什么

写 `std::vector<std::byte> buffer(4096)` 时，你看到的是 C++ 对象和元素；写 `ReadFile` 或 `read` 时，操作系统看到的是句柄、地址和长度。这两个世界有交集，但并不替你证明对方的条件。一个地址可能仍然映射，却已经没有那个 C++ 对象；一个对象可能仍然存在，但底层文件已经关闭；取消请求也可能已经返回，而内核还在使用缓冲区。

因此本课沿四层追踪责任：

1. **对象层**：谁拥有对象，什么时候构造、移动、析构？C02 已建立这层基础。
2. **资源层**：对象持有哪个 fd/HANDLE、映射或模块？复制的是数值，还是创建了一份内核引用？
3. **操作层**：一个请求是否已经被接受？提交、就绪、完成和取消分别改变了什么状态？
4. **证据层**：观察到的结果证明哪个条件？是否只是当前机器的一次执行？

这也是调试路线。看到“偶尔访问错误”时，不先猜一个智能指针类型：先画出对象、内核资源、请求之间的借用关系，再找关闭和完成的真实边界。

## 一个贯穿的任务

从读取资源文件开始。第一版用最普通的同步分块 I/O，正确处理尾段和失败。接下来研究映射如何把文件区域放入地址空间，再研究如何保留多份请求与缓冲，使完成通知驱动后续工作。三种方案有相同的成功输出检查，但不同的成本和生命周期条件。

这不是预先写好的“每版都更快”的故事。映射可能增加页错误或地址空间管理成本，异步路径可能因为工作量太小而不划算，池也可能保存过多内存。先对照代码与阶段数据判断成本，才能讨论改进。切换了持久性、等待方式、输入类型或取消保证时，明确说这是场景分支，而不是直接计算加速比。

有些机制不应硬塞进文件复制器。epoll 主要实验使用 pipe/socket/eventfd，因为 readiness 要回答“接下来进行 I/O 是否会阻塞”；普通文件不提供我们要研究的那类事件等待。IPC、动态装载和页保护分别用局部实验，最后再回访它们如何支持真实应用。

## 阅读顺序与先修

初学系统编程时先读 01—03，能解释句柄独占、错误捕获、短读写和 EOF 后再分支：

- 内存路线：04—08，先分清地址、页、对象，再讲 allocator/pmr。不要以地址可访问代替对象生命周期合法。
- 进程路线：09—10 与 15，理解子进程、继承、IPC、等待与模块卸载。
- 异步路线：11—14，先分清非阻塞、就绪与完成，再处理取消和关闭。这里只使用有限的单线程事件循环，不要求已有线程池或协程库。
- 综合路线：16—18，验证跨单元责任、阅读固定源码、检查性能结论的证据。

源码阅读中若涉及 release/acquire 等并发机制，再回访 C08 对应单元；C07 的入门单元不要求先完成整门 C08。C09 的 awaiter 和 C10 的 operation_state 会承接本课的请求存活责任，但它们各自的恢复/完成协议仍需单独学习。

## 如何做练习

先读练习说明里的契约和编辑位置。实现型题编译的是你自己的头文件，Reference 是另一份实现；输入、基础平台设施和 checker 可以共享。Student 初始拒绝运行或检查失败是明确的作业状态，不能通过改“完成”标志、输出预填答案或调用 Reference 解决。

观察型题可以一开始就通过：这只证明实际执行的检查成立。运行前写下预测，运行后解释差异，并指出观察边界。例如，在一个小文件上没有明显缺页，并不能证明映射不可能缺页。完整解析在各题 README 中；第一次尝试时先遮住解析与 Reference。

使用 [构建指南](../exercises/BUILD_GUIDE.md) 的单题入口缩短反馈时间。Release 也保留检查，所以不能把 `NDEBUG` 当作省略验证的理由。故意错误的代码与正常运行隔离；安全状态模型应明确它模拟了什么，不能把模型拒绝说成真实内核故障已经复现。

## 开始前的自测与解析

**问题一：`int fd2 = fd1;` 是否意味着有两份可以独立关闭的文件资源？**

解析：它只复制描述符数值。两份 C++ 对象若都认为自己独占同一个 fd，第二次关闭可能作用于已经复用的编号。真正的描述符复制要通过对应系统接口，并进一步判断共享的文件位置和内核对象状态。

**问题二：页已提交，是否能对任意类型直接解引用该地址？**

解析：页级可访问只是操作系统条件；C++ 还要求大小、对齐、对象创建、类型访问及生命周期合法。04—08 会把这些条件拆开验证。

**问题三：取消成功后，能否马上销毁请求对象？**

解析：必须检查平台对取消的契约。请求被接受后，仍可能以成功、取消或其他错误完成；上下文与缓冲需要保留到最终完成责任收束。14 章把这个条件变成可检查的状态和实际平台实验。

**问题四：读回刚写的数据，证明持久化了吗？**

解析：它可能只观察到缓存或共享映射中的数据。可见性、请求完成、刷写以及掉电之后的恢复是不同问题；本课解释系统接口边界，完整崩溃恢复由 C12 深入。

如果你只能背出结论，却不能画出资源与请求的关系，按入门路线完整阅读。课程的目标是能够推导和复现这些关系，而不是记住 API 名称。
