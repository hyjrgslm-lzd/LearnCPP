# C++ 协程标准条款与版本状态

这份索引连接课程讲解与正式定义。先在正文中理解一个具体问题，再通过条款标签查看完整规则。版本表区分已发布设施、执行库的工作草案入口、历史设计提案和具体实现观察；工程练习的实际 API 以仓库固定依赖与本机工具链为准。

## 版本状态

| 范围 | 状态 | 课程中怎么用 |
| --- | --- | --- |
| C++11 `<future>` | 已发布标准库 | P1 介绍 promise、future、async、shared_future；A3 把已有结果通道连接到显式 awaitable 包装。 |
| C++20 core coroutine language | 已发布标准 | `co_await`、`co_yield`、`co_return`、`promise_type`、`coroutine_handle`、协程状态分配/销毁、参数副本、`initial_suspend`/`final_suspend` 的基础语义。 |
| C++20 `<coroutine>` | 已发布标准库 | `std::coroutine_handle`、`std::suspend_always`、`std::suspend_never`、`std::noop_coroutine`。 |
| C++20 `<stop_token>` | 已发布标准库 | C1 从共享停止状态、source、token 和检查位置理解协作式取消。 |
| C++23 `std::generator` | 已发布标准库 | 惰性序列、`co_yield`、递归 `elements_of` 与 generator 生命周期。实际可用性仍取决于标准库实现版本。 |
| C++26 `std::execution` / coroutine utilities | 工作草案学习入口 | `std::execution::task`、`as_awaitable`、counting scopes、`this_thread::sync_wait` 用于理解执行库设计。H 模块实践采用固定 stdexec 版本，并在调用处标明具体命名空间与类型。 |
| P0912 / P0913 / P2502 / P2300 / P3149 / P3296 / P3552 | 历史或演进提案 | 用来理解动机和设计取舍；其中 P3296 专指 `let_async_scope`。最终语义以发布标准或当前工作草案条款为准。 |
| 协程帧布局、ABI、HALO 触发、诊断 flag | 实现细节 | 结合本机工具链与编译产物观察，记录工具链、优化选项及程序形状。 |
| 课程里的 `lazy_task` / `shared_task` / `when_all` / `sync_wait` | 具体教学实现 | 各实现有自己的启动、消费、线程和收束约定；正文沿实际源码说明这些选择。 |

2026-09-11 一手资料核对：N5051 说明 N5050 是 C++26 最终草案和 DIS 基础；N5055 说明 N5054 是 C++29 当前工作草案，并且 N5054 替换 N5050。C09 因此把 C++20/23 已发布协程设施、C++26 DIS 基础、C++29 工作草案、DR 和第三方实现分开登记。`stdexec::task`/`exec::static_thread_pool` 是 pinned stdexec 实现可用性；`std::execution::task` 必须由 `H2_std_task_probe` 这类 C++26 preview 下的真实协程体编译/链接/运行探针确认后才能标为标准库可用。probe 返回 77 表示能力缺失并由 CTest 记为 SKIP，不能冒充 PASS。

## 核心语言条款

| 主题 | 稳定条款标签 | 要点 |
| --- | --- | --- |
| 协程识别与 promise 类型 | [`[dcl.fct.def.coroutine]`](https://eel.is/c++draft/dcl.fct.def.coroutine) | 函数体包含 `co_await`、`co_yield` 或 `co_return` 时是协程；promise 类型由返回类型和参数类型经 `std::coroutine_traits` 决定。 |
| replacement body / 创建顺序 | [`[dcl.fct.def.coroutine]`](https://eel.is/c++draft/dcl.fct.def.coroutine) | 参数副本先创建；promise 构造参数来自参数副本或空参数；`get_return_object()` 在 `initial_suspend()` 前调用，且至多一次。 |
| 参数副本 | [`[dcl.fct.def.coroutine]`](https://eel.is/c++draft/dcl.fct.def.coroutine) | 每个协程参数在 replacement body 开头创建副本。非引用参数的函数体标识符指向这个副本；引用参数副本仍绑定原对象，原对象早死会造成悬挂风险。 |
| 协程状态分配与释放 | [`[dcl.fct.def.coroutine]`](https://eel.is/c++draft/dcl.fct.def.coroutine) | 标准称为 coroutine state。需要额外存储时，经非数组 allocation function 获得；优先查找 promise scope 的 `operator new/delete`。 |
| 分配失败 hook | [`[dcl.fct.def.coroutine]`](https://eel.is/c++draft/dcl.fct.def.coroutine) | 如果 promise scope 找到 `get_return_object_on_allocation_failure`，分配函数按 nothrow 语义处理，失败时调用该 hook 返回失败态对象。 |
| `unhandled_exception` 抛出 | [`[dcl.fct.def.coroutine]`](https://eel.is/c++draft/dcl.fct.def.coroutine) | `unhandled_exception()` 本身若以异常退出，协程被视为在 final suspend point 挂起，异常传播给 caller/resumer。课程实现通常选择 `noexcept` 存储异常。 |
| `final_suspend` | [`[dcl.fct.def.coroutine]`](https://eel.is/c++draft/dcl.fct.def.coroutine) | `co_await promise.final_suspend()` 不得是 potentially-throwing。协程在 final suspend point 挂起时，帧仍存在，等待外部消费/销毁。 |
| `resume`/`destroy` 前置条件 | [`[dcl.fct.def.coroutine]`](https://eel.is/c++draft/dcl.fct.def.coroutine), [`[coroutine.handle.resumption]`](https://eel.is/c++draft/coroutine.handle.resumption) | resume 要求句柄指向已挂起且尚未停在 final suspend 的协程；destroy 要求指向已挂起协程。拥有者与异步完成方需要协调这些调用的有效期。 |
| `co_await` 变换 | [`[expr.await]`](https://eel.is/c++draft/expr.await) | 对适用的 await 表达式，查找到 await_transform 声明后形成该调用，调用需合法；随后对 operator co_await 做重载决议，无可行函数时使用对象自身，歧义为 ill-formed。 |
| `await_suspend` 返回类型 | [`[expr.await]`](https://eel.is/c++draft/expr.await) | 只能返回 `void`、`bool` 或 `std::coroutine_handle<Z>`。返回 handle 时会恢复该 handle 指向的协程；返回 `bool false` 时当前协程立即继续。 |
| `co_yield` | [`[expr.yield]`](https://eel.is/c++draft/expr.yield) | `co_yield expr` 按 `co_await promise.yield_value(expr)` 建模。 |
| `co_return` | [`[stmt.return.coroutine]`](https://eel.is/c++draft/stmt.return.coroutine) | `co_return expr` 调用 `return_value`；无操作数或 `void` 表达式调用 `return_void`。 |

## 从条款回到具体实现

“协程帧”对应标准的 coroutine state。标准规定存储需求、对象生命周期和允许的分配消除条件；具体字段布局、存储位置与 ABI 由实现决定。F 模块用对象日志与分配计数观察本机实现，将观察结果和语言规则分别解释。

symmetric transfer 在课程中表示 await_suspend 返回 coroutine_handle 的控制转交。标准规定恢复所返回句柄指向的协程；机器级尾调用和栈深度取决于编译器及程序形状。

跨线程完成需要一条明确的结果发布关系。mutex、具有合适内存序的 atomic、线程 join 或异步 API 的同步约定可以建立这条关系。resume 的作用是继续协程控制流，数据可见性要从上述同步路径中寻找依据。

共享 lazy_task 的 sync_wait 拥有 root task，启动一次，然后等待完成通知。后续恢复由 awaiter、事件循环或 continuation 链推进。D、E 中专门的手动驱动实验会另行说明每次恢复允许发生的状态。
