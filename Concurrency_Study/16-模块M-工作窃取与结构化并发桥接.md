# 16 模块 M：工作窃取与结构化并发桥接

## 模块目标

到模块 L 为止，你的“多核扩展”手段还停留在**标准库替你切块**的并行算法（`std::execution::par`）。本模块把你带到调度层的两个前沿：①当任务是**不规则、递归分治**（divide and conquer）的，单一共享队列的线程池会被锁争用卡死——**工作窃取（work stealing）**用「每 worker 一条本地队列 + 空闲时偷别人」把争用降到最低并自动负载均衡（练习 M-1）；②当你想从“手摇 thread + future”升级到**结构化、可组合**的异步——C++26 的 **`std::execution`（P2300）** 用 sender/receiver 给出了统一答案，本模块为它搭一座**桥**，让你看清它如何取代裸线程（练习 M-2）。

一句话定位：**M-1 教你“多核之间如何更聪明地分活”（调度），M-2 教你“异步代码如何更结构化地组合”（编程模型）**。两者都是对前面模块的收口——前者把线程池从“单队列”推进到工业级形态，后者指明 C++ 并发的未来方向（深入见 `Execution_Study\`）。

> 工具链前提（务必先记）：
> - **M-1 纯标准库**（`<thread>`/`<deque>`/`<future>`/`<atomic>`），MSVC(VS2026, C++20) 零依赖直接编译运行。
> - **M-2 需要 `std::execution`**，但截至 2026-05 **MSVC 尚未实现**标准库的它。本套用 NVIDIA 参考实现 **stdexec** 回退（命名空间 `stdexec`，头 `<stdexec/execution.hpp>`、`<exec/static_thread_pool.hpp>`），且 **MSVC 必须加 `/Zc:preprocessor`**（CMake 已配）。本模块对 senders **只作桥接演示**，完整机制见 `Execution_Study\`。

## 模块完成标准

做完本模块，你至少要能稳定说清楚（can-do）：

- 你能讲清**工作窃取协议**：每个 worker 一条**本地双端队列（deque）**，owner 在**自己这一端（own end）**做 **LIFO** 的 push/pop，小偷从**另一端（other end）**steal 取最老任务。
- 你能解释**为什么本地 LIFO + 异端窃取**：LIFO 利于递归分治的缓存局部性、控制栈深；从另一端偷“最老/最大”的子树减少窃取频率、两端分离降低与 owner 的冲突。
- 你能对比**工作窃取池 vs 单队列池（Capstone1）**：单队列池所有 worker 抢同一把锁 → 高争用瓶颈；工作窃取常态走**无争用的本地队列**，只在空闲时偷，自动**负载均衡**。
- 你能说清 **fork-join 的合作式等待（cooperative blocking）**：等子任务结果时**绝不能裸 `future.get()` 死等**（等待者本身是 worker，死睡会让其队列里的子任务无人执行 → 死锁），而要“边等边帮忙跑任务”。
- 你能说出**任务粒度（granularity）**的权衡：cutoff 太小则调度开销吃掉收益，太大则并行度不足（呼应模块 L「并行不是免费午餐」）。
- 你能讲清 `std::execution` 的三个核心抽象：**scheduler**（在哪执行）、**sender**（将要产出值/错误/停止的异步工作描述，惰性可组合）、**receiver**（value/error/stopped 三通道接收端）。
- 你能用 sender 算法搭管线：`schedule` / `just` / `then` / `when_all` / `sync_wait`，并说清 `sync_wait` 是“异步世界”与“同步 `main`”之间的桥。
- 你能说出 sender/receiver **相对裸 thread+future 的四点好处**：结构化、可组合、错误/取消三通道、调度可换。
- 你能说出 MSVC 上要用 **stdexec 回退 + `/Zc:preprocessor`**，并知道深入内容在 `Execution_Study\`。

## 练习 M-1：工作窃取线程池

> 代码目录：`exercises/M1_work_stealing_pool/`

### 目标

实现一个**工作窃取（work stealing）线程池**：每个 worker 持有**自己的本地双端队列（deque）**，本地任务 **LIFO** 地从**自己这一端（own end）**push/pop；本地空了就去**偷（steal）**别的 worker 队列**另一端（other end）**的任务。用递归分治任务（并行 fib、二分求和）验证正确性，观察「窃取 vs 本地命中」比例，并对比第一阶段结课 Capstone1 的「单一共享队列 + 一把全局锁」线程池的差异。

### 前置理解

- **工作窃取（work stealing）调度**：与 Capstone1 的**单一共享队列**相反，这里**每个 worker 一条本地队列**。常态下 worker 只碰自己的队列——**零跨线程争用**；只有当本地空了，才去“偷”别人的。这把锁争用从“**每次取任务**”降到“**偶尔偷一次**”。
- **本地 LIFO + 异端窃取（核心协议）**：
  - owner 走**一端（本套取 back / bottom）**：`push_back` 提交、`pop_back` 取任务——**LIFO（取最新压入）**。
  - 小偷走**另一端（front / top）**：`pop_front` 取**最老**的任务。
  - 为什么这样设计：① **LIFO** 让递归分治“刚切出的子任务马上被本线程执行”，缓存还热、栈深可控；② 从**另一端偷最老**的任务通常是**更大、尚未展开的子树**，偷一次能让小偷忙很久，**降低窃取频率**；③ 两端分离 + 每队列独立锁，使 owner 的 push/pop 与小偷的 steal **冲突最小**。
- **负载均衡（load balancing）**：递归分治天然不均衡（某些子树深、某些浅）。工作窃取让**空闲 worker 主动去偷忙 worker 的积压**，把不均衡的工作自动均摊——无需中心调度器。
- **任务粒度（task granularity）**：递归到 `cutoff` 以下就**退化为串行**，避免任务切得过细，让“提交/偷取/future”的调度开销盖过计算本身（这正是模块 L「并行不是免费午餐」在调度层的回响）。
- **fork-join 的合作式等待（cooperative blocking）—— 本题最易踩的坑**：递归分治会“提交左子任务 → 等它的结果 → 同时自己算右子任务”。**等结果时绝不能裸 `future.get()` 死等**：等待者**本身就是一个 worker 线程**，若它阻塞睡死，它本地队列里积压的子任务就**没有线程去执行**，而其他 worker 也可能同样卡在各自的 `get()` 上 → **全员死锁**。正确做法是 `pool.wait_for(fut)`：**在等待期间继续 `try_run_one()` 帮忙跑任务**，直到结果就绪。这正是 TBB / Cilk 等真实工作窃取运行时的关键设计（“help on wait”）。
- **教学版简化**：工业级工作窃取队列是**无锁的 Chase-Lev deque**（见“对应官方参考”）。本题**不强求无锁**，用一把 `mutex` 保护每个 worker 的 `std::deque` 即可——重点是讲清**协议**（本地 LIFO / 异端窃取 / 合作式等待），而非锁的极致优化。

### 必做任务

1. **owner 端 LIFO 取任务**（对应 `// TODO [必做 1]`）：`WorkStealingDeque::pop()` 从 **back（own end）**弹出最新压入的任务。
2. **窃取端异端取任务**（对应 `// TODO [必做 2]`）：`steal()` 从 **front（other end）**取最老的任务。
3. **worker 主循环 = 本地优先 + 窃取回退**（对应 `// TODO [必做 3 + 必做 4]`）：先 `try_run_one()`（本地 `pop` 优先，本地空则**从随机起点轮转窃取**别的 worker 的 `front`——victim 随机化避免空闲 worker 都盯着 0 号形成新热点）；一轮无活则“停机且全空”退出，否则 `yield` 重试。
4. **合作式等待**（对应 `// TODO [必做 5]`）：`wait_for(fut)` 在结果未就绪时持续 `try_run_one()` 帮忙跑任务，**绝不裸 `get()` 死等**。
5. （已给出测试驱动）跑**并行 fib(32)** 与**二分求和**，验证结果与串行**完全一致**，并看析构日志里的「窃取次数 / 本地命中」比例。

### 进阶任务

- **fork-join 二分求和**（对应 `// TODO [进阶 1]`）：`parallel_sum` 把左半提交给池、右半本线程递归，体会负载均衡。
- **换无锁 Chase-Lev deque**：把加锁 `std::deque` 换成无锁工作窃取 deque（owner 端 push/pop 无锁、steal 用 CAS），对照论文实现，理解 `top`/`bottom` 索引与 ABA 防护。
- **调粒度看曲线**：改变 `cutoff`，观察「窃取频率 / 总耗时 / 本地命中比」随粒度的变化，找到本机的合适粒度。
- **观测负载均衡**：给每个 worker 加“执行了多少任务”的计数器，验证忙的活被闲的分担（各 worker 计数趋于接近）。

### 验收点

- 并行 fib / 求和结果与串行**完全一致**，程序**正常退出、不死锁**（合作式等待生效的直接证据）。
- 析构日志里**本地命中 ≫ 窃取次数**（常态走本地，窃取只在不均衡时发生）。
- 你能口述本地 LIFO / 异端窃取协议、合作式等待为何能防死锁、与 Capstone1 单队列池的差异。

### 观察点

- 本地命中次数远多于窃取次数——说明大部分任务在**无争用的本地队列**上被消化，这正是工作窃取省锁的来源。
- 窃取只在“某 worker 闲、某 worker 有积压”时发生——它是**负载均衡的机制**，不是常态开销。
- 把 worker 数与 cutoff 一调，窃取/本地比例随之变化——直观感受调度与粒度的关系。

### 常见坑

- **裸 `future.get()` 死等 → 死锁**：本题最致命的坑。递归分治里等待者本身是 worker，死睡会让其队列子任务无人执行。必须用合作式等待（边等边帮忙跑）。
- **owner 与小偷走同一端**：若 steal 也从 back 取，会与 owner 的 pop 高频冲突，失去“两端分离降冲突”的好处；且偷到的是“最新最小”的子任务，划不来。
- **粒度过细**：`cutoff` 太小 → 任务爆炸 → 提交/偷取/future 的开销盖过计算（呼应模块 L）。
- **窃取永远从 0 号扫起**：所有空闲 worker 都盯 0 号 → 新的争用热点。要 **victim 随机化**。
- **退出条件只看“停机”不看“全空”**：会丢弃在途任务。退出须是“**停机 且 所有队列都空**”。
- **拿加锁版当无锁版宣传**：本题是教学简化版（mutex 保护 deque）；真正无锁是 Chase-Lev，别混淆。

### 提示

- 本地端用 `push_back`/`pop_back`（LIFO），窃取端用 `pop_front`（取最老）。每队列一把 `mutex`、`std::optional<Task>` 表示“取到/没取到”。
- 池内线程提交任务时优先投**自己**的本地队列（用 `thread_local` 记“我是几号 worker”），保持局部性；非池内线程轮转投递。
- 合作式等待用 `fut.wait_for(0s) != ready` 轮询 + `try_run_one()`，跑不到任务再 `yield`。
- 用 `cs::logf(...)` 打印窃取/本地命中计数与一致性结论。
- 演示用 4 个 worker 即可看清窃取且更稳定；fib 的 `cutoff` 取得能制造适量子任务即可（如 24）。

### 复盘问题

- 工作窃取池为什么比单队列池锁争用更低？争用被从“什么时候”降到了“什么时候”？

## 练习 M-2：std::execution 桥接

> 代码目录：`exercises/M2_execution_bridge/`

### 目标

用 **`std::execution`（P2300，C++26）** 的 **sender/receiver** 演示如何**取代裸 thread + future**：用 `schedule(scheduler) | then(...) | then(...)` 组一条异步管线、`sync_wait` 取结果；用 `when_all` 并发汇合两个 sender。讲清相对手写线程的好处（结构化、可组合、错误/取消通道）。本模块对 senders **只作桥接演示**，深入机制明确指向 `Execution_Study\`。

### 前置理解

- **三个核心抽象**：
  - **scheduler（调度器）**：回答工作“**在哪执行**”——线程池、GPU、单线程等的统一抽象。本题用 `exec::static_thread_pool` 提供 `get_scheduler()`。
  - **sender（发送者）**：一段“**将要**产出「值 / 错误 / 停止」”的异步工作的**描述**。它是**惰性（lazy）**的——构造时不执行，被连接到 receiver 并 start 后才跑——也因此**可组合**。
  - **receiver（接收者）**：sender 完成时回调的接收端，有**三条通道**：`set_value`（成功值）、`set_error`（错误）、`set_stopped`（被取消/停止）。你通常不直接写 receiver，而是用算法把 sender 接到 `sync_wait` 这类“收尾”消费者上。
- **sender 算法（本题用到的）**：
  - `schedule(sched)`：产出一个“在 `sched` 上开始、不带值”的 sender（管线起点）。
  - `just(v)`：产出一个“已就绪值 `v`”的 sender（另一种起点）。
  - `then(f)`：把上游的值喂给 `f`，`f` 的返回值成为新 sender 的值——像 `future.then`，但是**惰性、可组合**的。
  - `when_all(a, b, ...)`：并发跑多个 sender，全部完成后汇合成“多个值”的 sender（下游 `then` 接 `(va, vb, ...)`）。
  - `sync_wait(s)`：在**当前线程阻塞**等到管线完成，返回 `std::optional<std::tuple<...>>`（值在 tuple 里；被停止则是 `nullopt`；出错则**重新抛出**异常）。它是“**异步世界**”与“**同步 `main`**”之间的桥。
- **相对裸 thread + future 的好处（本题灵魂）**：
  1. **结构化（structured）**：管线是一棵**树**，子计算的生命周期/资源随结构自然嵌套管理，不像裸线程那样把 `join`/`detach` 散落各处、容易泄漏或悬挂。
  2. **可组合（composable）**：`then` / `when_all` 像搭积木，免去手摇 `future.then` 链与“回调地狱”。
  3. **三条通道（value/error/stopped）**：**错误**与**取消（cancellation）**是**一等公民**，沿管线**自动传播**——裸线程里你得自己跨线程搬运异常、自己缝停止标志。
  4. **调度可换**：把 `scheduler` 一换，**同一段管线**就能换执行资源（线程池 → GPU → 单线程），实现“**做什么**”与“**在哪做**”的关注点分离。
- **工具链现实**：std::execution 是 **C++26 标准**（头 `<execution>`，命名空间 `std::execution`），但 **MSVC 截至 2026-05 未实现**。本题用 **stdexec**（NVIDIA 参考实现）回退：命名空间 `stdexec`、头 `<stdexec/execution.hpp>` 与 `<exec/static_thread_pool.hpp>`；**MSVC 必须 `/Zc:preprocessor`**（其头文件强制要求符合标准的预处理器，CMake 已配）。**本模块只作桥接演示**，sender 的完整机制（自定义 sender、completion signatures、域 domain、取消令牌 stop_token 细节等）**深入见 `Execution_Study\`**。

### 必做任务

1. **schedule | then | then 管线 + sync_wait**（对应 `// TODO [必做 1]`）：`stdexec::schedule(sched) | then(产出 21) | then(x -> x*2)`，`sync_wait` 取值，验证 == 42。体会“一条管线”替代了“起线程 + promise/future 回传 + join + try/catch”一整套手工活。
2. **when_all 并发两个 sender**（对应 `// TODO [必做 2]`）：两条 `schedule|then` 各自在池上并发跑，`when_all` 汇合后 `then((va, vb) -> va+vb)`，验证 == 123。
3. （进阶 `// TODO [进阶 1]`）**just 起头 + error 通道**：`just(10) | then(+5)` 验证 == 15；再让 `then` 内 `throw`，演示异常如何走 **error 通道**被 `sync_wait` 在调用线程**重新抛出**，你只需正常 `try/catch`。

### 进阶任务

- **换 scheduler**：把 `static_thread_pool` 换成单线程的 `run_loop`（或不同池大小），观察同一段管线如何不动而执行资源改变——亲手验证“调度可换”。
- **取消（cancellation）初探**：阅读 stdexec 的 `set_stopped` 与 stop_token 如何沿管线传播，理解“取消是一等公民”（细节留给 `Execution_Study\`）。
- **`bulk` 算法**：用 `stdexec::bulk` 表达“对 N 个下标并行做同一件事”，对照模块 L 的 `std::for_each(par)`，体会 sender 版数据并行。
- **对照手写版**：把必做 1 用裸 `std::thread + std::promise/future` 重写一遍，数一数你多写了多少 join/异常搬运代码，再回看 sender 版的简洁。

### 验收点

- 三段管线结果与期望一致（**42 / 123 / 15**）；`then` 内抛出的异常经 `sync_wait` **重新抛出**并被 `try/catch` 接住。
- 你能讲清 scheduler / sender / receiver 三者关系，及 sender/receiver 相对裸 thread+future 的**四点好处**。
- 你知道 MSVC 上要 **stdexec 回退 + `/Zc:preprocessor`**，并知道深入内容在 `Execution_Study\`。

### 观察点

- 必做 1 的两个 `then` 在**池线程**上跑（日志的 tid 与 `main` 不同），而 `sync_wait` 在 `main` 线程收尾——这就是“异步执行、同步取结果”的桥。
- 必做 2 的 `[a]` 与 `[b]` 可能落在**不同池线程**上并发执行，`when_all` 等两者都完成才进入 `[join]`。
- 进阶里异常**没有让程序崩溃**，而是沿 error 通道回到 `sync_wait` 重抛——对照裸线程“异常默认 `terminate`”，体会三通道的价值。

### 常见坑

- **忘了 `/Zc:preprocessor`**：stdexec 头文件直接 `#error` 拒编。MSVC 必加（CMake 已配；独立 `cl` 编译也要带）。
- **把 sender 当“立刻执行”**：sender 是**惰性描述**，不 `sync_wait`（或不连到消费者并 start）它根本不跑。
- **`sync_wait` 的返回类型搞错**：它返回 `std::optional<std::tuple<...>>`，取值要 `std::get<0>(result.value())`，不是直接拿值。
- **命名空间搞混**：标准是 `std::execution`，stdexec 回退是 `stdexec`（算法）与 `exec`（线程池等资源），别写成 `std::execution::then`。
- **以为本模块要精通 sender**：本模块只是**桥接演示**；想深入自定义 sender / completion signatures / 取消，去 `Execution_Study\`。

### 提示

- 头文件：`<stdexec/execution.hpp>`（算法）、`<exec/static_thread_pool.hpp>`（线程池）。
- 管道运算符 `|` 把 sender 与算法串起来：`schedule(sched) | then(f) | then(g)`。
- `sync_wait(std::move(pipeline))` 取结果；管线对象通常只用一次，记得 `std::move`。
- 想看错误通道：在某个 `then` 里 `throw`，再 `try { sync_wait(...) } catch (...)`。
- 用 `cs::logf(...)` 打印 tid，直观看到“管线在池线程上、收尾在 main 线程上”。

## 做完模块 M 之后，你现在应该能说清楚什么

至少把下面几句话说顺：

- **工作窃取调度（M-1）**：每个 worker 一条**本地 deque**，owner 在**自己一端**做 **LIFO** push/pop，小偷从**另一端** steal 取**最老**任务。常态走**无争用的本地队列**，只在空闲时偷——把锁争用从“每次取任务”降到“偶尔偷一次”，并自动**负载均衡**。
- **本地 LIFO + 异端窃取的理由**：LIFO 利于递归分治的缓存局部性与栈深控制；异端偷“最老/最大”子树降低窃取频率、两端分离降冲突。
- **fork-join 合作式等待**：等子结果时**绝不裸 `future.get()` 死等**（会死锁），要“边等边帮忙跑任务”（help on wait）——TBB/Cilk 的关键设计。
- **任务粒度**：cutoff 太小则调度开销吃掉收益、太大则并行度不足——这是模块 L「并行不是免费午餐」在调度层的回响。
- **工作窃取池 vs 单队列池（Capstone1）**：后者所有 worker 抢同一把锁 → 高争用瓶颈；前者每人一条队列、仅偷取时偶发跨线程加锁。
- **`std::execution`（M-2）三抽象**：**scheduler**（在哪执行）、**sender**（将要产出值/错误/停止的惰性可组合描述）、**receiver**（value/error/stopped 三通道）。用 `schedule`/`just`/`then`/`when_all`/`sync_wait` 搭管线；`sync_wait` 是异步与同步 `main` 的桥。
- **sender/receiver 相对裸 thread+future 的四点好处**：**结构化、可组合、错误/取消三通道、调度可换**——这是 C++ 并发的未来方向。
- **工具链现实**：M-1 纯标准库零依赖；M-2 因 MSVC 未实现 `std::execution`，用 **stdexec 回退 + `/Zc:preprocessor`**，本模块只作**桥接演示**，深入见 `Execution_Study\`。
