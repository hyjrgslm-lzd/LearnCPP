# 18 源码阅读路线

做完三个阶段的练习后，你已经**亲手实现过**互斥/条件变量/future、原子与内存序、无锁栈/队列、危险指针（hazard pointer）/RCU、缓存与伪共享、SIMD、并行算法、工作窃取与 sender 桥接。本附录给你一份**读工业级源码**的方法与路线——把“我会写玩具版”升级为“我读得懂真实实现为什么那样写”。

> 读源码的心态：**不是逐行读懂，而是带着问题去对照。** 你已经有了每个主题的“玩具实现”作锚点，读真实代码时只问一句：**“它比我的玩具版多做了什么？为什么？”** 答案通常是：可移植性、平台特化、ABA/内存回收、对齐与伪共享、异常安全、可配置策略。

## 三轮阅读法（适用于下面每一个对象）

并发源码尤其密集、宏多、模板深，**切忌从第一行读到最后一行**。用三轮递进：

- **第一轮 · 看形状（接口与骨架，约 30 分钟）**
  - 只看**公开头文件的接口**：有哪些类型、关键成员函数签名、返回值。
  - 找到**核心数据结构**（一个 struct/class 的成员字段）——并发数据结构的“真相”几乎都在字段布局里（哪些是 `atomic`、有没有 `alignas`/padding、有没有版本号/计数器）。
  - 跳过所有实现细节、宏展开、平台分支。目标：能画出“它由哪几块组成”。
  - **对照你的玩具版**：它的接口比你多了哪些重载/策略参数？

- **第二轮 · 补对象关系（数据流与协议，约 1–2 小时）**
  - 顺着**一条主路径**走（如“push 一个元素”“偷一个任务”“retire 一个节点”），看数据如何在字段间流动、**哪些原子操作、用了什么 memory_order**。
  - 找出**核心不变量（invariant）**与**线程协作协议**：谁发布、谁消费、谁负责回收、ABA 怎么防。
  - 注意**异常安全**与**资源生命周期**：失败路径怎么回滚、对象何时析构。
  - **对照你的玩具版**：你的版本在哪里偷懒了（没防 ABA？没处理满/空边界？没对齐？）。

- **第三轮 · 对照提案/论文（为什么这么设计，按需）**
  - 把实现与**标准提案 / 经典论文 / cppreference 语义**对齐：为什么选这个 memory_order、为什么要这层间接、这个 fast-path/slow-path 的取舍依据。
  - 读 commit log / issue / 设计文档，理解**历史包袱与权衡**（很多“怪写法”是为了绕某编译器 bug 或某平台 ABI）。
  - 目标：你能向别人**讲清一个设计决策的取舍**，而不只是“它就这么写的”。

## 推荐阅读对象与导读

### 1. folly（Facebook/Meta C++ 基础库）

工业级、注释丰富、有配套博客，是“原子与回收”主题的最佳对照。

- **`folly/synchronization/Hazptr.h`（及 `Hazptr-*.h`）—— 危险指针**
  - **读什么**：`hazptr_holder`（持有者）、`hazptr_obj_base`（可被保护/退休的对象基类）、`hazptr_domain`（全局保护记录与 retire 列表）的三角关系；`protect()` 的“读 → 设保护 → 复核”循环；`retire()` 与批量 `reclaim` 的阈值策略。
  - **对照本套**：模块 I 的练习 **I-2（hazard pointer）** 与教学头 `hazard_pointer.hpp`。
  - **关注什么**：保护记录的**复核（re-check）**为何必不可少（防止设保护与发布之间的竞态）；retire 列表的**批量回收阈值**如何摊薄扫描开销；与你玩具版相比它如何做到**可扩展**（per-thread 缓存、domain 分片）。

- **`folly/synchronization/Rcu.h` —— RCU（Read-Copy-Update）**
  - **读什么**：`rcu_reader`（读侧临界区，几乎零开销）、`synchronize_rcu()` / `rcu_retire()`（写侧等待宽限期 grace period）的实现；epoch/版本如何推进。
  - **对照本套**：模块 I 的练习 **I-3（RCU）** 与教学头 `rcu.hpp`。
  - **关注什么**：**读侧为什么能做到无锁近零成本**、写侧如何界定“所有读者都已离开”的宽限期；与 hazard pointer 在“读多写少”场景的取舍差异。

- **`folly/MPMCQueue.h` —— 多生产者多消费者有界队列**
  - **读什么**：基于**带 ticket/turn 的槽位（slot）**数组的设计；每个槽位的 `turn` 序号如何让生产者/消费者无锁协调；`alignas` 如何避免伪共享。
  - **对照本套**：模块 G 的 **G-3（SPSC 环形缓冲）**、Capstone2（无锁队列）、模块 J（伪共享）。
  - **关注什么**：从 SPSC 到 MPMC 多了什么（ticket 仲裁多个生产者）；**缓存行对齐**在真实队列里的位置；为什么用 turn 序号而非裸 CAS 链表（避免 ABA + 更好的缓存行为）。

### 2. libstdc++（GCC 标准库实现）

“标准库到底怎么实现的”一手答案。源码在 GCC 仓库 `libstdc++-v3/`。

- **`<atomic>` 的实现（`include/std/atomic`、`include/bits/atomic_base.h`）**
  - **读什么**：`std::atomic<T>` 如何根据 `T` 的大小/是否无锁退化到编译器内建 `__atomic_*` / `__sync_*`；`memory_order` 如何透传给后端；`is_always_lock_free` 的判定。
  - **对照本套**：模块 E（原子基础）、模块 F（内存模型与 memory_order）、模块 G（无锁结构）。
  - **关注什么**：**哪些类型“总是无锁”、哪些退化为带锁**（大对象 `atomic<T>` 内部其实有锁）；memory_order 到机器屏障的映射在不同架构（x86 vs ARM）上的差异——这正是模块 F 抽象语义的“落地”。

- **`<experimental/simd>`（`include/experimental/bits/simd*.h`）—— SIMD**
  - **读什么**：`simd<T, Abi>` 的 ABI 标签机制、`where()`/掩码 mask、load/store 与各后端（SSE/AVX/NEON）的特化分发。
  - **对照本套**：模块 K（数据并行与 `std::simd`）；本套因 MSVC 未实现而用 **xsimd** 回退，这里看“标准方向”的另一个实现。
  - **关注什么**：**ABI 标签如何在编译期选定向量宽度**、掩码类型 `simd_mask` 与 `where-select` 的实现；对照你用 xsimd 写的点积/where-select，体会概念一致、命名不同。

### 3. moodycamel ConcurrentQueue（`cameron314/concurrentqueue`）

业界广泛使用的工业级无锁 MPMC 队列，单头文件、性能极高。

- **读什么**：**per-producer 的 block 链表**（每个生产者有自己的子队列，降低争用）+ 消费者跨子队列消费的设计；block 的分配/回收与索引推进；显式 `ProducerToken`/`ConsumerToken` 的快路径。
- **对照本套**：Capstone2（无锁队列）、模块 G（无锁结构 + ABA）、模块 M-1（工作窃取也是“每生产者一条队列”的同源思想）。
- **关注什么**：它如何用**“每生产者独立队列”把争用拆散**（与工作窃取的本地队列异曲同工）；无锁回收如何避免 ABA；为什么作者反复强调“它**不是**严格 FIFO”——并发与强序的取舍。

### 4. xsimd（`xtensor-stack/xsimd`）

本套 SIMD 练习（模块 K）实际链接的回退库，header-only、跨平台。

- **读什么**：`batch<T, Arch>`（向量寄存器抽象）与 `batch_bool`（掩码）；`load_aligned`/`store`、`reduce`、`select` 等 API；`xsimd::dispatch` 的**运行时架构分发**（同一份代码按 CPU 实际支持的指令集选实现）。
- **对照本套**：模块 K 全部三题（K-1 基础 / K-2 点积 / K-3 where-select），以及文档里的 **xsimd ↔ std::simd 差异映射表**。
- **关注什么**：`batch` 与标准 `simd` 的 API 对应关系（你已经在 K 模块用过）；**对齐**为何重要（呼应模块 J 伪共享/对齐）；运行时 dispatch 如何兼顾“一次编译、按机器选最优指令集”。

### 5. NVIDIA/stdexec（`std::execution` / P2300 参考实现）

C++26 `std::execution` 的权威参考实现，也是本套模块 M-2 链接的库。

- **读什么**：`stdexec/execution.hpp` 里 `then`/`when_all`/`sync_wait`/`schedule` 等**算法如何用 sender adaptor 表达**；`exec/static_thread_pool.hpp` 这个 scheduler 怎么把工作投递到线程池；sender 的 **completion signatures**（一段工作可能产出哪些 value/error/stopped）。
- **对照本套**：模块 **M-2（execution 桥接）**——你已经用过 `schedule|then|then|sync_wait` 与 `when_all`。
- **关注什么**：**sender 的惰性与组合**如何用模板表达（连接 connect → 启动 start 的两段式）；三条 completion 通道（value/error/stopped）如何沿管线传播；与你在 M-2 看到的“好处四条”如何在代码里兑现。
- **深入提醒**：sender/receiver 的完整机制（自定义 sender、domain、取消令牌等）是 `Execution_Study\` 的主题；本附录只把它作为“读提案级参考实现”的范例。
