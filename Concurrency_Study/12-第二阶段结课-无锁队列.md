# 12 第二阶段结课 · 无锁队列

## 这份文件怎么用

阶段二的 10 道题（模块 E/F/G 各 3–4 道，外加 H/I）把无锁编程的零件拆开单独练了：

- **模块 E（原子操作基础）**：`std::atomic<T>` 的 load/store、`atomic_ref`、`compare_exchange`（CAS）循环；
- **模块 F（内存模型）**：`memory_order` 家族——`relaxed` / `acquire` / `release` / `seq_cst` 各自的语义与适用处，release/acquire 配对建立的 happens-before，发布模式（publish pattern）；
- **模块 G（无锁数据结构）**：Treiber 栈、ABA 问题、SPSC 无锁环形缓冲，以及 lock-free / wait-free / obstruction-free 三种进展保证。

这份文件负责把上面的零件**重新拼成两个完整的并发队列**，并和加锁版做吞吐对比。它几乎用到了阶段二的每一个概念，是检验你是否真正掌握"组合"而非"会用单个原子操作"的试金石。

> **本项目刻意自包含**：两个队列都建在**定长数组**上，槽位永久复用、从不释放，于是**天然规避节点回收（reclamation）问题**——没有 `new`/`delete`、没有指针被释放，也就没有 ABA 与 use-after-free。因此本项目**不依赖**模块 I 的 `hazard_pointer.hpp` / `rcu.hpp`。把"回收"这一无锁编程最难的坑用"有界设计"绕开，正是本项目的核心教学点之一。

建议顺序：先把两种队列的**数据布局**和**每个原子操作的内存序**在纸上画清楚（尤其 MPMC 里"每个槽位的 sequence 充当闸门"这一层），再动手把 `main.cpp` 里的 `// TODO` 占位替换成真正的 CAS 协议。

> 直接复用的前置题：练习 E-3（CAS 循环）、练习 F-1（release/acquire 配对）、练习 F-4（发布模式）、练习 G-3（SPSC 环形缓冲）。

## 项目目标

实现两个**有界无锁队列**，并与加锁版做基准对比：

1. **SPSC 有界环形队列** `SpscRingBuffer<T, Capacity>`：单生产者单消费者。`tail` 只由生产者写、`head` 只由消费者写——两个写者之间没有竞争，因此**无需 CAS**，只用 `release`/`acquire` 配对传递"槽位数据"的可见性。这是练习 G-3 的复习与对照基线。

2. **MPMC 有界队列** `MpmcBoundedQueue<T>`（Dmitry Vyukov 的 bounded MPMC queue 算法）：多生产者多消费者。固定容量数组，**每个槽位（cell）带一个 `std::atomic<size_t> sequence`** 作为"票据闸门"；`enqueue`/`dequeue` 通过在 `tail`/`head` 票据计数上 **CAS 抢位**、再读写槽位、最后用 `sequence` 的 release-store 发布状态。满/空判定完全由 `sequence` 与当前票据的差值决定，**不需要任何节点回收**。

3. **吞吐基准**：把 MPMC 无锁队列与"`std::mutex` + `std::queue`"的加锁版，在多生产者多消费者下做吞吐对比，打印 ops/sec，亲身体会无锁的收益与代价。

这个项目的重点不是"写出史上最快的队列"，而是让你把三件事同时做对：

- **为每一个原子操作选对 `memory_order`，并能说清理由**——哪里 `relaxed` 够用、哪里必须 `acquire`/`release` 配对、为什么 ticket 的 CAS 可以 `relaxed` 而数据的发布必须 `release`。
- **用 CAS 协议在多写者下保持正确**——抢 ticket、判满/判空、失败重试，整体保持 lock-free。
- **用"有界"绕开回收**——理解为什么定长数组复用槽位就天然没有 ABA 与 use-after-free。

## 固定题面

对外接口固定为下面两组（签名是验收的一部分，请勿改动语义）：

```cpp
// SPSC：单生产者只调 push，单消费者只调 pop。
template <class T, std::size_t Capacity>
class SpscRingBuffer {
public:
    bool push(const T& value);   // 满返回 false（仅生产者调用）
    bool pop(T& out);            // 空返回 false（仅消费者调用）
};

// MPMC：任意多生产者并发 enqueue，任意多消费者并发 dequeue。
template <class T>
class MpmcBoundedQueue {
public:
    explicit MpmcBoundedQueue(std::size_t capacity); // capacity 须为 2 的幂
    bool enqueue(const T& value); // 满返回 false（不阻塞）
    bool dequeue(T& out);         // 空返回 false（不阻塞）
};
```

MPMC 内部结构固定为 Vyukov 方案：

```cpp
struct Cell {
    std::atomic<std::size_t> sequence; // 每槽一个闸门
    T data;
};
std::vector<Cell> buffer_;             // 定长，2 的幂容量
std::atomic<std::size_t> enqueue_pos_; // 生产者群 CAS 的票据计数
std::atomic<std::size_t> dequeue_pos_; // 消费者群 CAS 的票据计数
```

## 必须包含的设计约束

1. **必须综合阶段二的核心**：原子操作（`load`/`store`/`compare_exchange`，模块 E）、`memory_order` 的正确选用且**每处都能讲出理由**（模块 F）、进展保证的判断（模块 G）。
2. **MPMC 必须用 CAS 抢 ticket**：`enqueue`/`dequeue` 在 `enqueue_pos_`/`dequeue_pos_` 上用 `compare_exchange_weak` 抢位，失败后重读重试。**禁止用一把锁串行化**（占位实现允许临时用锁，但最终交付必须是无锁的 CAS 协议）。
3. **满/空判定只能依赖 sequence 与票据的差值**：`diff = seq - pos`。`enqueue`：`diff==0` 轮到写、`diff<0` 满、`diff>0` 重读；`dequeue`：与 `pos+1` 比，对称。
4. **内存序逐处说明**：
   - 读 `cell.sequence` 用 `acquire`——要看到对端上一轮的发布；
   - 抢 ticket 的 CAS 可用 `relaxed`——它只是抢一个计数，数据载荷的可见性由后续 `sequence` 的 release-store 承担；
   - 写完数据后 `cell.sequence.store(..., release)`——把"数据已写好/这格已空"发布给对端，与对端的 `acquire` 配对。
5. **无需回收、禁止 new/delete 槽位**：容量固定、槽位永久复用。你要能解释**为什么这就消灭了 ABA 与 use-after-free**（对比模块 G-2 的 ABA、模块 I 的 hazard pointer/RCU）。
6. **禁止数据竞争**：所有跨线程共享的可变状态要么是 `std::atomic`，要么受同一把锁保护（占位过渡期）。最终无锁版里，槽位数据的可见性完全靠 sequence 的 acquire/release 链建立。
7. **SPSC 不得使用 CAS**：它的正确性来自"每个下标只有一个写者"，用 CAS 反而是误用——你要能说清推广到多写者时这套无 CAS 方案为何立刻失效。

## 推荐输入输出模型

为了把注意力留给队列结构，建议测试驱动写得很小、可预测：

- **SPSC 正确性**：生产者按 `0,1,2,...,N-1` 顺序 push；消费者按收到顺序核对"值严格等于递增序列"——同时验证 FIFO 与不丢数据。
- **MPMC 正确性**：每个元素是**全局唯一编号**；用一张 `std::atomic<int> seen[]` 标记表，消费者每取一个就 `fetch_add` 翻位，核对"每个编号**恰好被消费一次**"（不丢、不重、守恒）。注意 MPMC 下多消费者并发取，**不保证全局 FIFO**，故只验证"集合相等"而非顺序。
- **吞吐基准**：固定总量（如 4 生产者 × 4 消费者 × 20 万），分别用无锁 MPMC 与加锁版各跑一遍，计时算 `ops/sec`（一次 enqueue + 一次 dequeue 记 2 个 op），打印两者比值。

示例输出（用 `cs::logf` / `cs::println`，带线程 id 与时间戳）：

```
==== Capstone2：无锁队列（SPSC 环形 + MPMC Vyukov 有界）====
[SPSC] 消费总数 = 200000（期望 200000）-- 不丢数据 OK
[SPSC] FIFO 顺序检查 -- 严格递增、顺序正确 OK
[MPMC] 生产 = 200000，消费 = 200000（期望各 200000）
[MPMC] 守恒/不丢/不重 -- 每个编号恰好一次 OK
[bench] MPMC-lockfree：... ops/sec
[bench] Locked(mutex+queue)：... ops/sec
[bench] 无锁/加锁 吞吐比 ≈ ... %
==== 演示结束。 ====
```

## 必做任务

1. **跑通 SPSC 正确性**：复用练习 G-3 的环形缓冲，单生产者单消费者验证 FIFO 顺序与不丢数据。`tail` release / `head` acquire 配对，读自己写的下标用 `relaxed`。
2. **设计 MPMC 的数据布局**：定长数组，每个 `Cell` 含 `atomic<size_t> sequence` + `data`；两个票据计数 `enqueue_pos_` / `dequeue_pos_`。把每个 cell 的 `sequence` 初始化为它的下标 `i`（"第一圈轮到第 i 个写"）。容量取 2 的幂，用 `pos & (cap-1)` 取代取模。
3. **画 MPMC 状态机**：在纸上画出一个 cell 在一整圈里的 `sequence` 取值变化：`i`（待写）→ `pos+1`（已写、待读）→ `pos+capacity`（已读、待下一圈写）。标注每一步由谁写、用什么内存序。
4. **实现 `enqueue`（CAS + sequence）**：读 `enqueue_pos_`；`acquire` 读该 cell 的 `sequence`，算 `diff = seq - pos`：`==0` 用 `compare_exchange_weak` 抢 ticket（`relaxed`）、`<0` 返回满、`>0` 重读；抢到后写数据，再 `cell.sequence.store(pos+1, release)` 发布。
5. **实现 `dequeue`（CAS + sequence）**：与 `enqueue` 对称——`acquire` 读 `sequence`，与 `pos+1` 比：`==0` 抢 `dequeue_pos_`、`<0` 返回空、`>0` 重读；取走数据后 `cell.sequence.store(pos+capacity, release)`，让该格在下一圈重新对生产者"轮到被写"。
6. **写吞吐基准**：把无锁 MPMC 与加锁版（`std::mutex`+`std::queue`）在相同负载下计时，打印各自 ops/sec 与比值。
7. **写 MPMC 正确性测试**：多生产者唯一编号 + 标记表核对"恰好一次"，检测丢失与重复。
8. **逐处标注内存序理由**：在代码注释里，对每一个 `load`/`store`/CAS 写明选这个 `memory_order` 的原因（哪条 happens-before 靠它建立）。这是本项目最重要的"产出物"。

## 进阶任务

- **改 `seq_cst` 全序对比**：把 MPMC 里的 `acquire`/`release`/`relaxed` 全换成 `seq_cst`，对比正确性是否变化、吞吐损失多少，理解"够用就好"的内存序选择哲学。
- **阻塞版 MPMC**：在无锁版外面包一层 `atomic_wait`/`atomic_notify`（模块 H），让满时生产者、空时消费者真正睡眠而非自旋，做"无锁 + 阻塞唤醒"的混合。
- **wait-free 的边界讨论**：当前 enqueue/dequeue 是 lock-free 但非 wait-free（单线程可能反复重试）。讨论在什么负载下重试会成为问题，以及 wait-free 队列要付出什么代价。
- **缓存行与伪共享**：用/去掉 `alignas(64)`（cell 之间、两个 ticket 之间）各测一遍吞吐，量化伪共享（false sharing，模块 J）的影响。
- **对照链式无锁队列**：简述若改用链表式 Michael-Scott 无锁队列，**回收问题**会如何回来，需要 hazard pointer 或 RCU（模块 I）才能安全释放节点——反衬"有界"设计的省心。
- **泛型与移动语义**：让 `enqueue` 支持移动入队（`enqueue(T&&)`），思考 cell 里 `data` 的构造/析构时机。

## 验收点

- 你能在状态机图上指出一个 cell 的 `sequence` 在一整圈里取的三个关键值，以及每次变化由谁、用什么内存序写。
- SPSC：N 个元素 FIFO 顺序**完全正确**、不丢数据，多次运行稳定。
- MPMC：多生产者多消费者下，每个唯一编号**恰好被消费一次**（不丢、不重、总数守恒），多次运行稳定可复现。
- 你能逐处说出 MPMC 里每个 `memory_order` 的理由，尤其"为什么 ticket 的 CAS 可以 `relaxed`，而数据/状态的发布必须 `release`"。
- 你能解释**为什么有界数组复用槽位就天然规避了 ABA 与 use-after-free**，从而本项目不需要 hazard pointer/RCU。
- 吞吐基准能跑出无锁版与加锁版的 ops/sec 与比值；你能解释高争用下无锁版通常领先的原因（不阻塞、无上下文切换、无锁护送 lock convoy）。
- 你能判断 enqueue/dequeue 的进展保证是 lock-free 而非 wait-free，并说出区别。

## 项目复盘问题

- MPMC 里抢 `enqueue_pos_` 的 CAS 为什么可以用 `relaxed`？如果改成 `release` 或 `acquire` 会多保证什么、又是否必要？
- 数据的"发布"为什么放在 `cell.sequence.store(pos+1, release)` 这一步，而不是写 `cell.data` 那一步？消费者是靠哪条 happens-before 才能安全读到 `data` 的？
- `enqueue` 里 `diff < 0`（`seq < pos`）为什么意味着"满"而不是"空"？请顺着一整圈的 `sequence` 取值推演一遍。
- `dequeue` 取走数据后把 `sequence` 置为 `pos + capacity`，这个值是怎么来的？为什么正好让下一圈的生产者"轮到被写"？
- 为什么容量要取 2 的幂？如果用任意容量 + 取模，正确性会坏吗，还是只是变慢？
- SPSC 为什么**不需要** CAS？把它直接拿去做多生产者会发生什么（结合模块 G-3 的"思考边界"）？
- 这个有界 MPMC 为什么不需要 hazard pointer/RCU？如果换成链式（无界）无锁队列，回收问题会怎样回来？
- 当前算法是 lock-free 还是 wait-free？举一个让某个线程"长时间无法前进"的并发时序。
- 满时 `enqueue` 返回 `false`、调用方自旋 `yield`——这和"阻塞式背压"（条件变量/`atomic_wait`）相比，各自适合什么场景？

### 完成后能说什么

做完这个结课项目，你应该能稳定说出：

- "我能用 release/acquire 配对在两个线程间建立 happens-before，让一方写的数据对另一方安全可见，并解释为什么 SPSC 的两个独占写者根本不需要 CAS。"
- "我能实现 Vyukov 有界 MPMC 队列：用每槽一个 sequence 当闸门、在 tail/head 票据上 CAS 抢位，并逐处讲清每个 memory_order 的理由。"
- "我理解无锁编程最难的是回收，而'有界 + 槽位复用'用最朴素的方式绕开了它——没有 new/delete 就没有 ABA 和 use-after-free。"
- "我能用基准量化无锁相对加锁的收益，也能说清它的代价（lock-free 非 wait-free、高争用下的重试、内存序心智负担）。"
