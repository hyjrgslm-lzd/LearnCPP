# 并行算法 02：归约、扫描和括号的位置

[上一篇](02-execution-policies.md)中的输出各自独立。求和不同：所有输入最终参与一个结果。扫描更进一步，每个位置都需要一个前缀结果。本篇用 [L2/solution.cpp](../../exercises/L2_parallel_reduce_scan/solution.cpp) 的整数、点积和仿射变换三个例子，分别说明分组、类型与顺序。数值内核的真实实现仍在 [numeric_kernels.hpp](../../exercises/include/concurrency_study/numeric_kernels.hpp)。

## 1. 一个左折叠为什么有长依赖链

对输入 1、2、3、4 和初始值 0，accumulate 的计算模型是 `((((0+1)+2)+3)+4)`。每一步需要上一步结果。把第一个和交给一个线程、第二个和交给另一个线程，第二个仍要等待，不能仅靠启动线程消除依赖。

但若操作可以重新分组，就能先算 `1+2` 和 `3+4`，再把两个部分和相加。N 个元素仍有 O(N) 工作，理想平衡树的关键依赖深度则从 O(N) 降到 O(log N)。这只是算法结构推导，不包含线程分派、缓存、合并和工作窃取成本，也不是 N 个元素都能线性加速的承诺。

`std::reduce` 给实现这种分组自由，而且可以重排操作数。即使省略策略或使用 seq，也不能假设它重新变成 accumulate 的左折叠。不同函数名承诺了不同的累积结构；执行策略只是在该结构上约束执行方式。

## 2. 结合律、交换律不是一句“加法可以”

结合律 `(a op b) op c == a op (b op c)` 允许改变括号；交换律 `a op b == b op a` 允许交换顺序。若希望 reduce 在各种许可分组和重排下都得到同一结果，通常需要两者都成立，并且初始值和所有中间运算处在有效定义域中。

数学整数加法满足这些性质，但 C++ 有符号整数溢出是另一回事。Reference 使用 `int64_t` 输入和初始值，N 最大只有 4097，三角和 `N*(N+1)/2` 及中间和都在范围内，因而可以逐值精确检查。换成 int 输入并传入 `0LL`，也不能仅凭初始值类型就断言库中任意二元调用都会先把两个 int 升为 long long；reduce 的允许组合要逐一满足类型和运算要求。最清楚的方式是使输入和累积类型本来就一致，或者在 transform_reduce 的映射中明确提升类型。

初始值不是“每个分块的额外一次输入”。比如求和以 10 为 init，期望是整条区间的和加一次 10，不能让每个 worker 都从 10 开始再相加。手写线程局部和从加法单位元 0 开始，主线程合并后只加一次业务初始值，才能维持同一合同。

## 3. 先映射再归约，类型提升要发生在乘法前

点积为 `sum(a[i]*b[i])`。先 transform 到临时数组再 reduce 可以表达它，但会额外写入和读出临时数组。transform_reduce 可以直接把映射结果参与归约，避免这个完整中间结果。具体融合到何种机器码属于实现行为，但接口已不要求用户分配那块数组。

```cpp
const auto mul = [](float x, float y) noexcept {
    return double(x) * double(y);
};
const double result = std::transform_reduce(
    a.begin(), a.end(), b.begin(), 0.0, std::plus<>{}, mul);
```

这一段就在 L2 Reference 中，输入 `{1,2,3,4,5}` 和 `{2,3,4,5,6}`，解析结果为 70。注意 `double(x*y)` 会先做 float 乘法，溢出或舍入已经发生，再转换也无法找回信息；`double(x)*double(y)` 才把乘法移到 double 域。对 binary32 有限输入，其两个有效数相乘至多需要 48 个二进制有效位，binary64 的 53 位有效数能够精确容纳该乘积；加和仍可能舍入。

使用 par 时，mul 是独立、无共享写、无异常的映射，plus 合并部分和。浮点重排的误差要求在 [SIMD 精度篇](../simd/03-reductions-and-precision.md)完整推导，不能只把“并行结果不同”解释为 bug，也不能把任何巨大差异都解释成允许误差。

## 4. 扫描为什么需要比 reduce 更强的输出合同

inclusive_scan 输出每个含当前元素的前缀，exclusive_scan 输出当前元素之前的前缀，并在第一个位置放入 init。对 `x={1,2,3,4}`，inclusive 是 `{1,3,6,10}`，exclusive 且 init=10 是 `{10,11,13,16}`。只检查最后一个元素不足以验证扫描，因为中间前缀可能错而最后总和恰好正确。

L2 对每个下标 i 使用公式检查：inclusive 为 `(i+1)*(i+2)/2`，exclusive 为 `10+i*(i+1)/2`。空输入时不写输出；单元素时 exclusive 只写 init。输入及输出使用独立 vector，以免把本篇重点混入就地扫描的读写前提。

每次调用普通或 par 扫描前都重新把有效输出填成 -12345，前后保留 -777 边界哨兵。否则前一版已经正确的结果可能掩盖后一版完全没写的错误。Reference 故意分别跳过 inclusive 与 exclusive，要求同一个逐项检查器失败；仿射 scan 也在每轮前重新填错误系数，并注入 no-op 检查。空输入不要求写入，所以此类故障检查只对非空输入有判别力。

一种教学并行构造是两层扫描：先把输入分成连续块，每块求自己的前缀和并输出块总量；对块总量做前缀和，得到每块之前的偏移；最后把偏移加到该块的局部前缀。对长度 N、P 块，总工作仍是 O(N)，中间偏移有 O(P) 数据。标准库没有承诺必须使用这一算法，正文用它推导为何扫描可以并行，同时提醒额外传递和写回并非免费。

这个构造还有重要细节：块的原始顺序不能乱。扫描输出第 i 个位置的前缀时，参与的是原序列开头的一段，允许调整分组，但不会像 reduce 那样任意重排这段输入。于是结合但不交换的操作可以成为检查器，验证我们没有把两个合同混为一谈。

## 5. 用仿射变换观察“顺序保持，括号可变”

令一个变换表示为 `(a,b)`，作用是 `f(x)=a*x+b`。先应用 left，再应用 right，合成结果为 `(right.a*left.a, right.a*left.b+right.b)`。展开三次变换可证明，在整数运算不溢出的前提下，这个组合满足结合律；但交换两个变换通常改变结果。

L2 输入三项：`f0(x)=2x+1`，`f1(x)=3x+4`，`f2(x)=x-2`。inclusive_scan 应得到：

| 前缀 | 展开 | 系数 |
|---|---|---|
| f0 | `2x+1` | `(2,1)` |
| f1(f0(x)) | `3*(2x+1)+4` | `(6,7)` |
| f2(f1(f0(x))) | `6x+7-2` | `(6,5)` |

Reference 同时运行普通 scan 和可用的 par scan，与这组手写系数逐项比较。若把合并时的 left 和 right 颠倒，第二个结果就会变成 `2*(3x+4)+1=6x+9`，检查立即失败。这个小例子比全部使用加法更能揭示算法合同。

不要把同一个非交换操作交给 reduce 后仍要求 `{6,5}`。reduce 的自由更大，若需要稳定的顺序，应采用保持顺序的算法或者自己规定分组；“能编译”和“结果满足应用合同”是两件事。

## 6. 浮点关联变化可能改变整个结果

考虑 double 值 `1e20,-1e20,1`。先抵消前两项再加一得到 1；先算 `-1e20+1` 时，小量在该数量级上被舍入掉，再加 `1e20` 得到 0。差异不是一个无关紧要的末位，而是目标答案的全部。

Reference 刻意用从 volatile 对象读出的值计算两组括号，在严格浮点配置中检查 1 与 0。这样示例观察的是浮点算术结构，而不依赖某个 par 实现恰好采用哪种分组。不要编写“本机 reduce 必须等于 0”的测试，标准没有选定那棵树。

实际数值验收要从输入量级、运算数量和算法的误差传播制定边界。点积的一个基本尺度是 `sum(abs(a[i]*b[i]))`，它不会因正负抵消接近零。仅使用 `abs(got-ref)/abs(ref)` 在真值为零或很小时很不稳定。若业务要求逐位可复现，应固定分块和合并顺序、控制编译器浮点优化和 ISA，或者采用满足需求的精确/补偿归约方案，并单独衡量成本。

## 7. 复现与答案

```powershell
# 工作目录 Concurrency_Study/exercises
cmake -S L2_parallel_reduce_scan -B build/l2 -G "Visual Studio 18 2026" -A x64
cmake --build build/l2 --config Release
ctest --test-dir build/l2 -C Release --output-on-failure
```

必做 Part 的答案分别是：用一致的 int64_t 输入与 init 验证 reduce；用显式提升的乘法验证 transform_reduce；逐下标验证两种 scan；最后用仿射组合检查 scan 顺序，用两种括号检查浮点非结合性。完整程序为本题 `solution.cpp`，不需要学生猜测省略的辅助函数。

**reduce(seq) 能保证复现 accumulate 吗？** 不能。seq 不删除 reduce 自身的重分组和重排许可。

**scan 是否需要交换律？** 为使允许的重新分组保持结果，需要相应结合性质；保持操作数顺序意味着不必为了任意排列再要求交换律。实际类型和中间结果仍必须有效。

**为什么小整数题可以严格等于，而通用浮点题不行？** 题目限制了所有值和中间结果可精确表示；浮点一般输入不具备这个性质。检查标准来自输入合同，不来自“浮点永远不能用 ==”这种口号。

**初始值换成 double 就足够避免 float 乘法溢出吗？** 不够。映射必须在乘法前显式提升操作数，不能只提升已经计算完的乘积。
