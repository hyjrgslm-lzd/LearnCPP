# C05 样章教学审查：REVISE

审查对象：`chapters/00-roadmap.md` 到 `chapters/06-utf-transcoding.md`，`chapters/14-bounded-binary-fields.md`，以及 L06/L14 练习说明、检查器、Reference、good/bad 控制体和作者验证记录。

## 结论

REVISE。01-06 到 L14 的教学链路基本成立，但样章核心反例与实际 bad 控制体不一致，不能通过样章门。

## 阻断

[MEDIUM] `chapters/14-bounded-binary-fields.md:34` 到 `chapters/14-bounded-binary-fields.md:38`

问题：正文把样章的隔离反例定义为“bad 变体先消耗四字节长度头，再在截断 payload 失败时留下 `cursor=4`”，并用这个状态错误推导局部 `probe` 的提交点。但实际 `validation/bad/bounded_field.hpp` 只推进局部 `probe`，失败时没有写回外部 `cursor`；它真正被 `bad_rejected` 拒绝的原因是缺少 UTF-8 校验。

证据：

- `exercises/L14_binary_fields/validation/bad/bounded_field.hpp:13` 到 `:24` 只修改局部 `probe`，截断 payload 时直接返回错误。
- `exercises/L14_binary_fields/validation/bad/bounded_field.hpp:30` 只在成功路径写回 `cursor = probe`。
- `exercises/L14_binary_fields/CMakeLists.txt:8` 到 `:9` 的 `BAD_DIAGNOSTIC` 是 `rejects invalid utf8`。
- 直接运行现有 bad 可执行：`L14_binary_fields_validation_bad.exe` 返回 `check failed: rejects invalid utf8`。

风险：学生按正文阅读会以为实验先复现了“失败推进游标”的状态 bug，但当前可执行证据复现的是“未验证 UTF-8”的文本层 bug。这样“反例 -> 改进 -> 原实验复验”的因果链断开。

最小修复范围二选一：

1. 修改 `exercises/L14_binary_fields/validation/bad/bounded_field.hpp`，让 bad 控制体在读完长度头后先提交外部 `cursor`，再在 payload 截断处失败；同时把 `exercises/L14_binary_fields/CMakeLists.txt` 的 `BAD_DIAGNOSTIC` 改为 `truncated payload keeps cursor`，并重新跑 L14 leaf/verify-core Debug+Release。
2. 保留代码不动，改 `chapters/14-bounded-binary-fields.md:32` 到 `:38`，把隔离反例改成“缺少 UTF-8 校验”；同时重写 `:38` 到 `:49` 的改进推导，不能再声称这次实验证明了失败不推进游标。

推荐 1。它保留样章原设计：先用状态 bug 推出 `probe`，再用其他检查覆盖长度和 UTF-8。
