# 12 性能测量：先确定“完成了同一件事”

前面的并发章节回答了程序能否正确结束。接下来要回答的是，在明确输入和环境下，一个正确版本花了多少时间。计时器只能测出两个时刻之差，不能替我们判断版本是否完成了相同工作，更不能自动解释慢在哪里。本章是缓存、并行算法和 SIMD 的共同先修。

假设两个线程各处理十万个事件。版本 A 每次把一个原子计数器加一，版本 B 在局部累积 256 次以后才发布。若要求只是 join 后总数正确，两者可以放入同一组最终聚合实验；若监控线程要求每个事件立即出现在共享计数器里，B 已经改变了接口。这个区别先于“B 快了几倍”。[布局实验的真实实现](../exercises/J1_false_sharing/reference.hpp)和[对应基准](../exercises/benchmarks/layout_bench.cpp)会贯穿后续章节。

## 1. 写下实验问题，再选择秒表的边界

把实验问题写成一句可以证伪的话：“在两线程、每线程十万个事件、只要求结束后的总数正确时，分散计数器是否比相邻计数器耗时更少？”这里固定了并发度、工作量、语义和自变量。读写相同比特数不代表工作量相同；丢弃失败操作、跳过尾部、少算一次归约，都可能制造虚假加速。

本课程驱动复用 [benchmark.hpp](../exercises/include/concurrency_study/benchmark.hpp)。以下模式就在 `layout_bench.cpp` 中，检查位于计时区间以外：

```cpp
const double ms = cs::bench::measure_ms([&] {
    counters.run(variant, n, batch);
});
counters.verify(variant, n, batch);
cs::bench::emit_row("layout", name, n, 2, ms, n * 2, details);
```

`run` 包含清零、线程创建、处理、join；`verify` 检查每个计数器以及发布次数。因而它测的是一次完整任务的延迟。若问题改成“已有线程池中一个任务的稳态吞吐”，就要换实验协议，把线程池寿命延长，并标成场景切换；不能只从旧耗时里估一个启动成本减掉。

SIMD 加法的数组分配和初始化则在计时外，区间包含形状检查和一次算法调用。Cap3 的 GEMM 包含覆盖输出所需的清零，排序不包含输入副本的创建。边界不同的 suite 不直接混排。标准库 `par` 版本的 `threads=0` 表示线程数由实现控制且没有实测，不是程序没有线程；手写并行版本非空时记录裁剪后的计算 worker 数，并在 details 记录 caller=1，空任务记录 threads=1、workers=0，表示只有调用线程执行。

`steady_clock` 适合测经过时间，因为它的时钟不会向后跳。它并不保证任意小区间都有可分辨的非零时长。运行空输入或十几个元素时看到 0 ms，应保留这个结果并增大规模研究，不能把 0 随意替换成一个小正数来制造吞吐。

## 2. 完成量、吞吐和加速比各回答什么

设一次样本耗时为 `t_ms`，成功完成 `C` 个元素，则吞吐是 `1000*C/t_ms` 个元素每秒。布局基准的 size 是**每线程**事件数，completed 是两线程合计；SIMD 的 size 与 completed 均是元素数。对 GEMM，completed 是输出元素 `n*n`，而不是浮点运算次数。约定一次乘和一次加各算一个 FLOP 时，可另算 `2*n^3/(t_ms*10^6)` GFLOP/s，并说明边界含输出初始化。

加速比 `T_baseline/T_candidate` 只对同契约、同输入、同边界有意义。大于 1 是这组数据下的较快，小于 1 也是有效观察。算术变窄、容差放宽、把排序改成仅检查已排序、跳过 NaN，都是需要显式说明的变化。发生校验错误的运行返回非零，它没有资格参加有效性能排名。

别把“最终求和相同”当成逐项正确。两个位置一增一减可以抵消，排序也可能丢一个值并复制另一个值。这里的矩阵逐输出验证，排序验证有序性和每个值的重数；这些工作不计入内核时间，但必须真正执行并能失败。

## 3. 每进程单轮，采样由外部管理

驱动的一次调用只运行每个选择的 variant 一轮。它不私自做 300 遍取最小值，也不在正式区间前隐藏一个同算法预热。统一 runner 的接口是 `--exe EXE --check REFERENCE --variant NAME --output DIR -- 驱动参数`；`--check` 和 `--variant` 可重复，variant 不能是 `all`。从 exercises 目录先用 `rg --files .. | rg run_benchmarks.py` 找到主线程提供的 runner，传入实际构建产物绝对路径。

例如在 PowerShell 中，令 `$runner`、`$driver`、`$reference` 分别指向找到的脚本、`layout_bench.exe` 和 `J1_false_sharing_reference.exe`，执行：

```powershell
python $runner --exe $driver --check $reference `
  --variant packed --variant padded --variant shared --variant batched `
  --output build/results/layout-new -- --size 100000 --threads 2 --batch 256
```

runner 位于 `exercises/tools/run_benchmarks.py`。它在正式样本前运行正确性检查，做外部预热，然后按固定种子随机排列版本顺序，收集五次独立进程样本，并施加外部超时。CSV stdout 只有 header 和 rows，诊断去 stderr；缺能力的专项目标返回 77。输出目录应是新的结果目录，避免把不同编译配置的样本混到一起。

这里的外部预热让系统代码、文件页等状态有机会变暖，却**不会**让下一个新进程继承前一个进程的标准库线程池。每个进程的第一次 `par` 调用仍可能包含自己的运行时初始化。若要研究同进程第二次调用，应设计并注明另一组实验，而不能把当前方法解释成“线程池已经预热”。

保留五个样本、中位数、最小值和最大值；不要只公布最小值。最小值可以辅助观察低干扰状态，但越多次采样越容易偶然得到更小值，跨实验比较会混入采样数量偏差。随机顺序能减轻持续升温、后台负载和频率变化对固定版本顺序的偏向，不能消除全部噪声。若需要更多样本，应预先说明数量，保留之前的数据。

## 4. 优化器和计时器之间还有一份契约

如果计算结果没有可观察用途，编译器可以删掉计算；如果重复执行相同纯函数并只使用最后一次结果，编译器可能合并多次计算。因此“循环一千次，再打印一个数”不自动意味着测到了千次工作。我们的驱动接受运行时参数，在计时后检查所有输出或一个具有独立解析真值的归约结果；仍需用编译诊断确认实际执行路径。

把输入数组改成 volatile 通常会破坏目标循环的正常优化，把实验变成另一种工作负载。volatile 也不是线程同步原语。只在 [K2 的舍入实验](../exercises/K2_simd_dotproduct/solution.cpp)中，用一次 volatile 暂存刻意建立中间 float 舍入；不要把这个教学操作复制到所有热循环里。

源码函数名叫 scalar，只表示写法逐元素。编译器可能自动向量化它；函数叫 `par`，也不保证启动额外线程。先记录编译器版本、标准、优化选项、ISA、浮点选项、操作系统、CPU、内存、供电模式、后台负载，再结合向量化报告、反汇编或 profiler 解释结果。[SIMD 诊断正文](../topics/simd/04-diagnostics-and-bandwidth.md)给出具体命令。

## 5. 将原因写成可验证假设

如果 padded 比 packed 快，只能先说“在该布局和本次环境下耗时较低”。缓存一致性流量是有根据的机制解释，但要确认它是主要原因，还需要验证实际地址区域、线程所在 CPU、硬件事件和干扰条件。两线程可能被排在同一物理核的两个逻辑处理器上，也可能没有长时间重叠执行；仅打印 hardware_concurrency 不会解决这个问题。

同样，SIMD 加法在大数组上加速不明显，可以提出带宽限制假设：每个 float 加法至少有两个 4 字节输入和一个 4 字节输出，逻辑流量约为 `12*n` 字节。但这个数不是已测 DRAM 流量，缓存命中、写分配和写回都会改变总线上的字节数。扫描跨越缓存容量的数组规模，再采集硬件指标，才逐步缩小原因范围。

本章至此得到一个可复用顺序：先固定语义与输入，证明或检查实现正确，再测一次明确的区间，最后在外部重复采样并解释不确定性。后续每项优化都沿用这个顺序。

## 自测与答案

**把每事件发布换成每 256 次发布，可以与原版比较吗？** 在仅要求 join 后总数一致的聚合契约下可以。若观察者要求实时发布，则属于场景切换；还要计算最坏尚未发布数量及收尾刷新。

**一组数据为 1.0、1.1、1.0、7.0、1.2 ms，应该删掉 7.0 吗？** 不应默删。中位数为 1.1，范围为 1.0–7.0，全部样本保留。可以记录当时的外部干扰，另开预先约定的补充实验，但不能只挑有利样本。

**每进程预热能保证正式 par 样本不含线程池启动吗？** 不能。新进程有新的运行时状态，当前驱动的首次调用成本包含在样本中。

**SIMD 宽度为 4，验收条件应该是加速四倍吗？** 不是。加载、写回、循环控制、尾部、频率和瓶颈都影响时间；标量源码还可能已经自动向量化。验收是正确、无越界、有完整测量记录。
