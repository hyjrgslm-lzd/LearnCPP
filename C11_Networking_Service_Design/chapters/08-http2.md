# 08 HTTP/2：多流、压缩状态与流量额度

先读 HTTP/1 与事件循环。实践 [L08](../exercises/L08_http2/README.md)使用固定 nghttp2v1.70.0，在实际 TCP 上运行 prior-knowledge HTTP/2。它不实现 TLS 协商，也不是公共 HTTP 服务器。

## 1. 请求串行等待如何变成独立 stream

HTTP/1 同一连接的响应顺序会让短请求等在长响应之后。HTTP/2 将每个交换放入 stream，连接上的帧带 stream ID，可交错发送。应用语义仍是方法、状态、字段和 body；只是编码与调度不同。TCP 仍有全连接的字节顺序要求，所以丢失前段 TCP 字节时，后面的所有 stream 帧都要等重传；应用层队头阻塞改善不等于传输层阻塞消失。[RFC9113](https://www.rfc-editor.org/rfc/rfc9113.html)区分了连接与流状态。

帧头固定 9 字节：24 位长度、类型、flags、31 位 stream ID 等。stream 0 属于连接控制。HEADERS 建立字段块，DATA 携带 body，END_STREAM 结束一个发送方向，END_HEADERS 结束字段块；二者不是同一个结束。字段块跨帧时用 CONTINUATION，不能在中间任意插入其他帧。

客户端先发送连接前言和 SETTINGS。SETTINGS 是接收方约束的协商信息，ACK 确认收到，不携带新参数。L08 双方设置最大并发流 16、初始流窗口 1024 和字段列表建议上限 8192。建议上限不替代应用自己的累计解压字段大小限制；这个实验的固定少量请求不是对不可信无限连接的容量证明。

## 2. HPACK 需要连接级顺序

HPACK 以静态表、动态表和字面量编码字段，整数采用前缀编码，字符串可选 Huffman 编码。动态表条目随插入/淘汰改变，索引只在同一方向的同一连接压缩状态中有意义。解码器不能只把单个 HEADERS 丢给独立任务并任意乱序执行；后一个块可能引用前一个块新增的条目。

敏感字段可选择 never-index 编码，避免进入动态表；压缩不是保密机制。表容量受协议约束，解码后的字段长度仍要单独约束：小压缩块可能展开成大的字段列表。生产接入需要同时控制压缩字节、动态表、展开总长度和字段个数。

L08 发送两条含相同 `x-course` 的请求，检查远端解码值一致并观察第二个 HEADERS payload 更小。这是固定 nghttp2、固定输入和同一连接的压缩观察，不声称所有第二次请求都更短；表大小为零、字段改变或实现选择都会改变结果。

## 3. DATA 同时消费两个窗口

发送一段 DATA 长度 n，需要流窗口和连接窗口都允许 n。流窗口保护单个消费者，连接窗口保护整个连接。WINDOW_UPDATE 归还信用时不能超过允许范围，增量 0 是协议错误。初始流窗口由 SETTINGS 修改；连接窗口有自己的更新路径，不能把二者加成一个总计数。

L08 把自动窗口更新关闭。大流收到 1024 字节后不归还流额度，于是 8192 字节响应停止；小流仍可收到 `ok`。随后应用消费大流并调用 `nghttp2_session_consume`，同时归还流与连接额度，反复推进至完整 8192。这个证据直接定位“停在流窗口”，不是依据总耗时猜测锁竞争。

若为慢流归还连接信用却不归还流信用，其他流还能推进；若连接窗口也被耗尽，所有 DATA 流都会停。控制帧不按 DATA 的窗口消费，驱动仍必须读写控制流量，否则双方可能互等。将网络读暂停等同于暂停一个业务 stream，可能把全连接 SETTINGS/WINDOW_UPDATE 一并饿死。

## 4. 错误范围决定恢复范围

RST_STREAM 终止一个流，不必关闭其他流；L08 在未完成的大响应上 reset，再开小流验证连接可用。流的发送 payload 必须保留到库不再回调 data provider，课程在 stream-close 回调释放相应 map 项。

连接协议错误通过 GOAWAY 通知，包含最后处理的流范围与错误码。收到 GOAWAY 不能把所有未收到结果的请求无条件重试；有些可能已被业务处理，依旧需要幂等语义。实验注入连接级增量为零的 WINDOW_UPDATE，观察 PROTOCOL_ERROR GOAWAY，展示范围判断。

## 5. 接线与源码阅读

nghttp2 不替应用做 socket I/O。`mem_send2` 返回一段库拥有的待发字节，必须按接口有效期发送或复制；`mem_recv2` 消费收到的切片。实验先让字节经过真实 TCP，再按 7 字节切片喂解析器，确定性覆盖任意 TCP 分片。C callback 不得泄漏 C++ 异常，捕获后返回库错误码。

从 `lib/nghttp2_session.c` 的 mem_recv2 跟到 frame header 解码、流查找和回调；再从 `nghttp2_submit_response2` 跟到 outbound item、窗口检查和 data provider。对照教学代码的 sending、received、consumed 三张表：分别是谁拥有待发数据、已到数据和已归还信用？完成这条路径比仅定位一个 API 声明更能说明库与应用的责任边界。

## 6. 自测与解析

1. **流窗口为 0 能否发送 SETTINGS？** 能，DATA 流控不禁止连接控制帧；仍需驱动控制 I/O。
2. **小流成功是否证明 TCP 丢包无影响？** 不能，本实验验证流量额度隔离，未制造 TCP 丢包。
3. **reset 后可复用 stream ID 吗？** 不可当作新的同一连接请求复用，ID 与流生命周期绑定。
4. **HTTP2 header limit 是否就是压缩输入长度？** 不是；压缩块、动态表和解压字段列表是不同资源。
