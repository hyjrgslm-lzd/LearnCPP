# 06 TLS：加密之外还要验证身份

先读第 5 章。对应 [L07](../exercises/L07_tls/README.md)：memory BIO 分离协议与网络，真实 TCP 分支再核对 SSL stream 接线。测试 CA 与私钥只在进程或私有临时目录使用，不写入系统信任库。

## 1. 从明文威胁到握手责任

明文 TCP 不保证对端身份，也不防止路径上的读写。TLS 使用认证密钥交换建立会话密钥，用认证加密保护记录。身份、机密性、完整性是相关但独立的检查：一个加密连接若接受任意证书，仍可能连到攻击者。

TLS1.3 的主线是 ClientHello 提供版本、算法、key share 与扩展，ServerHello 选择参数并提供 key share，双方建立握手密钥；服务器发送加密的扩展和认证消息，CertificateVerify 证明私钥控制，Finished 绑定握手 transcript。客户端验证后发送自己的 Finished，进入应用数据阶段。双方必须对同一握手历史达成一致，不能只看“证书文件成功加载”。课程按 TLS1.3 机制讲解；规范版本与修订入口见[来源索引](../references/standards-and-implementations.md)。

密钥交换和记录加密交给 OpenSSL/MsQuic/gRPC 的固定后端。自写解析状态机是学习协议边界；自写密码算法或关闭身份验证并不能降低网络库接入难度。

## 2. 信任链、名称与用途逐项通过

根 CA 是本地配置的信任起点。服务器发送叶证书及必要中间证书，验证者构建并验证链、有效期、签名、用途等约束。证书 subject 文本相同不代表是同一个 CA，公钥和签名关系才有意义。L07 动态创建可信 CA 与不相关 CA，避免把“同名错误密钥”和“未知颁发者”混成同一个预期错误。

链有效仍需核对目标身份。本课连接 IP 回环，但请求的 TLS 身份是 localhost；证书 SAN 必须匹配 localhost。SNI 是告诉服务器选哪个站点的握手扩展，**发送 SNI 不等于客户端验证名称**。Asio SSL context 开启 verify_peer，stream 设置 host_name_verification，底层另设 SNI，三者各负其责。生产以 IP 作为身份时应检查 IP SAN，不能把任意地址字符串当 DNS 通配名。

mTLS 还要求服务器请求并验证客户端证书。客户端认证成功只得到经过认证的身份；是否有权取消某个任务仍是应用授权。L07 检查可信客户端、缺少客户端证书、过期叶证书、错误名字和未知 CA。测试生成的是教学身份，不实现组织级证书颁发、吊销发布或密钥轮换服务。

## 3. TLS 记录不等于应用消息

一次 SSL_read 可能只返回部分应用消息，SSL_write 也有自己的重试约束。非阻塞 OpenSSL 可能返回 WANT_READ 或 WANT_WRITE；一个逻辑写操作可能需要读握手流量，不能机械地把函数名映射到 poll 事件。memory BIO 驱动把 TLS 输出字节搬到对端输入，再继续握手/读写，能确定性观察协议推进而不依赖 TCP 切片。

TCP SSL stream 将这一状态机接到异步 socket。缓冲一直保留到组合操作完成；TLS 层、HTTP parser 和业务队列各自有容量，不能把一个 flat_buffer 的上限称作整个进程上限。攻击者在握手、证书解析和大量半连接阶段也会消耗资源，因此握手时间和连接数同样受限。

## 4. ALPN、恢复和关闭

ALPN 由 TLS 握手协商应用协议，例如 h2 与 http/1.1。协商出 h2 后必须运行 HTTP/2 parser，不能因某个端口通常提供 HTTP/1 而忽略结果。L08 的裸 TCP prior-knowledge 分支没有 TLS/ALPN；P2 的 gRPC 使用自己的 TLS/HTTP2 栈，不能将两项独立实验拼成未实现的 HTTPS 网关。

会话恢复用 PSK/ticket 减少握手成本，ticket 生命周期与密钥轮换要受策略控制。0-RTT 数据可能被重放，TLS 加密本身不为业务提供 exactly-once；有副作用的操作通常需要拒绝 early data 或应用级抗重放设计。重复提交依旧使用第 10 章的幂等记录。

close_notify 给出 TLS 层的关闭信号。TCP EOF 缺少 close_notify 可能代表截断，不能一概吞成优雅关闭；具体应用若能用自身明确长度判断已收到完整消息，也应记录 TLS 关闭状态。异步 shutdown 有时间预算，超时后可强制关闭，但报告为强制收束而非清洁关闭。

## 5. 自测与解析

1. **SNI 正确、证书验证关闭，安全吗？** 不安全；SNI 只是选择信息，验证器仍须检查信任与目标身份。
2. **mTLS 能否替代任务权限检查？** 不能，它认证主体，不决定这个主体可访问哪些任务。
3. **TLS read 到一段 JSON 能否立即解析完整请求？** 不能据此断定边界，应由上层帧或 HTTP 长度决定完整性。
4. **0-RTT 为何不能直接用于扣款？** 重放可能重复触发副作用；需要明确抗重放/幂等策略，而非只依赖加密。
5. **未知 CA 和错误主机名要分开测吗？** 要；一个失败不能证明另一条验证配置存在，正例还要证明可信身份确实可用。
