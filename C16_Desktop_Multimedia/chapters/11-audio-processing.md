# L11 增益、混音、RMS/Peak、波形降采样与重采样边界

音频处理先求正确，再求实时。媒体工作台至少需要四类基础处理：调音量、混合两段信号、显示电平或波形、把不同采样点数的数据放到同一宽度上观察。本章用 float PCM `[-1, 1]` 建模，避免格式转换干扰。

本章所有输入 sample 和 gain 都必须是有限值。`NaN` 和 `Inf` 不能默默流入 RMS、peak、min/max 或重采样结果；一旦进入，比较和聚合会变得不可解释。练习用 `invalid_argument` 拒绝非有限值。归一化区间仍是 `[-1, 1]`，超过范围的有限结果由增益/混音函数 clamp。

## 1. 增益与削波

增益是乘法：`out = sample * gain`。但输出仍必须落在格式范围内。float PCM 常用 `[-1, 1]`，超过范围就会削波或在写回整数格式时溢出。练习采用 clamp，明确把超出范围压到边界。真实应用也可以选择 limiter 或归一化，但必须说明策略。

## 2. 混音

最小混音是逐 sample 相加再 clamp。两段输入长度不同不能悄悄按较短长度混完就算成功，因为尾部语义不清：是静音补齐、截断，还是错误？本题要求长度相同，不同长度抛出异常。

## 3. RMS 与 Peak

Peak 是最大绝对值，适合检测削波风险。RMS 是均方根：

```text
sqrt(sum(sample * sample) / count)
```

RMS 不是平均绝对值。平均绝对值也有用途，但不能冒充 RMS。检查器用一组含正负和满幅的样本区分两者。

## 4. 波形 min/max

屏幕上 1000 像素不可能画 48000 个采样点。波形缩略图常把一段样本降成一个 min/max bucket。这样能保留尖峰，不会像简单取平均那样把瞬态抹掉。本题保留尾部 bucket：最后不足一个 bucket 的样本也要显示，否则结尾点击/seek 会偏。

## 5. 线性重采样与限制

线性重采样把输出索引映射回输入连续坐标，在两点之间插值。它足以演示“样本位置”和“输出长度”的关系，也能做简单可视化。但它没有抗混叠滤波；把高频信号降采样时会折叠。课程不把它包装成高质量 sample-rate converter。真实音频转换应使用带低通滤波的重采样器，或依赖后端库的明确能力。

边界要清楚：空输入或请求 0 个输出，返回空；请求 1 个输出，返回第一个样本；输入只有 1 个样本但请求多个输出，结果应把这个常量重复到请求长度。这符合“输出长度由调用方请求”的契约，也避免把常量信号重采样成长度错误的片段。

## 6. 练习

位置：`C16_Desktop_Multimedia/exercises/L11_audio_processing`。

Part：

1. `apply_gain_clamped`：乘以 gain 后 clamp 到 `[-1,1]`。
2. `mix_clamped`：同长度逐点相加并 clamp。
3. `measure`：计算 RMS 与 peak。
4. `reduce_minmax`：按 bucket size 生成 min/max，保留尾部。
5. `resample_linear`：给定输出点数，保留端点并线性插值。
6. 非有限输入或 gain 必须拒绝，不能生成看似合法的数值结果。

`bad` 变体不 clamp、把平均绝对值当 RMS、丢失 waveform 结构，并用常数填充重采样。检查器会拒绝。

## 7. 解析

正确实现的核心是把每个函数的输入域写清楚。mix 要求等长，bucket size 必须大于 0，输出点数不能为负。空输入在 metric 中返回 0，在重采样中返回空。`output_count == 1` 是特殊情况：无法同时保留两个端点，只能返回第一个样本。

源码阅读：L14 的 `QAudioBufferOutput` 只给出解码 buffer，不做这些业务处理。媒体工作台如果显示 RMS/波形，应在自己的分析管线里完成，并记录格式、声道混合策略、重采样限制。不要把后端输出“有声音”当成电平算法已验证。
