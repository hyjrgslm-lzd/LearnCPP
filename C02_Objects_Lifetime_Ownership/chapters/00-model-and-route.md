# 00. 对象模型与学习路线

C02 讨论的是 C++ 程序里“一个值到底是什么、什么时候存在、谁负责清理、失败时会发生什么”。如果只把对象看成变量名，很快会在 RAII、移动、智能指针、placement new、别名规则和优化行为处卡住。本章先建立共同语言：类型、声明、对象、存储、作用域、生命期和资源。

本课假定你能读写普通 C++ 函数、类、`std::vector`、`std::string`、基本异常处理和简单模板调用。但本课不假定你已经系统掌握对象模型。后续章节第一次使用会先讲必要机制，不把关键语义丢给外链或“自行查阅”。

## 类型、声明和值

类型描述一段表达式或对象允许做什么。`int` 可以做整数运算；`std::string` 管理字符缓冲；`std::unique_ptr<T>` 表示独占所有权。类型不是对象本身，而是解释对象和表达式的规则。

声明把名字引入程序：

```cpp
int count = 3;
std::string name = "core";
```

`count` 和 `name` 是名字。名字引用的对象分别有类型、存储、生命期和值。声明还可能只声明函数、类、别名或模板，并不一定创建对象：

```cpp
struct Packet;
void send(Packet const&);
```

这两行只告诉编译器有这些实体存在，不构造 `Packet` 对象。

表达式产生值、对象身份或副作用。`count + 1` 产生一个结果值；`++count` 修改对象；`name[0]` 指向 `name` 内部的一个字符。后续 02 章会细讲值类别，本章只需要先记住一件事：表达式不总是“临时值”，它也可能指向已经存在的对象。

## 对象、存储和生命期

对象是 C++ 程序按某个类型创建出来的实体。对象需要一段合适的存储。存储只是字节位置和对齐，生命期才决定那些字节现在是否真的容纳了某个类型的对象。

```cpp
alignas(std::string) unsigned char buffer[sizeof(std::string)];
auto* p = new (buffer) std::string("hello");
p->~basic_string();
```

`buffer` 的存储一直存在，但 `std::string` 对象只在 placement new 完成之后、析构函数开始之前存在。12 章会系统讲这种手动对象创建。本章先用它区分两个概念：存储存在，不等于对象存在。

多数日常代码由声明自动管理对象生命期：

```cpp
void f() {
    std::string s = "abc";
}
```

进入 `f` 后，`s` 的存储被占用，初始化完成后 `std::string` 对象开始生命期；离开作用域时析构函数运行，生命期结束。析构之后，原来的名字不能再拿来访问对象，因为对象已经不存在。

## 存储期不是生命期

存储期说明底层存储能保留多久。常见四类：

| 存储期 | 例子 | 存储何时存在 |
|---|---|---|
| automatic | 函数里的局部变量 | 所在块执行期间 |
| static | 全局变量、`static` 局部变量 | 程序运行期间 |
| thread | `thread_local` 对象 | 线程运行期间 |
| dynamic | `new` 或 allocator 得到的存储 | 分配到释放之间 |

生命期说明对象何时真的开始和结束。普通局部变量里二者几乎重合；动态存储、union、手动构造和对象复用会把二者拆开。后续智能指针、控制块和 `object_buffer<T>` 都依赖这个区分。

## 作用域、可见性和所有权

作用域只管名字能在哪里被找到：

```cpp
{
    int x = 1;
}
// x 在这里不可见
```

不可见不等于对象必然已经销毁；可见也不等于对象仍然有效。引用、指针、迭代器和 view 经常把一个作用域里的对象地址带到另一个作用域。03 章会讲这些借用关系。

所有权是工程约定：谁负责让资源最终释放。C++ 标准不会给“拥有者”这个词一个统一运行时标记，但标准库类型会表达常见约定。`std::unique_ptr<T>` 拥有一个动态对象；`std::span<T>` 借用一段连续元素；`std::string_view` 借用字符序列。拥有者决定资源生命期，借用者只能在被借用对象仍然存在时使用。

## 资源不只是内存

资源是必须成对获取和释放的东西：堆内存、文件句柄、socket、锁、GPU buffer、临时目录、日志订阅等。对象生命期和资源生命期可以绑定，也可以脱钩。RAII 的核心是让对象的构造获取资源，析构释放资源，使异常和早返回也走同一条清理路径。

```cpp
void write_file(std::filesystem::path const& p) {
    std::ofstream out(p);
    out << "data\n";
}
```

`out` 是对象，文件句柄是资源。离开函数时 `out` 析构，文件资源被关闭。07 章会完整展开 RAII；04 章先讲为什么构造失败时也能清理已经完成的成员。

## 本课路线

01 章先把初始化讲清楚：对象怎样从“有存储”变成“有值”。02 章讲表达式和值类别：为什么同一段代码有时复制、有时移动、有时只是绑定引用。03 章讲生命期和借用：哪些引用能活，哪些已经悬空。04 章讲构造、析构和异常展开：对象创建到一半失败时，C++ 精确清理哪些部分。

05 到 07 章用这些基础建立复制、移动、返回值、RAII 和所有权。08 到 10 章进入 `unique_ptr`、`shared_ptr`、`weak_ptr` 和控制块。11 到 14 章讲布局、存储复用、别名、provenance、UB 与优化。15 章把前面内容合到一个 `object_buffer<T>` 项目里。

学习时先读正文，再做对应练习。实现型练习的 `src/student` 是唯一学生编辑区；`reference` 是答案；`checks` 是公开检查器；`validation/good` 和 `validation/bad_*` 用来证明检查器能接受正确实现、拒绝代表性错误。不要通过改 checker、调用 reference 或返回常量绕过练习，那样不会学到对象模型。

## 阅读能力自测

先不要写代码，直接判断下面每段程序在对象模型上发生了什么。

### 题 1：名字消失和对象销毁

```cpp
std::string* p = nullptr;
{
    std::string s = "abc";
    p = &s;
}
// 这里能读 *p 吗？
```

### 题 2：存储存在和对象存在

```cpp
alignas(int) unsigned char bytes[sizeof(int)];
int* p = reinterpret_cast<int*>(bytes);
// 这里能读 *p 吗？
```

### 题 3：资源归属

```cpp
FILE* f = std::fopen("data.txt", "w");
if (!f) {
    return;
}
std::fprintf(f, "hello\n");
std::fclose(f);
```

如果 `fprintf` 前面又加入一个可能抛异常的函数调用，谁保证 `fclose` 一定执行？

### 题 4：借用不保活

```cpp
std::string make();
std::string_view v = make();
// 这里能安全使用 v 吗？
```

### 题 5：构造失败

```cpp
struct A {
    A();
    ~A();
};

struct B {
    B();
    ~B();
};

struct C {
    A a;
    B b;
    C();
    ~C();
};
```

如果 `B()` 抛异常，哪些析构函数会运行？

## 自测解析

题 1 不能读 `*p`。`s` 是 automatic storage duration 的局部对象，离开块时析构，生命期结束。`p` 仍然保存一个地址，但它不再指向活着的 `std::string` 对象。

题 2 不能读 `*p`。`bytes` 的存储存在，也满足 `int` 对齐，但还没有开始 `int` 对象的生命期。12 章会讲哪些操作能在存储中开始对象生命期。

题 3 里资源归属由人工控制。正常路径会执行 `fclose`，但如果中间抛异常并离开函数，裸 `FILE*` 本身不会自动关闭。RAII 会把 `FILE*` 放进一个析构时调用 `fclose` 的对象，使所有离开路径统一清理。

题 4 不能安全使用 `v`。`make()` 返回的 `std::string` 是临时对象，`std::string_view` 只是借用字符，不拥有字符串，也不会延长字符串生命期。

题 5 中 `a` 的析构函数会运行，`b` 的析构函数不会运行，`C` 的析构函数也不会运行。原因是 `a` 已经构造完成，`b` 没有构造完成，最外层 `C` 对象也没有完成构造。04 章会用可运行事件记录验证这条规则。
