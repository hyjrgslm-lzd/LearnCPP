# B01 调度粒度与成本

这是观察/测量单元。默认只跑有限正确性检查，不把测量程序通过当作读者已完成归因分析。背景和完整实验解析见[测量章](../../chapters/16-measurement.md)。

同一组uint64输入反复应用多项式，比较serial、每元素单独schedule+spawn、一次bulk三种工作组织。逐元素结果必须等于独立代数形式的oracle；未写入/漏尾部不能靠checksum碰巧通过。输入、输出、期望数组和2线程pool在计时前准备；计时含构图/提交、计算与完成等待，不含最终线程shutdown。每个进程只测一个版本一次，不复用上一样本状态。

先按根构建指南提供STDEXEC_ROOT，单独配置本目录，构建B01_costs。运行`B01_costs --self-test`检查空、小、非整齐输入。`B01_costs --bench bulk 32768 512 4242`是显式测量；size上限262144，work上限4096，参数须完整解析为无符号整数。

## 必做与解析

1. 预测work=0时成本来自哪里。运行三种模式，记录逻辑提交量：serial=0，per_item=N，bulk=1。这只数driver提交，不是上游内部任务数、分配次数或实际工作线程数。
2. 把work提升到512/2048，检查数值正确后观察总完成时间。重计算能摊薄调度成本；并不保证一定获益，必须保存无收益。
3. 解释pre_wait_seconds：per_item是提交循环，期间worker可能同时计算；bulk是构图后、sync_wait前，尚未开始主要工作；serial记0。不能把三者当同一种阶段时间排名，更不能据此断言锁竞争或分配器就是瓶颈。
4. 正式采样使用本目录sample_benchmarks.py：`--binary <实际产物> --output <新证据目录> --note <并行工作/环境说明>`。固定两种size、两种work、三版本；每组一次预热、五个独立进程样本，顺序由固定种子打乱。共12预热、60正式样本，不过滤异常值。
5. 根据中位数、范围和离散解释当前环境。窗口太短、外部构建干扰或误差大于差异时，不作快慢定论。程序打印configured_pool_threads=2是配置量，不代表观测到两个线程都参与。

正确性检查和计时使用同一transform版本。独立oracle采用等价的`(x+1)*(x+2)+5`，所有算术为uint64模运算。pool先于借用数组销毁；提交中途抛异常时先等已接受任务收束再展开。完整进程仍有外部超时，超时或清理失败不能计入有效性能样本。
