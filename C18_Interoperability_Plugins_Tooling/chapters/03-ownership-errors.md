# 03：借用、分配与错误必须一起设计

把 `std::string` 换成 `const char*` 后，边界问题不会自动消失。指针只给出地址，既不告诉调用方长度，也不说明地址在返回后还能使用多久。我们先用一个不转移内存所有权的接口建立正确基线，再观察它怎样进入 Python 和 Lua。

## 一次调用的借用范围

主操作读 `input[0,length)`，写 `output[0,length)`。两块内存都由 host 提供，插件只在本次调用期间借用；调用结束后不能保留任何一方的裸指针。返回长度 `written` 的存储须与两块 payload 分离；允许 payload 之间重叠，不允许元数据写入破坏 payload。host 同时保证内存实际存在且可访问。空指针检查只能拒绝显式无效形态，不能证明非空地址未悬空。

这条规则让最小 C 调用方、Python buffer exporter 和 Lua string 都能接入同一核心。但它们保存 owner 的办法不同：Python 需要持有对象或 buffer view；Lua 需要让字符串及其可达引用存活；C++ 需要让容器不在调用期间析构、移动或重分配。跨语言包装的责任是建立借用前提，不是把一串数字强制转换成地址。

## 容量错误怎样影响可重试性

假设输入五字节，输出容量只有二。一个直观实现会先转换两字节，再发现剩下的放不下。它没有越界，却已经破坏调用方的旧输出。若协议承诺失败不提交，这仍然是错误。

[L02](../exercises/L02_buffers_errors/README.md) 先把输出填成哨兵，再用小容量调用，检查整个输出是否保持原样。这个实验定位的是“检查发生在写入之后”，不是内存分配慢，也不是字符转换规则不对。修复先验证输入和容量，再开始写入；最后才提交返回长度及业务计数。

容量不足时所需长度是输入长度，调用方可以在本次函数已经返回后分配新缓冲并重试。不要在同一次未完成调用中让插件要求调用方移动仍被借用的容器。成功时 `written` 是实际输出长度，失败时哪些 out 参数有效须按状态分别定义。

## 重叠是一个独立问题

主契约允许输入与输出重叠。若 `output = input + 1`，正向边读边写会把下一轮的输入覆盖。检查器用 `a b c d e f` 这样的非重复序列暴露它；只用全是 `a` 的输入可能掩盖问题。

一个足够简单的正确方案是先 `memmove` 到输出，再在输出内转换。长度为零时不调用需要有效指针前提的内存函数。独立 good 采用输入快照，它更易推理但多一次分配；两者结果可比较，成本却必须另测。这里没有证据支持“快照在所有场景都不值得”。

## 谁分配，谁销毁

插件状态由模块创建，也由模块提供的 destroy 销毁。共享运行库可以减少兼容问题，但不会让不同分配域自然等价。Windows 跨 DLL 传递 CRT 对象或异堆释放的限制见 [Microsoft 官方说明](https://learn.microsoft.com/en-us/cpp/c-runtime-library/potential-errors-passing-crt-objects-across-dll-boundaries?view=msvc-170)。课程默认用 host-owned 输出缓冲，避免把一个无必要的跨模块分配协议塞进第一版接口。

需要返回拥有型对象时，包装器可以持有 opaque handle 和创建它的模块 owner。对象最后一个引用消失时，先调用模块 destroy，再释放模块 owner。反过来先卸载模块，哪怕数据内存还在，析构代码也可能已经失效。

## 错误转换要落在边界两侧

C++ 内部可以抛异常，但 ABI 入口必须捕获并转换成状态码，不能让它穿到不知道其运行时协议的调用方。捕获前后仍要遵守资源清理和不提交保证：`catch (...)` 只避免异常逃逸，不能撤销已经写坏的输出。

相反方向也一样。Python callback 的失败需要检查 error indicator；Lua 的错误可能通过 longjmp 离开控制流。不能用一层普通 C++ `catch` 想当然地捕获两者。先学习各自运行时协议，再在边界上做显式转换；后面两条语言路线会分别演示。

## 自测与解析

1. **`const` 是否保证调用期间数据不变？** 不保证。它限制当前访问路径的写操作，不能阻止另一个线程或别名修改对象。调用方仍需满足同步与存活约定。
2. **容量不足时可否返回成功并截断？** 当前契约不允许，因为会改变记录内容。要提供截断模式必须另立明确语义和检查，不能让绑定层猜结果是否完整。
3. **`shared_ptr<void>` 能否单独解决模块卸载？** 不能。除数据 owner 外，还须保证 deleter、虚表、回调代码所处模块存活。持有关系必须覆盖代码与数据两个层面。
4. **为什么不自动执行跨 CRT 错误释放来证明问题？** 那是不可控 UB，可能随机崩溃或貌似正常。课程用所有权协议、独立分配域的安全模型与正确路径检查说明缺陷，不把一次崩溃当作完整证明。
