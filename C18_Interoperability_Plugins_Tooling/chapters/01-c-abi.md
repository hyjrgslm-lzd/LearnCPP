# 01：语言链接不是通用二进制协议

问题从一个很小的团队边界开始：实现者用 C++，调用者只会编译 C。双方都写出了名为 `upper` 的函数声明，为什么链接器仍可能找不到实现？先回到 C01：链接器匹配的是目标文件中的符号，不是源码里的自然语言含义。

## 从正确基线开始

[L01](../exercises/L01_c_linkage/README.md) 用 C 编译 `consumer.c`，用 C++ 编译 `implementation.cpp`。共同头文件的关键形状如下：

```cpp
#ifdef __cplusplus
extern "C" {
#endif
int c18_l01_upper(const unsigned char* input, size_t length,
                  unsigned char* output);
#ifdef __cplusplus
}
#endif
```

`__cplusplus` 分支使 C 编译器不必理解 C++ linkage 语法；两端仍包含同一份函数声明。类型也必须是 C 能理解的类型。C++ 函数体可以使用标准库，限制的是跨边界的表示，而不是函数体只能写 C。

这里尚未引入运行期插件。L01 是链接期绑定的 V0，用来把符号、类型和字节契约分开观察。后面的插件只有一个协商入口，不能把 V0 的自由函数清单直接当成最终兼容协议。

## 先定位“名字不一致”

预测：如果两端实际使用的 linkage 不一致，工具链可能产生不同的符号。用构建目录中的实验副本移除 C++ 端 C linkage，再查看编译、符号和链接诊断。不要先改返回值或多加一个库目录，因为这两个变化都不能修复名字不匹配。

有一个容易误判的细节：定义前若已经包含带 C linkage 的声明，后续未写 linkage 的定义会继承它。只从定义行删掉 `extern "C"` 可能仍然成功。这时应该检查完整声明链，而不是得出“extern C 没用”的结论。语言 linkage 的具体规则见 [C++ 草案 dcl.link](https://eel.is/c++draft/dcl.link)，课程的复现实验只报告当前工具链看到的符号。

修复是让双方从同一份受保护的 C 头文件获得声明。复验仍用原来的 C 调用方；把调用方也改成 C++ 会改变实验前提，不能算原问题已解决。

## 名字、导出、调用约定是不同层

语言链接回答如何与另一语言的函数类型和外部名字衔接；动态导出回答该符号能否从 DLL/SO 的导出表找到。Windows 的导出属性和 Linux visibility 由构建目标负责。函数被链接进二进制，不代表能由 `GetProcAddress` 或 `dlsym` 找到。

接下来是调用约定：参数怎样传递，返回值怎样传递，栈和寄存器由谁维护。选择 C ABI 可以缩小接口面，却不会使一个 x64 DLL 被 x86 程序直接加载，也不会使 Windows 的库成为 Linux ELF 库。课程将实际验证平台、架构和工具链组合，不声明“任何编译器都兼容”。

`extern "C"` 也不会自动把 `std::string` 变成 C 字符串。下面的反例可能被某个 C++ 编译器接受，但不是可交付给 C 调用方的接口：

```cpp
// 只做静态检查反例，不作为课程公共 ABI。
extern "C" std::string transform(std::string const& value);
```

调用方还需要知道对象布局、引用传递方式、分配器和异常协议；名字被固定并没有消除这些依赖。这正是 P2 静态检查要诊断的危险声明之一。

## 为什么传 bytes 而不是字符串

L01 输入包含 `a, NUL, z, 0xff`。如果实现用 `strlen`，它会在第二个字节停止，后面的输出仍是哨兵。检查器先重置输出，再比较每个字节，因此“返回成功但只处理前缀”的行为不会蒙混过关。

长度是数据的一部分。`const unsigned char*` 表示借用字节，不等于承诺 NUL 结尾、UTF-8 或可修改。当前基线要求输出有效且足够长；[L02](../exercises/L02_buffers_errors/README.md) 才加入容量失败协议。这个顺序使每个新责任都有自己的问题证据。

## 检查与解析

- **C 调用方通过，证明什么？** 证明当前构建的 C 声明、C++ 定义和链接选项相互匹配；不证明未来结构扩展或动态装载协议。
- **为何不用重载区分多个处理操作？** C 风格外部入口不应依赖 C++ 重载解析。用显式名字或版本化函数表表达操作，并把能力协商放在可检查的数据中。
- **为何 `char*` 不足以描述所有权？** 类型没有说明谁释放、是否可修改、存活到何时。后续章节把这些前提写入协议和检查，而不是让绑定作者猜测。
