# 00 怎样学习 C13

C13 把数值、数据布局和性能放在同一条工程路径上：先明确任务和数值结果，再选择表示和实现，最后通过可比较实验解释成本。不能从“用了 SIMD”“换成 SoA”“调用了专业库”直接推导更快，也不能把编译成功等同所有数值输入正确。

## 先修按需进入

| 当前任务 | 所需先修 | 不必预先完成 |
|---|---|---|
| 稳定求和、随机输入 | 基本算术、vector/span、误差背景由本课补齐 | 原子、协程、GPU |
| 布局与矩阵 | C02 生命周期与别名；C06 连续容器 | 完整并发运行时 |
| 量纲与源码 | C03 类型语义、C04 模板约束 | 自己实现完整量纲库 |
| SIMD 与并行 | 本课数值检查，C08 必要同步与执行策略 | 高级无锁回收 |
| NUMA | C07 虚拟内存、C08 线程位置 | GPU memory model |

先修只引入需要的切片，不用整门课当通行证。每个示例中遇到的语义应该能回到主讲处：借用回到 C02，范围协议回到 C06，发布/同步回到 C08，CPU 数据和数值成本由本课承接。

## 同一个主案例，几个独立分支

主案例有三维位置和速度、毫秒输入边界、一次位置更新、3×3 坐标变换和稳定归约。完整输出数组是业务结果，归约值是额外统计，两者都检查。

L02 将 AoS 与 SoA 作为同契约候选，额外单列转换成本。L03 的通用矩阵乘法是局部机制实验，不能假设大型 GEMM 的分块策略适合三个坐标。L05 的二维动能管线是用于阶段定位的独立场景，不与三维综合项目直接计算加速比。

## 代码与练习的三种身份

- 实现题：编辑自己的 `student/solution.hpp`，调用会到达该实现；未完成不会伪装为通过。
- Reference 和独立 good：提供完整答案与另一种检查器对照；bad 保留可稳定拒绝的语义错误，避免用 UB 制造随机崩溃。
- 观察题：完整程序负责产生真实结果；读者仍需先预测，再解释当前结果能说明什么和不能说明什么。

## 学完时应该能做什么

能给算法写清形状、借用、错误和误差契约；能解释一个非整块尾部为什么不能丢；能区分原生标准库与第三方实现；能从函数/阶段/计数器证据形成下一轮假设。若只有一个耗时数字，应继续缩小观察范围，而不是编一个硬件瓶颈故事。

构建、运行与检查见 [BUILD_GUIDE](../exercises/BUILD_GUIDE.md)。默认短检查服务于学习和本机构建，完整性能研究需要额外采样与环境记录，但不改变核心代码的业务结果。
