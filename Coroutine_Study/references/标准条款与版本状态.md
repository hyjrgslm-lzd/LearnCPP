# C++ 协程标准条款与版本状态

这份索引只做一件事：区分哪些内容已经是发布标准，哪些只是当前工作草案或历史提案，哪些属于编译器实现细节。阅读课程正文时，遇到“标准规定”“实现可选择”“教学简化”这几类说法，先按本文件校准边界。

## 版本状态

| 范围 | 状态 | 课程中怎么用 |
| --- | --- | --- |
| C++20 core coroutine language | 已发布标准 | `co_await`、`co_yield`、`co_return`、`promise_type`、`coroutine_handle`、协程状态分配/销毁、参数副本、`initial_suspend`/`final_suspend` 的基础语义。 |
| C++20 `<coroutine>` | 已发布标准库 | `std::coroutine_handle`、`std::suspend_always`、`std::suspend_never`、`std::noop_coroutine`。 |
| C++20 `<stop_token>` | 已发布标准库 | 协作式取消的基础工具；它本身不强杀协程。 |
| C++23 `std::generator` | 已发布标准库 | 惰性序列、`co_yield`、递归 `elements_of` 与 generator 生命周期。实际可用性仍取决于标准库实现版本。 |
| C++26 `std::execution` / coroutine utilities | 工作草案内容 | `std::execution::task`、`as_awaitable`、counting scopes、`this_thread::sync_wait` 等按 current working draft 学设计，不当作所有编译器已可用的生产 API。`async_scope` 作为提案/第三方库术语单独说明。 |
| P0912 / P0913 / P2502 / P2300 / P3149 / P3296 / P3552 | 历史或演进提案 | 用来理解动机和设计取舍；其中 P3296 专指 `let_async_scope`。最终语义以发布标准或当前工作草案条款为准。 |
| 协程帧布局、ABI、HALO 触发、诊断 flag | 实现细节 | 只能对目标编译器和版本实测；标准不保证字段顺序、栈/堆位置、跨 ABI 传递 `coroutine_handle` 的可移植性。 |
| 课程里的 `lazy_task` / `shared_task` / `when_all` / `sync_wait` | 教学简化 | 只用于观察机制。生产实现要补齐调度器、取消传播、异常/停止通道、并发同步、分配策略和 ABI 边界。 |

## 核心语言条款

| 主题 | 稳定条款标签 | 要点 |
| --- | --- | --- |
| 协程识别与 promise 类型 | [`[dcl.fct.def.coroutine]`](https://eel.is/c++draft/dcl.fct.def.coroutine) | 函数体包含 `co_await`、`co_yield` 或 `co_return` 时是协程；promise 类型由返回类型和参数类型经 `std::coroutine_traits` 决定。 |
| replacement body / 创建顺序 | [`[dcl.fct.def.coroutine]`](https://eel.is/c++draft/dcl.fct.def.coroutine) | 参数副本先创建；promise 构造参数来自参数副本或空参数；`get_return_object()` 在 `initial_suspend()` 前调用，且至多一次。 |
| 参数副本 | [`[dcl.fct.def.coroutine]`](https://eel.is/c++draft/dcl.fct.def.coroutine) | 每个协程参数在 replacement body 开头创建副本。非引用参数的函数体标识符指向这个副本；引用参数副本仍绑定原对象，原对象早死会造成悬挂风险。 |
| 协程状态分配与释放 | [`[dcl.fct.def.coroutine]`](https://eel.is/c++draft/dcl.fct.def.coroutine) | 标准称为 coroutine state。需要额外存储时，经非数组 allocation function 获得；优先查找 promise scope 的 `operator new/delete`。 |
| 分配失败 hook | [`[dcl.fct.def.coroutine]`](https://eel.is/c++draft/dcl.fct.def.coroutine) | 如果 promise scope 找到 `get_return_object_on_allocation_failure`，分配函数按 nothrow 语义处理，失败时调用该 hook 返回失败态对象。 |
| `unhandled_exception` 抛出 | [`[dcl.fct.def.coroutine]`](https://eel.is/c++draft/dcl.fct.def.coroutine) | `unhandled_exception()` 本身若以异常退出，协程被视为在 final suspend point 挂起，异常传播给 caller/resumer。课程实现通常选择 `noexcept` 存储异常。 |
| `final_suspend` | [`[dcl.fct.def.coroutine]`](https://eel.is/c++draft/dcl.fct.def.coroutine) | `co_await promise.final_suspend()` 不得是 potentially-throwing。协程在 final suspend point 挂起时，帧仍存在，等待外部消费/销毁。 |
| `resume`/`destroy` 前置条件 | [`[dcl.fct.def.coroutine]`](https://eel.is/c++draft/dcl.fct.def.coroutine), [`[coroutine.handle.resumption]`](https://eel.is/c++draft/coroutine.handle.resumption) | 对未挂起协程调用 resumption member function 是 UB；对未挂起协程调用 `destroy()` 也是 UB。 |
| `co_await` 变换 | [`[expr.await]`](https://eel.is/c++draft/expr.await) | 先按 promise scope 查找 `await_transform`；再对结果枚举适用的 `operator co_await` 并做重载决议；无可行 operator 时对象本身作为 awaiter。歧义为 ill-formed。 |
| `await_suspend` 返回类型 | [`[expr.await]`](https://eel.is/c++draft/expr.await) | 只能返回 `void`、`bool` 或 `std::coroutine_handle<Z>`。返回 handle 时会恢复该 handle 指向的协程；返回 `bool false` 时当前协程立即继续。 |
| `co_yield` | [`[expr.yield]`](https://eel.is/c++draft/expr.yield) | `co_yield expr` 按 `co_await promise.yield_value(expr)` 建模。 |
| `co_return` | [`[stmt.return.coroutine]`](https://eel.is/c++draft/stmt.return.coroutine) | `co_return expr` 调用 `return_value`；无操作数或 `void` 表达式调用 `return_void`。 |

## 标准库与执行库条款

| 主题 | 条款标签 | 要点 |
| --- | --- | --- |
| `coroutine_handle` | [`[coroutine.handle]`](https://eel.is/c++draft/coroutine.handle) | 句柄是恢复、查询、销毁协程状态的轻量对象；不拥有生命周期语义，所有权由库类型定义。 |
| `std::generator` | [`[coro.generator]`](https://eel.is/c++draft/coro.generator) | C++23 惰性输入 range。`begin()` 会恢复协程到第一个产出或结束；迭代器 `operator++` 继续恢复到下一个产出。generator 对象负责销毁其协程状态。 |
| `std::stop_token` | [`[thread.stoptoken]`](https://eel.is/c++draft/thread.stoptoken) | 表达“请求停止”的共享状态；不会抢占执行。 |
| `execution::as_awaitable` | [`[exec.as.awaitable]`](https://eel.is/c++draft/exec.as.awaitable) | 当前工作草案中的 sender-to-awaitable 桥接。`await_suspend` 中连接/启动 sender，完成时恢复 awaiting coroutine。 |
| `execution::task` | [`[exec.task]`](https://eel.is/c++draft/exec.task) | 当前工作草案中的 coroutine return type + sender。`connect` 后由 operation state 拥有并 `start()` 一次。 |
| `execution::when_all` | [`[exec.when.all]`](https://eel.is/c++draft/exec.when.all) | 当前工作草案中 `when_all` 在任一 error/stopped 时请求停止其他输入；全部到达后根据 disposition 完成。 |
| `this_thread::sync_wait` | [`[exec.sync.wait]`](https://eel.is/c++draft/exec.sync.wait) | 当前工作草案中的同步消费者：阻塞当前线程，直到输入 sender 完成，并返回异步结果。 |
| execution scopes | [`[exec.scope]`](https://eel.is/c++draft/exec.scope) | 当前工作草案中的 counting-scope 设施；课程和第三方库中的 `async_scope` 不是该标准 API 的同名保证，必须逐实现对照。 |

## 课程用语边界

- “协程帧”在课程里等同于标准的 coroutine state，但不要推断具体字段顺序或 ABI。
- “默认堆分配”是教学视角：标准说实现可能需要额外存储，并通过 allocation function 获得；实现也可能消除分配。
- “HALO”是优化，不是语义。标准允许省略动态分配，但不承诺何时发生，也不承诺栈上布局。
- “symmetric transfer”在课程里指 `await_suspend` 返回 `coroutine_handle` 的控制转交模式。标准规定会恢复返回的 handle；是否生成机器级尾调用、是否零栈增长，是实现质量与优化结果，不是可移植语义保证。
- `resume()` 不是内存屏障。跨线程完成时，结果写入和恢复之间的可见性要由底层同步关系、mutex/atomic、事件队列或线程 join 等机制保证。
- `sync_wait` 不应循环 blind-resume 任意协程。课程最终运行时契约是：`sync_wait(std::move(task))` 拥有 root task，只 start 一次，然后等待 `final_suspend` 或等价完成通知；只有专门的 `manual_coroutine` 练习才允许手动逐步 resume。
